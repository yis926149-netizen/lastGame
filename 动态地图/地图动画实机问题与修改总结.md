# 地图重建动画方案：实机问题与修改总结

> 日期：2026-08-04
> 定位：**历史事件记录**（竞技场突起动画实机问题、根因与修改措施），内容保持当时原貌，不作持续更新。
> ⚠️ 后续修订（2026-08-05）：顶点动画已从 Shader vert 迁往 CPU 侧（每帧写 `mesh.vertices`）；UV3 语义由 `(staggerDelay, participates)` 改为 `(delayStart, delayEnd)`；keep-below clip 顶出方案落地并实机验证通过；动画管线设计约束固化于方案 §二十二。最新状态以《动态地图变化与分块重建方案.md》阶段四实机验证记录 ③⑤ 与 §二十二、《全地图波浪式上下变化测试.md》为准。
> 关联文档：`动态地图变化与分块重建方案.md`（§十九-21、阶段四、§二十-10）
> 范围：竞技场突起动画（`mapRenderMode=Chunked` + F10 立即突起）实机验证中发现的问题、根因与修改措施。

## 一、最终采用的技术路线（方案 A 修复版）

**独立 `*_Transition` Shader + 动画期间按 Chunk 材质切换**：

- 三套稳定地形 Shader（`TerrainBase_Fog` / `RealMaterialMaskBlend` / `ThreeMaterialBlend_Land`）**永久冻结**（仅保留 `Cull Off`），动画代码只存在于独立文件：
  - `Assets/Shader/TerrainBase_Fog_Transition.shader`（`Custom/TerrainBase_Fog_Transition`）
  - `Assets/Shader/RealMaterialMaskBlend_Transition.shader`
  - `Assets/Shader/ThreeMaterialBlend_Land_Transition.shader`
- 动画数据通道（每顶点语义，§20-10）：`UV2.x=startVertexY`、`UV2.y=targetVertexY`；`UV3.x=staggerDelay`、`UV3.y=participates`
- `ChunkMapRenderer.CommitAnimatedChunkGeometry` 提交后对脏 Chunk 切换材质，`FinalizeChunkAnimation` 恢复稳定材质
- 动画进度由 `MapVisualTransitionService.Tick` 经 `MaterialPropertyBlock._ChunkProgress` 驱动

## 二、问题清单与修改措施

### 问题 1：阶段四首版把动画代码写进稳定 Shader，实机"整个地图都乱"

| 项 | 内容 |
|---|---|
| 现象 | 三套稳定地形 Shader 被并入 UV2/UV3 顶点动画代码（`vert` 无条件读 `texcoord1/texcoord2`），实机整个地图几何错乱（§十九-21） |
| 根因 | 直接修改稳定 Shader，非动画 Chunk 的 mesh 无 UV2/UV3 数据也被变形逻辑影响 |
| 修改 | 动画代码从三套稳定 Shader **全部回退**（仅保留 `Cull Off`）；新建独立 `*_Transition` Shader，稳定渲染永不加载动画代码 |
| 附带 | 阶段三 Chunked 此前的"散点/缺面"几何损坏实为同一动画 Shader 代码所致，回退后 `Chunked` 恢复可用 |

### 问题 2：F10 突起"地图先是突变突出一小段，再上升才成型"

| 项 | 内容 |
|---|---|
| 现象 | 原地块高度不一（平地/高地/海底），动画开始瞬间相关地块突变为平整地面（最终平台拓扑），然后整体上升 |
| 初步误判 | 双重 smoothstep 缓动（C# Tick 已缓动 + Shader 再 smoothstep）+ 错峰过长 → 已先修（Shader 改线性插值、`LocalProgress` 去二次缓动、`StaggerSpan` 0.6→0.35），**未解决** |
| 诊断结论 | F12/染色诊断逐层确认：材质切换成功、MPB=0 正确、Tick/Finalize 正常、mesh UV2/UV3 数据完全正确（participates 全部=1、startY 各异）——**问题不在数据通道** |
| 真实根因 | 动画 staging 是按**目标平台数据重新生成的最终拓扑**。旧地形的不同高度、海床、水岸、坡/阶梯过渡连接关系在 Commit 换 mesh 时已消失；Shader 只能插值顶点 Y，无法从最终平台拓扑还原旧拓扑 → 画面必然先"变平"再"整体升起" |
| 修改 | 尝试过两版方案（见问题 5、6），最终**硬回退为纯顶点 Y 插值**（见问题 6），拓扑过渡列为遗留事项 |

### 问题 3：突起时对应地块迷雾没有去除

| 项 | 内容 |
|---|---|
| 现象 | 竞技场 37 格突起后迷雾仍然遮盖 |
| 根因 | `ForceRefreshFogVisuals` 走 `RequestTransition` 渐变，`FogTransitionManager.TransitionSpeed=0.5/s`（0→1 需 2 秒），动画 1.2s 结束时迷雾仍浓；文档 §18.2 要求"突起帧 37 格瞬间点亮" |
| 修改 | `IMapRenderBackend.ForceRefreshFogVisuals(snapCells=null)` 新增 snap 参数；`MapRenderer`/`ChunkMapRenderer` 对指定格 `SnapTransition`（瞬间点亮），其余格保持渐变；`ArenaEventManager.Activate` 传 `_arenaCells`；释放 lease 的恢复路径仍走渐变（"重新聚拢"语义不变） |

### 问题 4：诊断染色实验（过程性，已移除）

| 项 | 内容 |
|---|---|
| 目的 | 区分"数据层 vs Shader 读取层"（临时加 `diagParticipates` 染红 + F12 打印 UV 分布） |
| 结论 | mesh 数据 100% 正确；`TerrainBase_Fog_Transition`（solid）在 GPU 读不到 `texcoord2`，而过渡区两套 Shader 能读到——一度误判为 surface shader 按 Input 裁剪 appdata，尝试自定义 `appdata_anim` 结构，无效果后放弃该方向 |
| 修改 | 全部诊断染色、F12 调试方法、逐帧日志**已移除** |

### 问题 5：A+C 混合·dither 抖动交叉淡化（沙化颗粒）

| 项 | 内容 |
|---|---|
| 现象 | 旧 Terrain 快照 + 新平台双层不透明抖动交叉淡化，实机"一阵沙化的感觉，星星点点的" |
| 根因 | dither 按像素 hash 随机 clip，两层散点像素互相闪烁，颗粒感强（尤其高度差大的区域） |
| 修改 | 放弃 dither，改为"顶出 clip 平面"（见问题 6） |

### 问题 6：顶出 clip 方案（红黑效果）→ 最终硬回退

| 项 | 内容 |
|---|---|
| 现象 | 平台从旧地表逐像素 clip 顶出方案，实机"红黑效果" |
| 根因分析 | ① 红：三套 Shader 已无红色代码，实机红色来自 **Unity 未重新导入新 Shader**（GPU/材质仍用含诊断染色的旧版）——已要求 Ctrl+R 强制刷新；② 黑：`clip(-1.0)` 裁掉非动画区后，旧地形快照在部分环境未正确填补；且 ShadowCaster pass 不执行 surf 的 clip，平台 mesh 全尺寸投阴影形成"隐形地形黑块"（曾尝试动画期间关闭阴影） |
| 最终决策 | **硬回退**：删除全部红黑相关代码——旧 Terrain 快照（`CaptureTerrainGhost`/`FadeTerrainGhost`）、`clip()`、dither、`_TransitionRole`、阴影切换、participates 0/1 区分。三套 Transition Shader 仅保留**纯顶点 Y 插值动画**（UV2/UV3 数据、`_ChunkProgress`、材质切换、Finalize 恢复全部保留） |
| 静态验证 | 三套 `*_Transition.shader` 已无 `diagParticipates` / 红色 / `TransitionDither` / `TransitionRole` / `clip`；`MainGame.csproj` 编译 0 error |

## 四、遗留事项

1. **拓扑过渡动画**：真正的"旧地形平滑过渡到平台"需要旧拓扑快照层（A+C 或顶出 clip），当前实现均引入红黑/沙化副作用，暂缓。后续方向：先解决 Shader 未重新导入时的排查流程（实机验证前必须 Ctrl+R + 重新进入 Play），再评估"旧快照 + 新平台"双层的深度处理方案。
2. **`TerrainBase_Fog_Transition` 的 texcoord 读取**：诊断曾发现 solid 区 GPU 读不到 `texcoord2`（与 Input 字段数相关的 surface shader 编译行为），自定义 `appdata_anim` 实验未成功即放弃——若后续恢复拓扑方案需重新验证。
3. **阴影一致性**：若恢复 clip 类方案，ShadowCaster pass 必须同步裁剪（或动画期间关阴影），否则出现"隐形地形黑块"。
4. **实机验证前置**：`.shader` 文件修改后 Unity 失焦不会自动重新导入，必须 Ctrl+R 强制刷新并重新进入 Play，否则一切 Shader 改动不生效（本次多次"没效果/红黑"的重要干扰项）。
