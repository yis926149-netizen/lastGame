# 不可放置区域红色遮罩 · 实施问题记录与最终方案

> 目的：记录本次「屏幕空间 UI 红色遮罩」的实施过程、踩到的坑、**真正的根因**，以及最终落地的路线三方案。
> 关联设计文档：`不可放置区域红色遮罩实现方案.md`
>
> ⚠️ **本文档 2026-09-01 大幅修订**：原「问题 B」根因判断（怪 `PickNextByLeftHand` 转角公式）**是错的**。
> 前两版轮廓追踪失败、以及「马赛克拼接」观感，是**同一个根因**：噪声扰动击穿了浮点坐标角点焊接。
> 详见 §4.1。若按原结论去重写左手法则，会第三次失败。

## 1. 需求回顾

卡牌「提起」时，把**不可放置的地块区域作为一个整体**，用一层半透明红色遮罩圈出来，要求：
- 覆盖地块主体及地块之间的矩形/三角过渡区；
- 看起来是**一整片连续、平滑**的红色区域，而不是「每个六边形各一块」的割裂/马赛克感。

已确认的三项决策：
1. 红区**不过滤山格**：非清除山脉整片算入不可放置集（`CanBuildOnCell`/`CanSpawnUnitOnCell` 拒绝非清除山格，快照已含它们），故山脉被整片圈红；
2. 相机是**透视**相机；
3. 红区口径 = 不可放置地块（全图口径，`PlayerInputHandler.RaisedUnplaceableCells`）。

## 4. 依次遇到的问题与根因

### 问题 A：时序导致快照读空（已解决）
- **现象**：提起卡后 `RaisedUnplaceableCells` count=0，Rebuild 早退。
- **根因**：`PlacementRangeMaskUI.Update`（MonoBehaviour）与 `PlayerInputHandler`（`ITickable`）在同帧运行，顺序不保证；提起卡变化那一帧，遮罩组件先于 PlayerInputHandler 跑，读到的是上一帧的空快照。而原逻辑只用「卡引用变化」这个一次性触发，错过后永不重建。
- **解决**：脏检测改为「卡引用变化 OR 快照数量变化 OR 相机变化」。快照从 0→598 的那一帧靠「数量变化」补上重建。

### 问题 B：整体外轮廓追踪算法在真实数据上崩溃

尝试过两版「求区域整体外轮廓」的算法，都失败：

- **第 1 版（有向边 pick-first 串环）**：582 格的单一连通区域，本应产出 1 个大外环，却产出 **35 个碎环**（多为 3 点近共线）。
- **第 2 版（左手边界追踪 / 无向边奇偶剔除）**：改用「无向边出现奇偶剔除内部边 + 相对来路转角选边」，582 格的外轮廓**只追踪出 6 个点**（一个单格小六边形）。

> ❌ **原记录的根因判断是错的**。原文把第 1 版怪到「T 型交叉处顶点度数 > 2」、把第 2 版怪到
> 「`PickNextByLeftHand` 转角公式方向不对」。两条都不成立，真正根因见 §4.1。
> 尤其「T 型交叉度数 > 2」与事实相反——六边形网格里 T 型交叉**根本不可能存在**（见 §4.1 的度数不变量）。

### 4.1 ⭐ 真正的根因：噪声扰动击穿了浮点坐标的角点焊接

`HexMetrics.Perturb`（`HexMetrics.cs:42-43`）把每格的 `RealCenterWorldCoordinate` 在 XZ 上
**逐格独立**推开 ±0.2。旧实现绕着这个**扰动后**的格心画正六边形，于是：

- 相邻两格「本该重合」的公共角点，实际相差 **0.1~0.4**（而六边形半径才 3）；
- 旧 `PlacementMaskGeometry.Quantize` 按 **0.01** 精度量化坐标来焊接角点 → **永远焊不到一起**；
- 内部边因此一条也剔不掉（`(kv.Value & 1) == 0` 筛不掉任何东西），
  邻接表退化成 **582 个孤立六环** → 这才是「只追踪出 6 个点」的真正原因；
- 同一个扰动让逐格填充之间**既重叠又漏缝**。Stencil 只能消重叠，**对缝隙无能为力**，
  漏出的背景亮线就是「马赛克拼接图」的网格纹来源。

**一个根因，两处症状**：轮廓追踪失败 = 马赛克观感 = 同一个扰动。

### 4.2 ⭐ 为什么单元测试没拦住

旧 `PlacementMaskGeometryTests.cs:40` 的夹具是：

```csharp
cell.RealCenterWorldCoordinate = new Vector3(wx, 0f, wz);   // 未扰动！
```

夹具喂的是**精确格心**，浮点焊接在夹具里完美成立、在真机里必然失败——
bug 正好从测试缝里溜过去，还倒过来给了「几何算法没问题」的错误信心。

> **教训**：几何测试的夹具必须复现生产数据的**噪声特性**。喂理想值的几何测试是假阳性温床。
> 新 `PlacementMaskTopologyTests` 的夹具**刻意注入 ±0.2 确定性伪随机扰动**：
> 一旦实现回退到读 `RealCenterWorldCoordinate`，用例立刻失败。

### 4.3 ⭐ 度数不变量：T 型交叉不可能存在

任一角点恰由 3 个互为邻居的格共享，这 3 格贡献 AB/BC/CA 三条边。按「在集合内的格数」统计该角点的边界边度数：

| 在集合内的格数 | 0 | 1 | 2 | 3 |
| --- | --- | --- | --- | --- |
| 边界边度数 | 0 | 2 | 2 | 0 |

**恒为 0 或 2**。所以边界必然是若干条**互不相交的简单闭环**，追踪只需「走向非来路的那个邻居」，
**不需要左手法则、不需要转角比较**——前两版的脆弱性来源被整体消除，而不是被调参绕过。

（该不变量已用穷举脚本在凹形、带洞、离散多形状上验证，并由 `Build_EveryBoundaryCornerHasDegreeTwo` 守住。）

### 问题 C：逐格填充的马赛克叠加
- 放弃外轮廓后，改用**逐格扇形三角化直填**。形状正确，但相邻格半透明红在边界处 alpha 叠加 → 深浅不均的网格纹。
- **当时的处理**：`PlacementRangeMask.shader` 用 Stencil（`Ref 1, Comp NotEqual, Pass Replace`）保证每像素只上色一次。
- **实为治标**：Stencil 只消重叠，缝隙依旧。路线三顶点去重后**严格密铺**（既无缝也无叠），
  Stencil 失去存在理由，shader 已删。

## 5. 路线三如何逐条解决原有观感问题

> **注**：本表的「锯齿→连续曲线」一栏，最初落地方案是 Catmull-Rom 重采样；
> 后经真机观察发现它**只能把锯齿磨圆、磨不掉**（插值样条穿过每个输入点），
> 遂换成「DP 简化 + 定半径圆角」两段式，见 §5.1。表内已按最终方案更新。

| 原问题 | 路线三的解法 |
| --- | --- |
| 1. 边缘是六边形锯齿轮廓 | 追踪出**整体边界闭环**后做 **Douglas-Peucker 简化**（把 0.5R 锯齿当噪声删掉，留下直线段）+ **定半径圆角**（每个折角换一段二次贝塞尔），六边形折角被拟合成「直线 + 圆角折线」 |
| 2. 红色发灰、像蒙了层脏色 | 填充 alpha 压到 **0.55**（真机标定值；初版建议 0.16 实测太淡），只作「氛围底」；对比度全押在描边上 |
| 3. 没有边界强调 | 新增**羽化描边缎带**：每点 3 列顶点（外缘 a=0 / 中线 a=0.95 / 内缘 a=0），屏幕空间恒定粗细（**12f**，真机标定值；初版 2.6f 太细） |
| 4. 红区几乎铺满全屏、压抑 | 同第 2 条。582/598 格铺满屏时，低 alpha 底 + 强描边读作「圈出一个区域」而非「盖了层脏色」 |

**关键实现选择**：

- **角点身份用立方坐标三元组，不用浮点坐标**。每个角点恰由 3 个互为邻居的格共享，
  把这 3 个立方坐标排序后作为键 → 「是否同一角点」变成**整数相等判定**，与噪声扰动彻底无关。
  这是对 §4.1 根因的正面修复，而非规避。
- **角点由「未扰动格心」推出**（`CenterWorldCoordinate + Height * elevationStep`，
  与 `MeshDataGenerator.SolidAreaCenterWithoutPerturb` 同式），换来严格密铺。
  代价：遮罩边界与地形 silhouette 最多差 **0.2 世界单位**，在半透明层上不可见。
- **共享角点的 Y 取均值**，让高差处的角点高度连续，避免描边在陡坡处跳台阶。
- **洞环同样描边**：被不可放置格包围的可放置格孤岛，值得圈出来。
- **描边居中于路径**，故不依赖闭环绕向（追踪出的环 CW/CCW 不定，刻意不做绕向归一化）。
- **投屏失败（相机背后）的处理**：填充层按顶点重编号剔除牵连三角形；
  描边层则**整环作废**——拆环会连出跨屏的错误线段。

### 5.1 轮廓拟合：为什么「先简化、再圆角」，以及容差为何不能更大

描边层对每条闭环依次做：**世界空间简化 → 定半径圆角 → 投屏 → 去重 → 羽化缎带**。
简化与圆角都放在**投屏前的世界空间**，容差以六边形外接圆半径 `R` 为单位有稳定几何含义，
且推拉相机时轮廓形状不变（放在屏幕空间，缩放会改变简化力度）。

**Step 1 · Douglas-Peucker 简化**（`PlacementMaskOutline.SimplifyClosed`，容差 `eps = 0.6R`）

闭环没有天然端点，直接跑 DP 会把「起点附近」永久钉死。做法是取离 `loop[0]` 最远的点作
第二锚点，把闭环拆成两条开链分别简化——两个锚点都落在轮廓极值上，不会卡在锯齿中间，
结果对起点选择不敏感。

> **为什么必须先简化、而不是直接平滑（Catmull-Rom 为什么被换掉）**
> Catmull-Rom 是**插值**样条，穿过每一个输入点。六边形边界的锯齿**本身就是顶点**，
> 样条只会把锯齿磨圆，磨不掉——观感仍是「沿地块的波浪边」。要先得到直线段，
> 必须把锯齿当噪声**删掉**，而不是柔化它。

> **容差为什么卡在 0.6R，不能再大（几何有硬约束）**
> 直边上的锯齿振幅 = `R − R·cos60°` = **0.5R**；孤立单格「角点相对邻角连线」的凸起
> = **也是 0.5R**。二者在垂距意义上**不可区分**，所以没有任何容差能同时「抹平锯齿」
> 和「保住孤立六边形的六角形状」。实测窗口：`eps > 0.5R` 才开始抹锯齿；
> `eps ≥ 0.8R` 会连「单格凹口」这类真实特征一起丢。取 **0.6R** 居中——
> 代价是孤立单格必然塌成四边形（配上圆角后是个圆润小块），这是自觉接受的取舍。

**Step 2 · 定半径圆角**（`PlacementMaskOutline.RoundCorners`，半径 `0.55R`，每折角 5 段贝塞尔）

简化留下的是「直线 + 折角」折线。每个折角替换为一段二次贝塞尔（切点 → 顶点 → 切点）。
切点距离 `t = radius / tan(θ/2)` 且**夹取到相邻边半长**——这保证圆角**永不外溢出原轮廓**，
即使半径远大于边长或遇到极锐角。夹取的副作用是锐角处圆角自动变小，正是想要的行为。

**Step 3 · 投屏后去重**（`PlacementMaskOutline.DedupClosed`，阈值 0.5 Canvas 单位）

圆角段在「切点被夹到边中点」时会产出**重合点**，缎带的角平分线在重合点处退化为尖刺。
`RoundCorners` 又会造出 `CornerWorld` 里不存在的**新点**，故描边层不能复用 Rebuild 那
张「整体投屏表」，只能逐点现投，投完再去一遍重（含首尾环绕）。

衡量这条流水线的两个测试：
`SimplifyClosed_FlattensSawtoothAlongStraightRun`（12 格直排 → 简化后 ≤8 点）守住「锯齿被抹平」；
`SimplifyClosed_PreservesSingleCellNotch`（5×5 挖掉边界一格 → 简化后凹口必须比无凹口版多转折点）
守住「容差没把真实特征吞掉」。加 `RoundCorners_NeverOvershootsInputBounds`（尖刺多边形，半径 2/5/40）
共 5 个新用例，拓扑层测试从 14 例增至 **19 例**。

## 7. 关键代码事实（供接手参考）

- 六边形几何：`MapGenerationConfigSO.OuterRadius = 3f`，`InnerRadius = OuterRadius * 0.866`，尖顶布局；角点相对格心角度 `{0,60,120,180,240,300}`（+Z 为 0°，顺时针）。角点世界坐标计算见 `MeshDataGenerator.cs:84-99`。
- **⚠️ 噪声扰动**：`HexMetrics.Perturb`（`HexMetrics.cs:42-43`）把 XZ 逐格独立推开 **±0.2**。
  凡是「跨格拼接几何」的需求，都**不能**基于 `RealCenterWorldCoordinate` 做浮点坐标焊接，
  必须走网格拓扑身份（见 §4.1）。`MeshDataGenerator.ExtractSphereOfInfluenceBoundary`
  的 `QuantizeKey` 有**同一个隐患**，若哪天用到跨格拼接需一并检查。
- 方向枚举：`Enums.HexDirection { NE, E, SE, SW, W, NW, None }`，遍历邻居必须 `for i in 0..5`（None=索引6 会走到 GetNeighbor 的 default: return null）。
- 邻居查询：`IMapDataService.GetNeighbor(cell, dir)`；立方坐标偏移见 `HexMapService.cs:162-168`。
  **但角点身份必须用算术偏移**而非 `GetNeighbor`：图外邻居同样参与角点身份，`GetNeighbor` 对图外返回 null 拿不到坐标。
- 目标 Canvas：`[Inject(Id="TargetUICanvas")]`，实测 renderMode = **ScreenSpaceOverlay**（投屏时 uiCam 传 null）。
- 提起态快照出口：`PlayerInputHandler.RaisedUnplaceableCells / RaisedPlaceableCells`（只读，`GetAllCells` 全图遍历，**不含山格过滤**）。
  快照是 `GetAllCells()` 的一次二分，故**不含重复格**——度数不变量在生产数据上成立。
- UGUI 坑：本工程（Unity 2022.3）`AddComponent` 建 `Graphic` 子类**不会隐式补 `CanvasRenderer`**，必须手动 `AddComponent<CanvasRenderer>()`，否则 `Rebuild()` 首行即早退、永不出 mesh（见 `UITrailRenderer.cs:269-276`）。
- 3 列羽化缎带是本工程既有手法，参考 `HexHighlightRenderer.AppendGlowBeamQuad`（`HexHighlightRenderer.cs:304-333`）：不需要专用 shader 也不会出硬边「纸片」。
- 相机：`Camera.main`，由 `CameraController` 驱动，透视，「缩放」是沿视线推拉距离（非正交尺寸）。
