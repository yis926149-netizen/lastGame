## 一、审计结论与执行红线

原清单方向基本正确，但有以下必须先修正的结论：

1. **不得按原 A5 的 `MeshDataGenerator.cs:2019-3024` 范围删除。** 该范围绝大多数是仍在执行的 `BuildTriStep3*` / `BuildTriStep4*` 三角过渡算法，仅夹有少量旧赋值注释。
2. **不得随 C1 删除 `Fog.mat` / `Fog.shader`。** `MapGenerationConfig.asset.fogMaterial` 仍指向 `Fog.mat`，`MapRenderer.SetupFogGlobalShaderProperties` 仍从中读取 `_MainTex` / `_Color` 并设置全局 `_FogTex` / `_FogColor`。
3. **不得把 `MapRenderer` 整体视为可直接删除的 WholeMap 后端。** Chunked 首次启动仍由 `GameFlowManager -> MapRenderer.MapRender()` 分派，且全局迷雾初始化、地貌/资源实例化、环境雾、`FogInit` 和费用标签仍由 `MapRenderer` 协调。
4. **不得随顶点色链删除 FogMask 管线。** `FogTransitionManager -> HexCellData.FogAlpha -> _FogMaskTex -> FogBlend_final` 是当前实际迷雾管线；顶点色 R/G 才是零消费者兼容链。
5. **不得在 B3 阶段删除 WholeMap 的 `MeshTransitionVertexRanges`。** 它除迷雾颜色外还被 `ApplyStylizedTransitionNormals` 使用；只能等法线范围迁移或 WholeMap 几何删除后再删。
6. **不得把所有 `MapController.CreatMesh` 重载一起删除。** 通用重载仍被 WholeMap River/Water/Grid、势力范围、玩家模型线和测试使用；Chunked 也仍使用 `MapController` 的材质、法线和切线辅助函数。
7. **TerrainGhost、Transition 材质缓存、`MapInteractionGate`、`TemporaryVisibilityService`、`FogTransitionManager`、`MapChunkView`、`IMapRaycastService` 和强类型 `MapChangedEvent` 是正式能力，不属于整模块清理对象。**

## C 类：需场景/架构决策，不可直接删除

### C1：地图外围 FogCover / FogConnector

**静态审计结论：它们不是探索状态迷雾，而是地图边缘封皮/斜坡/露底填充。**

- `FogCover`：激活的场景对象；`fogInit` 后按 `fogCoverWidth` 生成矩形环形封皮，并创建 Connector。
- `FogCover_two`：激活的第二层封皮，固定宽度 1，整体上移 0.05。
- `FogConnector`：不是场景对象，由 `FogManager` 运行时动态创建；连接真实不规则地图边缘、MinY 斜坡和矩形封皮内边。
- `FogConnectorMeshTests` 当前只测 `GenerateSlopeMesh`，没有覆盖生产入口 `GenerateConnectorMesh` / `GetFogConnectorBoundaries` / 材质接线，不能作为整条 Connector 正确性的证明。

**当前材质接线状态：**

- GameScene 的 `FogCover.connectorMaterial` 已指向 `FogConnector.mat`，运行时 Connector 会克隆专用的 `Custom/FogConnector` 材质。
- `connectorMaterial == null` 时仍会走代码 fallback：新建 `Custom/FogConnector` 材质并从 `fogCoverMaterial` 拷贝 `_MainTex` / `_Color`。
- 专用材质接线已完成，仍需 Unity 内目视验收 Connector 与 FogCover 的纹理连续性和地图边缘遮盖。

**决策分支：**

- 若外围封皮承担最大相机范围下的地图边缘遮盖：保留 FogCover/Connector（专用材质接线已修正），并补生产路径测试。
- 若确认删除：删除 FogCover/FogCover_two 场景对象、动态 Connector 逻辑、`FogCover.mat` / `FogCover_two.mat` / `FogConnector.mat` 及专用 Shader、对应 MeshGenerator 边界 API 和测试。
- **两种分支都保留 `Fog.mat` / `Fog.shader`，除非先把全局迷雾纹理/颜色迁移到独立配置。**
- `fogCoverWidth` 同时被 `CameraController` 用作边界 padding。若删除封皮，应迁移/重命名为相机边界参数，而不是保留错误语义名称。

### C2：GridMesh 应拆成两项

#### C2-A：旧高亮 fallback（可先删）

#### C2-B：G 键全局格线（产品决策）

`GridMesh` 仍有独立职责：WholeMap 为每格创建 `SubGridLine_*`，G 键切换 `MapGenerator.gridGameObject`。Chunked 没有等价全局格线，当前两后端行为不一致。

若决定取消全局格线，需同步删除：

- `MapRenderer.GridMeshCreat` / `RebuildGridCell`；
- `HexCellData.GridMesh`；
- `MapGenerator.gridGameObject`；
- `IMapDataService.UpdateRuntimeData` / `HexMapService` 的 grid 参数；
- `PlayerInputHandler` 的 G 键切换。

若需要保留 G 键功能，应先为 Chunked 实现等价 Chunk Grid，再决定是否清理 WholeMap 单格网格对象。

### D1：可直接做的签名/死字段清理

### D2：接口收窄候选

- `IMapRaycastService.IsMapObject`：只有 `MapRaycastService.RaycastMap` 内部调用，可从接口移除并改为 private helper。
- `IMapRaycastService.GetCellByWorldPosition`：当前只是转发 `IMapDataService`，且唯一调用方 `CardController` 已持有 map data service。可删除，或改为让射线服务返回包含 cell 的统一命中 DTO；需先确定接口职责。

### D3：前瞻占位 API（需产品决策）

- `MapTransitionStagger.OuterToCenter` / `Random` / `Directional` / `Wave`：当前未实现，只警告并降级为 `Simultaneous`；生产只用 `Simultaneous` / `CenterToOuter`。若第一版不承诺，删除成员与降级测试；若未来地震/洪水需要，则保留并明确标注未支持或补实现。
- `HexHighlightChannel.AttackRange` / `Selection`：当前零调用方。近期无接入计划可删；属于明确公共扩展契约则保留。

### D4：实验门控与旧兼容模式

- `enableExperimentalChunkRenderer`：Chunked 已实机验证，但仍与 `MapRenderMode` 构成双重门控。完成终态 A/B 截图、连续激活资源稳定性和停止游戏 ghost 清理验证后，可先去掉实验开关，仅保留模式选择；若仍需紧急回退则暂留。
- `TransitionGenerationMode.Legacy`：见 C3，仅 WholeMap 消费。

### D5：分帧提交整组（暂不建议删除）

删除 B1 后，`CommitSliced` 将没有生产玩法调用方，只剩阶段五测试；但它是大范围洪水/地震/地图编辑器的正式性能能力。除非明确放弃这类需求，否则保留：

- `CommitSliced` / `HasSlicedCommitPending` / `TickSlicedCommit` / `ForceCompleteSliced`；

### D6：协议字段（保留）

`MapChangedEvent.AffectedChunks` 当前主要由测试读取，但它属于正式强类型事件和后续诊断/观察者扩展点。不要仅因当前无生产订阅者删除；更合理的后续是让脏 Chunk 可视化真正消费它。
