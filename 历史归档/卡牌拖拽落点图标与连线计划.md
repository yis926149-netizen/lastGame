# 卡牌拖拽落点图标与连线计划

> 版本：v1
> 目标：解决「视觉位置（手里的卡牌）」与「逻辑位置（上移后的落点）」在观感上的断裂。
> 手段：① 在逻辑位置的世界空间放一个醒目图标（**仅可放置时显示**）；② 在 UI 画布上用一条直线把图标与卡牌连起来。

**前置**：本计划建立在 `卡牌拖拽统一上移-修改计划.md`（v3）已落地之上。当前 `GetCardDragLogicPosition`
已被**模型预览、地块高亮、落点判定**三者共用（见 §1.1），本计划不改动这套坐标语义。

---

## 一、现状与问题

### 1.1 现在的坐标分工（已实现，本计划不改）

| 用途 | 坐标 | 代码位置 |
|---|---|---|
| 卡牌 / 幽灵卡 UI 位置 | 原始触点 | `CardController.OnDrag`（:376） |
| 世界空间模型预览 | **逻辑位置** | `CardDragWorldPreviewController.TrySnapToTerrain`（:239） |
| 可放置地块高亮 | **逻辑位置** | `PlayerInputHandler.HighlightGridOnMouseHover`（:112） |
| 松手落点判定 | **逻辑位置** | `CardController.OnEndDrag`（:404） |

即模型、高亮、落点三者已经重合于逻辑位置（`卡牌拖拽统一上移-修改计划.md` §七中"模型在触点、高亮在其上方"
的描述已过期）。**真正剩下的断裂只有一处**：手里的 2D 卡牌 ↔ 上方的 3D 模型 + 高亮。

### 1.2 问题

1. 逻辑位置目前只有一圈黄色六边形描边（`HexHighlightRenderer`，`HexHighlightChannel.CardPlacement`），
   在复杂地形 / 密集单位下辨识度低。
2. 卡牌与落点之间没有任何视觉关联，玩家需要自己脑补"我手上的东西会掉到上面那格"。

## 二、总体设计

```text
             ┌──────────┐
             │   图标    │  ← 世界空间，billboard，仅「可放置」时显示
             └────┬─────┘
                  │
             ┌────┴─────┐
             │ 模型预览  │  ← 已有，位于 hit.point + hoverHeight
             └──────────┘
        ╭───── 高亮六边形 ─────╮  ← 已有，逻辑位置所在格
                  ╎
                  ╎  ← 连线（UI 画布，Image 拉伸+旋转）
                  ╎
             ┌────┴─────┐
             │  卡牌     │  ← 原始触点（手指压在这）
             └──────────┘
```

三条硬约束：

1. **图标锚在地块中心，不锚在 `hit.point`。** 用 `cell.RealCenterWorldCoordinate`，
   与高亮六边形完全对齐，并且天然消除手指抖动造成的图标晃动。
2. **图标只在「该格可放置」时显示。** 与高亮完全同源：`ICardDropHandler.CanDeployTo`
   （`PlayerInputHandler.CanHighlightCellForCard`）。射线未命中、或命中但不可放置 → 隐藏。
3. **连线与图标共存亡。** 图标隐藏时连线必须同帧隐藏，不允许出现连向虚空的线。

## 三、必须先做的两件事（进入编码前）

### 3.1 先调偏移量，再动手

当前 `CardDragLogicOffsetRatio = 0.065f`（`CardController.cs:47`）。在 1080×1920 设备上
偏移约 125 设备像素，Canvas 按高度匹配（`UIScreenHelper.ReferenceHeight = 1920`）时约合 125 Canvas 单位。

**这个距离对连线来说太短**：图标本身要占几十单位，剩给线的长度可能只有几十单位，
做出来的效果是"卡牌顶上有个小毛刺"，而不是一条有指向感的线。

行动：编码前先把常量临时改到 `0.10f ~ 0.12f` 在编辑器里跑一遍，确认距离感成立后再定值。
该常量被模型预览 / 高亮 / 落点三者共用，改一个数三处同步，无额外风险。

### 3.2 统一射线最大距离（推荐一并修，否则图标会"凭空消失"）

现存不一致：

| 调用点 | maxDistance |
|---|---|
| `CardDragWorldPreviewController.TrySnapToTerrain`（:240） | **300**（显式传参，注释说明最大缩放下需 ~160） |
| `PlayerInputHandler.HighlightGridOnMouseHover`（:115） | 100（默认值） |
| `CardController.OnEndDrag`（:411） | 100（默认值） |

高缩放下会出现「模型仍在跟随地形，但高亮与落点射线已打不到」的窗口。今天的表现只是高亮闪断，
加入图标后会变成**图标突然消失**，非常显眼。

建议：把后两处显式改为同一个 300。为避免魔数三处散落，把
`CardDragWorldPreviewController.RaycastMaxDistance` 提升为
`CardController` 上的 `public const float CardDragRaycastMaxDistance = 300f`，三处共用。

> 若决定不做 3.2，则必须在验收中显式记录"最大缩放下图标可能消失"为已知限制。

## 四、新增文件与职责

### 4.1 `Assets/Scripts/UI/CardDragPreview/CardDragTargetMarkerView.cs`（新建，MonoBehaviour）

世界空间图标视图。**直接照搬 `PublicBuildingMarkerView` 的成熟范式**，不要新造轮子：

- world-space Canvas + `Image`；
- `LateUpdate` 中 `transform.LookAt(pos + cam.forward, cam.up)` 做 billboard；
- `Awake` 中把自身及全部子物体设到 `Marker` 层，调用 `MarkerOverlayCamera.Ensure(Camera.main)`，
  并 `mainCamera.cullingMask &= ~(1 << markerLayer)`。

**必须自己调用 `MarkerOverlayCamera.Ensure`**：该叠加相机目前只由 `PublicBuildingMarkerView.Awake`
创建，若本局尚未出现任何公共建筑浮标，相机不存在，图标会直接不可见。

走 `Marker` 层带来的收益（这也是选它而不是普通 world-space Canvas 的原因）：
叠加相机 `clearFlags = Depth` 且在主相机之后渲染，图标**永不被山体 / 前景单位遮挡，也不吃选择性雾化**。
逻辑位置经常落在山背后，这一点是刚需。

#### 图标外观完全由编辑器绑定，代码不碰

这是本节的硬约束：**视图脚本不创建任何 GameObject、不 `Resources.Load`、不写 sprite / color / size**。
图标长什么样、多大、有没有描边光晕子物体，全部在编辑器里做完，代码只负责位置、朝向、显隐。

```csharp
[Header("图标绑定（编辑器指定）")]
/// <summary>落点图标本体。sprite / color / RectTransform 尺寸一律在 Inspector 上设定，代码不覆盖。</summary>
[SerializeField] private Image _icon;

/// <summary>可选：与图标一起显隐的装饰（光晕、箭头、外圈等）。留空即不使用。</summary>
[SerializeField] private GameObject[] _decorations;
```

约定：

- `_icon` 未绑定时，`Awake` 打一条 `Debug.LogError` 并让本视图恒隐藏（**不静默降级**——
  否则表现为"功能没生效"，排查成本远高于一条报错）。
- 代码对 `_icon` 唯一的写操作是 `SetActive` 层面的显隐（走根节点），不写 `_icon.sprite`、
  不写 `_icon.color`、不写 `rectTransform.sizeDelta`。想换图直接在 Inspector 换。
- 呼吸动画若要做，比照 `PublicBuildingMarkerView` 以 `_baseScale`（`Awake` 采样）为基准缩放，
  绝不写死 `localScale = Vector3.one`——那会覆盖你在编辑器里调好的尺寸。

> **不做按卡种切图**（不同兵种 / 建筑用不同图标）。第一版只有一个通用落点图标；
> 真要做，接口应是 `SetIcon(Sprite)` 由 `CardDragTargetMarkerController` 从
> `NormalCardConfigSO` 取，而不是在视图里查表。列入后续。

API：

```csharp
/// <summary>显示于指定地块中心上方；worldCellCenter 取 cell.RealCenterWorldCoordinate。</summary>
public void ShowAtCell(Vector3 worldCellCenter);
public void Hide();
/// <summary>连线上端点的世界坐标（图标底部），供 CardDragLinkView 反投影。</summary>
public Vector3 LinkAnchorWorldPosition { get; }
```

高度：`worldCellCenter + Vector3.up * FeelConfigProvider.CardDragTargetIconHeight`。

**不要复用 `CardDragPreviewHoverHeight`**——那是模型悬停高度（默认 1.0），图标用它会插在模型身体里。
图标必须高于模型头顶，建筑根缩放可达 2.5，初值建议 3.5 并留作调参。

> 世界空间图标会随相机拉远而变小。若希望它在屏幕上保持恒定大小，需要按相机距离补偿缩放；
> 第一版不做，先用 `cardDragTargetIconScale` 在常用缩放档位上调到合适即可。

### 4.2 `Assets/Scripts/UI/CardDragPreview/CardDragLinkView.cs`（新建，MonoBehaviour）

UI 画布连线视图。一个 `Image`，`RectTransform.pivot = (0, 0.5)`，
每帧设 `sizeDelta.x = 两点距离`、`localRotation = 两点夹角`、`anchoredPosition = 下端点`。
**不引入 UILineRenderer 或 LineRenderer**（项目当前零依赖，无必要新增一套渲染 / 材质 / 排序问题）。

同 4.1，线的外观也在编辑器绑定：

```csharp
[Header("连线绑定（编辑器指定）")]
/// <summary>线体。sprite（可用九宫格虚线图）/ color / material 在 Inspector 设定，代码不覆盖。</summary>
[SerializeField] private Image _line;
```

代码对 `_line` 只写 `rectTransform` 的 `sizeDelta.x`（长度）、`localRotation`、`anchoredPosition`，
**不写 sprite / color**；`sizeDelta.y`（线宽）由 `FeelConfigProvider.CardDragLinkWidth` 驱动，
若该值 ≤ 0 则视为"用编辑器上设好的宽度"，代码不覆盖。`_line` 未绑定时报错并恒隐藏。

**在 `LateUpdate` 中自行计算两个端点，不接受外部 push 位置**。原因：
`PlayerInputHandler.Tick`（Update）与 EventSystem 的 `OnDrag` 回调（同为 Update）执行顺序不保证，
若由 Tick 推送卡牌位置，快速拖动时线会滞后卡牌一帧、肉眼可见地脱开。LateUpdate 读当前值即无此问题。

**上端点**：`Camera.main.WorldToScreenPoint(markerView.LinkAnchorWorldPosition)`
→ `RectTransformUtility.ScreenPointToLocalPointInRectangle` 转到本 Image 父物体的局部坐标。

> 必须加 `screenPoint.z > 0` 守卫。图标跑到相机背后时 `WorldToScreenPoint` 返回镜像坐标，
> 线会瞬间甩到屏幕另一侧。不满足即隐藏连线。

**下端点**：取**卡牌顶边中点**，不取触点。

- 取触点：语义最准，但起点被手指完全盖住，实际只看到从指缝里冒出来的一截；
- 取卡牌顶边中点：线从卡牌"长"出来，视觉干净，不被手遮挡。**采用这个。**

卡牌 RectTransform 来源：拖拽中的卡牌。战术卡走幽灵卡代理，须取 `_dragProxy` 而非 `_rectTransform`
（见 `CardController.OnDragUpdate` :261 的同款判断）。为此在 `CardController` 上新增只读属性：

```csharp
/// <summary>当前拖拽中的卡牌视觉 RectTransform（战术卡为幽灵代理）；无拖拽时为 null。</summary>
public static RectTransform ActiveDragVisualRect { get; }   // 基于已有 _activeDraggingCard（:79）
```

**画布与层级**：

- 必须与拖拽中的卡牌在同一个 Canvas / CanvasScaler 体系下，否则缩放模式不一致时线的粗细与坐标都会错。
  当前手牌 Canvas 为 ScreenSpaceOverlay（见 `CardController.OnDrag` :374 注释），
  故 `ScreenPointToLocalPointInRectangle` 的 camera 参数传 `null`；**若将来改为 ScreenSpaceCamera，此处需同步改**。
- 连线必须渲染在卡牌**下方**（线压在卡面上很难看）。卡牌在 `OnDrag` 里执行
  `transform.SetAsLastSibling()`（:367），因此把连线挂为手牌面板的**前置兄弟节点**即可稳定压在其下。
- 已知：ScreenSpaceOverlay 画布在所有相机之后绘制，连线会盖在图标之上。因连线终止于图标底部，
  重叠面积极小，接受不处理。

线宽用 Canvas 参考单位（`FeelConfigProvider.CardDragLinkWidth`），不用设备像素。

### 4.3 `Assets/Scripts/UI/CardDragPreview/CardDragTargetMarkerController.cs`（新建，普通类）

图标 + 连线的生命周期与状态入口，注入 `PlayerInputHandler` 使用。

```csharp
public void SetTargetCell(HexCellData cell);   // null = 隐藏（射线未命中 / 不可放置）

```

- `Camera.main` 为空时全部按隐藏处理，不抛异常。

## 五、既有文件的修改

### 5.1 `PlayerInputHandler.cs`

`HighlightGridOnMouseHover` 是全项目**唯一**同时持有「逻辑位置命中格」与「该格是否可放置」的地方，
图标必须由它驱动。当前实现的问题：整段逻辑被 `cell != _lastDraggingHighlightCell` 包住，
**同格内不进入分支**，图标无法靠它做每帧的显示 / 隐藏。

改法：每帧先算出「本帧的可放置格」（可能为 null），无条件推给 marker controller；
`_lastDraggingHighlightCell` 缓存**只保留给昂贵的 `SetHighlightedCells` 网格重建**，不再控制图标。

```csharp
private void HighlightGridOnMouseHover()
{
    Vector2 dragLogicPosition = CardController.GetCardDragLogicPosition(_input.MousePosition);

    HexCellData placeableCell = null;
    if (_mapRaycastService.RaycastMap(dragLogicPosition, out RaycastHit hit,
            CardController.CardDragRaycastMaxDistance))          // ← §3.2
    {
        var cell = _mapData.GetCellByWorldPosition(hit.point);
        if (cell != null && CanHighlightCellForCard(cell)) placeableCell = cell;
    }

    // 图标 / 连线：每帧无条件同步（内部自行判重）。
    _targetMarker.SetTargetCell(placeableCell);

    // 高亮网格：维持原有「变化才重建」的缓存语义，行为不变。
    if (placeableCell != _lastDraggingHighlightCell)
    {
        if (placeableCell != null)
            _hexHighlightRenderer.SetHighlightedCells(
                HexHighlightChannel.CardPlacement, new[] { placeableCell }, Color.yellow);
        else
            _hexHighlightRenderer.ClearChannel(HexHighlightChannel.CardPlacement);
        _lastDraggingHighlightCell = placeableCell;
    }
}
```

> 注意这次重写顺带修掉了一个旧行为差异：原代码中「命中地图但格不可放置」只在 `cell` 变化时才清高亮，
> 从可放置格拖到不可放置格再拖回来的中间态可能残留。新写法以 `placeableCell` 为唯一真值，无此问题。
> 这属于行为收敛而非退化，验收时确认高亮无残留即可。

`ClearCardDragHighlight()`（:99，同时是 `CancelCardDragging` 的实现）必须追加 `_targetMarker.Clear()`。
该方法覆盖了松手、暂停、`CardController.ClearHighlights()` 全部收尾路径，是唯一需要挂的清理点。

本文件其余坐标一律不动（`GetCardUnderMouse` / `IsPointerOverBlockingUI` / 探索点击均须保持原始触点）。

### 5.4 `GameInstaller.cs`

在 `CardDragWorldPreviewController` 绑定附近（:355）追加：

```csharp
Container.BindInterfacesAndSelfTo<CardDragTargetMarkerController>().AsSingle()
    .WithArguments(_cardDragTargetIconPrefab, _cardDragLinkPrefab);
```

两个 prefab 为 `[SerializeField]` 字段，在 GameScene 的 GameInstaller 上赋值
（与 `TacticalCardPresenter` 取锚点的既有写法一致，:364-366）：

```csharp
[Header("卡牌拖拽落点提示")]
[SerializeField] private CardDragTargetMarkerView _cardDragTargetIconPrefab;   // 世界空间图标 prefab
[SerializeField] private CardDragLinkView _cardDragLinkPrefab;                 // UI 连线 prefab（第二批才需要）
```

字段类型直接用视图组件类型（而非 `GameObject`），Inspector 上就能拒绝拖错 prefab，
实例化后也无需 `GetComponent`。

`BindInterfacesAndSelfTo` 顺带绑定 `IDisposable`，容器销毁时视图随之清理。

#### 编辑器侧需要你完成的绑定工作（清单）

1. 做一个图标 prefab：根节点挂 `Canvas`（Render Mode = World Space）+ `CardDragTargetMarkerView`，
   子节点放 `Image` 并设好 sprite / 颜色 / 尺寸；把该 `Image` 拖到视图的 `_icon` 槽。
2. 若有光晕、外圈、箭头等装饰子物体，一并拖进 `_decorations` 数组（可留空）。
3. 根节点的 `localScale` 就是图标的世界大小，在这里调（代码只按 `cardDragTargetIconScale` 做倍率，
   以 `Awake` 采样到的 `_baseScale` 为基准，不会覆盖你调好的值）。
4. 把 prefab 拖到 GameScene → GameInstaller → `Card Drag Target Icon Prefab`。
5. 连线 prefab（第二批）：根节点挂 `CardDragLinkView`，子节点一个 `Image`（可用九宫格虚线图），
   `pivot` 设 `(0, 0.5)`，拖到 `_line` 槽；再把 prefab 拖到 `Card Drag Link Prefab`。

3. 不在「不可放置」时改变模型预览的表现（模型仍显示；只有图标与连线隐藏）。
4. 不改动放置资格判断规则（`CanDeployTo` 一字不动）。
5. 不改动 `OnBeginDrag` / `OnDrag` / `OnDragUpdate`。
6. 不引入 `LineRenderer` / UILineRenderer / 任何新渲染依赖。
7. 不做屏幕边缘的图标翻转或 Clamp（触点靠近屏幕顶部时逻辑位置出图 → 射线不命中 → 图标隐藏，
   与既有"未命中即无高亮"行为一致）。
8. 不做曲线 / 虚线 / 流动动效，第一版只有直线。
9. 不改探索点击、UI 阻挡检测、卡牌点选的原始坐标。
10. **代码不生成任何图形资源**：不 `new GameObject` 造图标、不 `Resources.Load` sprite、

12. 不做图标随相机距离的恒定屏幕大小补偿（见 §4.1 末尾）。

## 七、实施顺序（建议分两批验证）

**第一批：只做图标。** §3.1 调偏移 → §3.2 统一射线距离 → §5.5 配置 → 4.1 + 4.3 + 5.1 + 5.4。

跑一次真机。图标做到位（billboard + 呼吸 + 永不被遮挡）之后，很可能会发现**连线是多余的**——
它承载的信息量与占用的屏幕面积不成比例，且下半段本来就被手指压着。

**第二批：确认第一批仍不够时再做连线。** 4.2 + 5.2 的 `ActiveDragVisualRect`。
实现成本不高，随时可补，不必提前压上。

## 八、验收标准

**图标**

1. 拖动卡牌时，逻辑位置所在的可放置格中心上方出现图标，始终面向相机。
2. 图标位于高亮六边形正上方、模型预览头顶之上，不与模型穿插。
3. 图标被山体 / 前景单位挡住时仍完整可见，且不被选择性雾化影响。
4. 逻辑位置落在**不可放置格**时，图标隐藏，且与高亮六边形的消失严格同帧。
5. 逻辑位置射线未命中地图（如拖到屏幕顶部出图）时，图标隐藏。
6. 图标随格跳变（不随手指连续抖动），跨格时无残影、无重复实例。
7. 在 Inspector 上换掉 `_icon` 的 sprite / 颜色 / 根节点缩放后，运行时表现随之改变，
   代码不产生任何覆盖（外观完全由编辑器控制的直接验收项）。
8. GameInstaller 上图标 prefab 未赋值时，控制台出现一条明确报错，游戏其余功能不受影响、不抛空引用。
9. 本局未出现任何公共建筑浮标时，图标依然可见（即 `MarkerOverlayCamera` 由本功能自行 Ensure）。

**连线（若实施第二批）**

10. 线从卡牌顶边中点连到图标底部，全程无脱节、无一帧滞后。
11. 图标隐藏时连线同帧隐藏。
12. 图标转到相机背后 / 出屏时连线隐藏，不出现甩到屏幕另一侧的错误线段。
13. 线渲染在卡牌之下，不遮挡卡面。
14. 不同分辨率 / 宽高比下线宽与端点位置正确（Canvas 参考单位，非设备像素）。
15. 在 Inspector 上换掉 `_line` 的 sprite / 颜色后表现随之改变，代码不覆盖。

**回归**

16. 普通卡（有模型预览）与战术卡（幽灵卡代理，两个槽位）行为均正确；战术卡连线取幽灵卡而非原卡。
17. 松手落点仍与高亮 / 图标所在格一致。
18. 拖动取消、暂停、失焦、失败落点、成功放置全部路径下，图标与连线均被清理，无残留。
19. 连续快速拖多张卡，无视图泄漏（视图对象数恒定）。
20. 最大缩放下图标 / 高亮 / 落点均不消失（§3.2 生效的直接验收项）。
21. 探索点击、卡牌点选、UI 阻挡检测行为与修改前完全一致。

## 九、已知限制与风险

1. **一帧内的坐标源差异**：`PlayerInputHandler.Tick` 用 `Input.mousePosition`，
   模型预览用 `PointerEventData.position`，二者在代码层不保证同源。图标吸附格中心、模型吸附 `hit.point`，
   极小差异不可见；仅在格边界上可能出现一帧的"图标已跳格、模型未跳"。接受，纳入真机观察。
2. **图标遮挡目标格**：`cardDragTargetIconHeight` 取小了图标会压住高亮六边形。以调参解决。
3. **连线在短距离下信息量偏低**：这是 §3.1 必须先调偏移的根本原因；若最终偏移仍取 0.065，
   建议直接放弃第二批（连线）。
4. **手牌 Canvas 渲染模式**：连线实现绑定在 ScreenSpaceOverlay 假设上，改为 ScreenSpaceCamera 需同步修改（§4.2）。
5. 手指仍压在卡牌上（拖拽常态，本计划不解决，也不试图解决）。
