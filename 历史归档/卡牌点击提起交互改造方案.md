# 卡牌点击提起交互改造方案

## 0. 目标与范围

**现状**：`CardController.OnPointerEnter` / `OnPointerExit` 驱动"悬浮上移 0.025×参考高度"。移动端无悬停概念，Unity 在触摸按下 / 抬起时补发 Enter / Exit，导致该效果退化为"按住才抬起、抬手就落下"的按压反馈，且中途手指移出卡面不会 Exit。

**目标交互**：

| 操作 | 期望结果 |
|---|---|
| 轻点卡牌 | 卡牌上移并**保持**（Raised 粘滞态） |
| 轻点该卡牌外任意位置 | 卡牌落回原位 |
| 再次轻点该卡牌自身 | 落回原位（toggle） |
| 轻点另一张卡牌 | 旧卡落下、新卡提起（Raised 全局唯一） |
| 按住拖拽 | **行为完全不变**（现有 Begin/Drag/EndDrag 链路） |

**不在本次范围**：Raised 态承载的信息内容（卡牌详情面板等）——见 §7 遗留决策。

---

## 1. 总体设计

### 1.1 状态机

卡牌当前只有 `_isDragging` 单一标志。改造后为三态：

```
                 轻点自身 / 点击卡外
        ┌──────────────────────────────┐
        ↓                              │
     [Idle] ───── 轻点 ──────────→ [Raised]
        │                              │
        │ OnBeginDrag      OnBeginDrag │
        ↓                              ↓
     [Dragging] ←──────────────────────┘
        │
        └── OnEndDrag / CancelDrag ──→ [Idle]
```

- **Idle**：`anchoredPosition == _originPosition`
- **Raised**：`_originPosition + (0, ReferenceHeight × 0.025, 0)`，无 tween 回落
- **Dragging**：现有逻辑，位置由 `OnDragUpdate` 逐帧写入

**关键约束：Dragging 结束后一律回到 Idle，不回 Raised。** 否则 `OnEndDrag` 的 `ResetToOrigin()`（复位到 `_originPosition`）与 Raised 的视觉位置矛盾。

### 1.2 为什么"轻点"与"拖拽"不需要手写计时器

Unity EventSystem 的既有语义：指针按下后位移超过 `EventSystem.pixelDragThreshold` 即进入 Drag 链，`IPointerClickHandler.OnPointerClick` **不再触发**；未超阈值则只触发 Click、不触发 Drag。二者天然互斥。

**但默认阈值仅 10 像素**，高 DPI 手机上手指抖动极易越界 → 用户想轻点却触发了一次微小拖拽并弹回。**必须提高阈值**，见 §4.3。

### 1.3 Raised 与 Dragging 必须是两个独立的静态标志

`CameraController` 第 263 行用 `CardController.IsAnyCardDragging` 屏蔽相机拖动。**Raised 态不应屏蔽相机**——玩家提起卡后仍需平移地图寻找落点。因此新增独立的 `_activeRaisedCard`，**不得**并入 `IsAnyCardDragging`。

## 2. `CardController` 改动

### 2.1 新增字段与属性

```csharp
private bool _isRaised;
private static CardController _activeRaisedCard;

/// <summary>当前处于"点击提起"粘滞态的卡牌；无则 null。
/// 注意：与 IsAnyCardDragging 语义独立，不参与相机屏蔽。</summary>
public static CardController ActiveRaisedCard => _activeRaisedCard;
```

### 2.2 实现 `IPointerClickHandler`

类声明追加接口，新增：

```csharp
public void OnPointerClick(PointerEventData eventData)
{
    if (IsNextCard || _isDragging || !_isAffordable) return;
    if (_isRaised) LowerCard();
    else RaiseCard();
}
```

拦截条件与原 `OnPointerEnter` 一致（预告卡 / 拖拽中 / 买不起）。

### 2.3 提起 / 落下

```csharp
private void RaiseCard()
{
    // Raised 全局唯一：先让上一张落下。
    if (_activeRaisedCard != null && _activeRaisedCard != this)
        _activeRaisedCard.LowerCard();

    _isRaised = true;
    _activeRaisedCard = this;
    _rectTransform.DOKill();   // 见 §4.1 tween 冲突
    _rectTransform.DOAnchorPos(
        _originPosition + new Vector3(0, UIScreenHelper.ReferenceHeight * 0.025f, 0), 0.2f);
}

private void LowerCard()
{
    if (!_isRaised) return;
    _isRaised = false;
    if (_activeRaisedCard == this) _activeRaisedCard = null;
    _rectTransform.DOKill();
    _rectTransform.DOAnchorPos(_originPosition, 0.2f);
}
```

### 2.4 删除悬浮逻辑

`OnPointerEnter` / `OnPointerExit` 的 `DOAnchorPos` 整体移除。两种处理方式：

- **推荐**：从类声明中摘掉 `IPointerEnterHandler, IPointerExitHandler`，删除两个方法。
- 若 PC 端仍想保留桌面悬浮反馈：保留方法但加 `if (_isRaised) return;` 且仅在非触屏下生效（`Input.touchSupported == false`）。会引入平台分支，除非明确需要否则不做。

### 2.5 各收尾路径必须清 Raised

| 位置 | 处理 |
|---|---|
| `OnBeginDrag`（L372） | 进入拖拽前 `LowerCard()`——但**不播 tween**，见 §4.1；建议改为直接置位 `_isRaised = false; _activeRaisedCard = null;` |
| `OnEndDrag` / `CancelDrag` | 已调用 `ResetToOrigin()` / 复位，只需确保 Raised 标志为 false |
| `OnDisable`（L503） | **必须**清 `_activeRaisedCard`（卡打出后销毁），否则 `PlayerInputHandler` 持有已销毁对象引用 |
| `SetAffordable(false)`（L238-247） | 金币掉到买不起时，现有 `DOAnchorPos(_originPosition)` 分支正好复用，但**必须同时清 `_isRaised` 与静态引用**，否则视觉已落下、状态仍是 Raised |

建议新增 `ReleaseRaiseCapture()`（对称于现有 `ReleaseDragCapture`），在 `OnDisable` / `CancelDrag` 中调用：

```csharp
private void ReleaseRaiseCapture()
{
    _isRaised = false;
    if (_activeRaisedCard == this) _activeRaisedCard = null;
}
```

## 3. "点击卡外收起"的实现

### 3.1 方案选型

| 方案 | 评价 |
|---|---|
| 全屏透明 Image 遮罩 | 会**吞掉这一次点击**——玩家想"点地图放下卡"需点两次。否决 |
| 每张卡自己 `Update` 轮询 | 每张手牌每帧一次 `RaycastAll`，浪费。否决 |
| **`PlayerInputHandler.Tick` 轮询**（采用） | 复用现有 `GetCardUnderMouse()`，不吞事件，与 `HandleCardDragging` 同机制 |

### 3.2 新增 `HandleRaisedCardDismiss`

挂进 `Tick()`，置于 `HandleCardDragging()` 之后、`HandleTileClickForExploration()` **之前**（顺序关系见 §4.4）：

```csharp
private void HandleRaisedCardDismiss()
{
    var raised = CardController.ActiveRaisedCard;
    if (raised == null) return;
    if (!_input.GetMouseButtonDown(0)) return;

    // 点在卡牌自身上 → 交给 OnPointerClick 做 toggle，此处不介入，避免双重处理。
    if (GetCardUnderMouse() == raised) return;

    raised.LowerFromExternal();
    _dismissedRaisedThisFrame = true;   // §4.4
}
```

`CardController` 需暴露一个 `public void LowerFromExternal() => LowerCard();`（或直接把 `LowerCard` 提为 public）。

**注意**：点在**另一张**卡上时 `GetCardUnderMouse()` 返回新卡 ≠ raised，会走到 `LowerFromExternal()` 落下旧卡；随后新卡的 `OnPointerClick` 提起自己。结果正确，且 `RaiseCard` 内的"先让上一张落下"是幂等兜底。

## 4. 必须一并处理的冲突点

### 4.1 tween 冲突：Raised 位置 vs 拖拽起点

`OnDrag` → `OnDragUpdate` 用 `_originPosition`（**原始**位置）作为进度基准并直接写 `anchoredPosition`。若从 Raised 态起拖：

- Raised 的 `DOAnchorPos` tween 可能仍在播 → 与拖拽的逐帧赋值争抢 `anchoredPosition`，出现抖动
- 视觉起点比 `_originPosition` 高 0.025H → `_upwardDistance` 起始即为正，缩放/淡出进度**从非 0 开始**跳变

**处理**：`OnBeginDrag` 开头即 `_rectTransform.DOKill()` 并同步清 Raised 标志（不播回落 tween，因为下一帧拖拽会立即接管位置）。这一条是本次改造最容易漏、且必然可见的问题。

### 4.2 高亮闪烁：`HandleCardDragging` 的触发时机

现状 [PlayerInputHandler.cs:81-93](Assets/Scripts/Core/Services/PlayerInputHandler.cs#L81-L93) 是"按下在卡上就开高亮，抬手就清"。**轻点提起也会走完整 Down→Up**，导致地图上闪一帧红/金光。

**处理**（二选一）：

- **推荐**：把 `_isDraggingCard = true` 的触发点从 `GetMouseButtonDown` 迁移到真正的拖拽开始——由 `CardController.OnBeginDrag` 主动调用一个新的 `PlayerInputHandler.BeginCardDragHighlight(cardData, dropHandler)`。语义更准，且省掉每次按下的一次 `RaycastAll`。
- 保守：在 `HandleCardDragging` 的 Down 分支加门禁 `if (!CardController.IsAnyCardDragging) return;`。但 `OnBeginDrag` 与 `GetMouseButtonDown` 的帧序不保证，可能漏掉首帧高亮。

不改这一处，提起卡时地图会有明显闪烁。

### 4.3 `pixelDragThreshold` 抬高

在 EventSystem 初始化处（或 `GameInstaller`）设置：

```csharp
EventSystem.current.pixelDragThreshold =
    Mathf.Max(10, (int)(Screen.dpi * 0.08f));   // ≈ 2mm 物理距离
```

不做此项，移动端"轻点提起"的成功率会明显偏低。

### 4.4 与"点击地图探索"的冲突（易漏）

[HandleTileClickForExploration](Assets/Scripts/Core/Services/PlayerInputHandler.cs#L280-L328) 会把"点击未探索且相邻己方的地块"判定为探索操作。玩家为了**收起卡牌**而点地图时，若恰好点在这类地块上，会**同时触发一次非预期的探索**（消耗金币、不可撤销）。

**处理**：新增帧标志 `_dismissedRaisedThisFrame`，在 `HandleRaisedCardDismiss` 中置位；`HandleTileClickForExploration` 的 Down 分支据此把 `_explorationPointerDown` 置 false，并在该方法末尾（或下一帧 Tick 开头）复位标志。

即：**收起卡牌的那一次点击只用于收起，不产生其他游戏行为**。这与 §3.1 否决遮罩方案的"不吞事件"并不矛盾——此处是有意针对探索这一条高风险路径做屏蔽，而非全局吞掉。

> 是否也要屏蔽相机拖动？不需要。收起是在 `GetMouseButtonDown` 判定的，而相机平移需要位移，两者不冲突；且允许"按下收起卡牌 + 继续拖动地图"的连贯操作反而更顺手。

### 4.5 暂停 / 场景切换

`GameLoop.IsPaused`、状态机切换等路径若会隐藏手牌，需保证 `OnDisable` 走到 `ReleaseRaiseCapture()`（§2.5 已覆盖）。

## 7. 遗留决策（建议实施前确认）

1. **Raised 态要承载什么？** 单纯上移 0.025H 对触屏用户不提供任何新信息，反而在"打出卡牌"路径上**多加了一次点击**。若不打算在提起后展示卡牌详情 / 效果说明 / 可放置区域预览，这个状态对玩家是净负担。建议明确其信息载荷后再实施。
2. **是否保留 PC 端悬浮？** 若发布目标含 PC，桌面用户失去 hover 反馈会有落差（§2.4 给了平台分支方案，代价是多一条分支）。
3. **Raised 是否应显示放置高亮？** 若希望"提起 = 预览可放置区域"，则 §4.2 的高亮触发改造需扩展为同时响应 Raised 态——会与 §4.4 的探索屏蔽产生更多交互，建议作为后续迭代而非本次范围。
