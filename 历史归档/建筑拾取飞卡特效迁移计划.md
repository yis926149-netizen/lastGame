# 建筑拾取飞卡特效迁移计划

> 目标：让 `PublicBuilding_Collectible` 拾取奖励卡时，复用「战术卡牌飞入」的两段式飞卡表现。奖励卡从建筑根格位置飞入玩家手牌 slot 0。
> 参考实现：`Assets/Scripts/TacticalCard/TacticalCardPresenter.cs` 的 `AddCardWithFly` / `PlayFlySequence`；其视觉参数可复用，但其固定 10 秒 DOTween driver 不能照搬。
> 状态：已实施（代码已按本计划落地；运行时验收项需在 Unity 编辑器内最终确认）。

---

## 一、决策记录（已与需求方确认）

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 是否引入飞入队列 | **不引入**。飞行中再次触发时，直接走同步结算（互斥，不排队）。 |
| 2 | 右移与飞入的时序 | **飞行卡飞到 slot 0 时旧卡还在；落地瞬间才右移**并落位新卡。 |
| 3 | 落地弹跳 + 音效 | **不加**。保持最简。 |
| 4 | 实现层级 | **方案 A**：在 `CardPresenter` 内新增飞入方法，不抽通用飞卡服务。 |
| 5 | 并发时的视觉结果 | 后一次奖励立即同步插入 slot 0；先前飞行卡仍落入 slot 0，并在其落地时把后一次奖励右移。数据顺序正确，短暂视觉重叠为可接受代价。 |

## 三、详细改动

### 3.1 `CardPresenter.cs`：先补强同步插牌入口

现有 `InsertCardAtFront` 并非完整兜底：它只检查 `config` 和 placeholder，之后仍会直接使用 `_cardService`、`_container`、`_handRoot` 和 card prefab。飞行路径不能把它无条件当作“奖励一定发到”的安全方法。

将其整理为一个返回成功状态的私有或公共入口，例如：

```csharp
private bool TryInsertCardAtFront(NormalCardConfigSO config)
```

规则：

1. `config == null` 时返回 `false`，由调用方保持现有告警语义。
2. 检查 `_cardService`、`_container`、`_uiConfig`、`_handRoot`、`NextCardPlaceholder`、其 `RectTransform`、普通卡 prefab 和实例化结果；任一无效时记录一次明确错误/警告并返回 `false`，不部分移动 slot。
3. 检查全部通过后，执行当前 `InsertCardAtFront` 的原子顺序：`ShiftSlotsRight`、更新既有 view 的 `PlacementID/OriginPosition/位置`、从 `_cardViews` 删除并销毁被挤出 view、创建新 card view、`RegisterCardView(0, view)`、加入 `_cardViews`。
4. 既有公开 `InsertCardAtFront` 保留为兼容入口，内部只调用 `TryInsertCardAtFront(config)`；本次没有其他调用方需要改动。
5. 右移现有卡时只遍历有效 view；若 list 中出现已销毁 view，跳过并清除，避免飞行期间的其他 UI 销毁造成空引用。

这一步完成后，“特效失败则同步插牌”的语义才可被可靠地表达为“尝试同步插牌，并记录最终失败原因”。场景或 Presenter 已卸载时不应虚假承诺奖励一定显示到已不存在的 UI。

### 3.2 `CardPresenter.cs`：新增飞入入口和状态

新增字段（放在 `_handRoot` 附近）：

```csharp
// 飞入特效互斥标志：不排队，飞行中再次触发直接同步结算。
private bool _cardFlyInProgress;
```

新增公共方法：

```csharp
/// <summary>
/// 将指定卡牌以飞入表现插入手牌第一位（slot 0）。
/// 飞行从 worldStartPos 起飞；落地瞬间才执行同步插牌和旧卡右移。
/// 飞行中再次触发时，本次直接同步结算，不进入队列。
/// </summary>
public void InsertCardAtFrontWithFly(NormalCardConfigSO config, Vector3 worldStartPos)
```

入口顺序：

1. `config == null` 时直接返回，与现有 `InsertCardAtFront` 一致。
2. 若 `_cardFlyInProgress` 为 true，调用 `TryInsertCardAtFront(config)` 后返回。不可排队，也不可取消当前飞行。
3. 检查动画环境：`_cardService`、`_container`、`_uiConfig`、普通 card prefab、`NextCardPlaceholder` 及其 `RectTransform`、`_handRoot as RectTransform`、`Camera.main`。任一无效时调用 `TryInsertCardAtFront(config)` 后返回。
4. `Camera.main.WorldToScreenPoint(worldStartPos)` 后先检查 `screenPos.z > 0`。起点在相机背后时销毁临时对象或直接同步插牌，不能把坐标 clamp 到屏幕边缘后从错误位置飞出。
5. 仅在飞行卡实例化、坐标换算和 driver 建立均成功后，设置 `_cardFlyInProgress = true`。任何创建异常必须回退同步插牌，不能留下忙碌标志。
6. 整个创建过程使用 `try/catch`；catch 中记录异常、清理临时对象和 driver、调用同步插牌。`finally` 不能无条件清除忙碌标志，只有未成功进入动画时才清除。

### 3.3 `CardPresenter.cs`：飞行卡视觉初始化

飞行卡使用 `_uiConfig.GetCardPrefab()`，父节点为 `_handRoot`。普通卡 prefab 不同于战术卡 prefab，不能只设置根 `Image`：它还带有 `cost` 文本和一个尺寸远大于卡面的透明 `Button`。

初始化步骤：

1. `_container.InstantiatePrefab(prefab, _handRoot)`，确认返回对象和根 `RectTransform` 非空。
2. 禁用根 `CardController`，避免拖拽、金币订阅和普通卡交互逻辑。
3. 设置根 `Image.sprite = config.cardSprite`。
4. 费用显示二选一并固定执行：
   - 显示：按 `GetCardCost(config)` 写入 prefab 中的费用 TMP；或
   - 隐藏：禁用 `cost` 子节点，避免默认费用文本错误。
5. 对 `GetComponentsInChildren<Graphic>(true)` 中所有 Graphic 设置 `raycastTarget = false`；对全部 `Button` 设置 `interactable = false`。不能只关闭根 Image 的射线。
6. `anchorMin/anchorMax = (0.5f, 0.5f)`、`SetAsLastSibling()`，并设置初始 anchored position、scale、rotation 与 alpha。
7. 使用 `CanvasGroup` 管理透明度；没有时添加。飞行卡从未注册到 `_cardService` 或 `_cardViews`，只作为临时视觉对象。

### 3.4 `CardPresenter.cs`：坐标换算与两段式动画

slot 0 的落点必须与普通手牌完全使用同一坐标系：

```csharp
RectTransform handRootRect = _handRoot as RectTransform;
Vector2 slot0Offset = _cardService.GetSlotOffset(0);
Vector2 slot0Pos = placeholderRect.anchoredPosition + slot0Offset;
```

`revealLocal` 也必须由同一个 `handRootRect` 得到：

```csharp
RectTransformUtility.ScreenPointToLocalPointInRectangle(
    handRootRect, screenPos, null, out Vector2 revealLocal);
```

当前 Canvas 是 Screen Space Overlay，因此 camera 参数为 `null` 正确；以后若 Canvas 改为 Screen Space Camera 或 World Space，必须同时修改此参数和验收结果。

安全区和两段动画可沿用战术卡的参数：

- 渲染尺寸按 `flyRect.rect.size * _uiConfig.CardSize * handRootRect.lossyScale.x` 计算；尺寸无效时回退保守默认值。
- 世界坐标映射到屏幕坐标后，以卡牌半尺寸加 8 像素为边距 clamp。
- 阶段 1，`0.50s`：`EaseOutQuad` 上升到 `liftPos`、`EaseOutBack` 从 `0.35` 放大到 `1`、旋转 `-3° -> 0°`、alpha 淡入。
- 阶段 2，`0.25s`：以 `EaseInCubic` 沿二次贝塞尔从 `liftPos` 飞向 `slot0Pos`；控制点为 `liftPos * 0.5f + (0, -arcBump * 0.25f)`。
- 总时长为 `0.75s`，但业务进度唯一来源是 `_gameLoop.GameTime`；`_gameLoop` 缺失时才允许降级使用 `Time.time`。

### 3.5 `CardPresenter.cs`：暂停与完成清理

禁止照搬 `TacticalCardPresenter` 的：

```csharp
DOTween.To(..., 10f)
```

`GameLoop.SetPaused` 不会暂停 DOTween；若 driver 有固定自然结束时间，暂停超过该时间后仍会调用 `OnComplete` 并提前结算奖励，违反“暂停冻结”。

实现要求：

1. DOTween 仅可作为每帧 `OnUpdate` 回调驱动，不能让其固定自然完成负责业务结束；driver 必须在到达 `GameTime` 总时长时由代码主动完成/清理，或采用不会在暂停期间自然结束的等效驱动方式。
2. 每帧用 `currentGameTime - startGameTime` 计算进度。暂停时 `GameTime` 不变，位置、缩放、旋转、alpha 和业务结算均不得变化。
3. 建立唯一的幂等结束函数，例如 `FinishFly(bool settleCard)`，用 `flyCompleted` 守卫。下列路径都只能调用该函数：正常抵达、`flyGO == null`、坐标换算失败、创建异常、driver 被终止、场景/父节点销毁。
4. `FinishFly` 的顺序：标记已完成、终止 driver、关闭并销毁有效的 `flyGO`、清除 `_cardFlyInProgress`、调用 `TryInsertCardAtFront(config)`。即使飞行卡已经被销毁，也必须尝试一次同步结算。
5. 终止 driver 时必须避免其 `OnComplete` 重入；`flyCompleted` 守卫负责这一点。
6. 不在 `flyGO == null` 分支只调用 `driver.Kill()`。`Kill` 通常不会执行 `OnComplete`，该写法会丢失奖励。
7. 飞行对象不存在事件订阅，但 driver 闭包仍持有 `flyGO`、config 和 Presenter。必须在结束路径 Kill driver 并置空必要引用；这比“无订阅所以无需清理”更准确。

落地时才执行同步插牌：

```csharp
// FinishFly 内，且仅执行一次。
TryInsertCardAtFront(config);
```

动画期间不得调用 `ShiftSlotsRight`，不得注册新 view。这样旧卡仍占据 slot 0，飞行卡只是最上层临时视觉；落地后同一时刻发生“飞行卡消失 -> 旧卡右移/末位挤出 -> 新卡出现”的切换。

### 3.6 `PublicBuilding_Collectible.cs`

只改 `TriggerEffect` 的玩家分支：

```csharp
// 之前
_cardPresenter.InsertCardAtFront(_rewardCard);

// 之后：RootHex 是生成流程不变量；异常对象仍退回同步插牌。
if (RootHex != null)
    _cardPresenter.InsertCardAtFrontWithFly(_rewardCard, RootHex.RealCenterWorldCoordinate);
else
    _cardPresenter.InsertCardAtFront(_rewardCard);
```

要点：

- `RootHex.RealCenterWorldCoordinate` 是建筑根格中心世界坐标，与战术卡奖励使用的 `cell.RealCenterWorldCoordinate` 起点语义一致。
- `OnCaptured` 的顺序是先 `TriggerEffect`，后 `Destroy(gameObject)`；在调用时读取起点安全，传入的是值类型 `Vector3`，不受之后销毁影响。
- `_rewardCard == null` 的告警和返回逻辑保持不变。
- AI 分支保持当前实现：全部非玩家阵营仍写入同一个 `_aiPlayerState`。本迁移不扩展多 AI 阵营的奖励归属。

## 四、边界与坑（实施时必须核对）

1. **手牌已满**：只在落地同步插牌时挤掉末位；飞行卡不参与 `_cardService` 和 `_cardViews`。
2. **暂停**：验收必须覆盖暂停超过 10 秒。`GameTime` 不变时，视觉和结算都必须不变。
3. **互斥不是队列**：飞行中第二次触发立即同步插牌；先飞出的卡后落地时仍会插入 slot 0。
4. **异常销毁**：飞行卡、父 Canvas、driver 任一异常结束都必须调用一次幂等完成函数，不能只 Kill Tween。
5. **同步插牌失败**：若 Presenter/UI 已销毁，记录明确错误。不能在 UI 已不存在时承诺奖励一定成功显示；游戏流程层若需要跨场景持久奖励，属于本计划范围外的数据层设计。
6. **视觉 prefab**：费用必须正确显示或明确隐藏；所有子 Graphic/Button 必须关闭射线和交互。
7. **坐标空间**：`revealLocal`、`slot0Pos`、flyRect 的 `anchoredPosition` 必须都属于 `_handRoot`；不可混用 screen/world/localPosition。
8. **相机背面**：`WorldToScreenPoint` 返回的 `z <= 0` 时不要 clamp 后播放边缘飞卡，直接降级同步结算。
9. **无新增数据层影响**：飞行只延迟 UI 手牌注册；不要改变卡池、预告卡、AI 手牌或奖励配置。

## 六、风险与回滚

- **主要风险**：普通卡 prefab 的交互和费用子节点与战术卡 prefab 不同；若未主动处理，飞行卡会显示错误费用或以透明大 Button 阻塞 UI。
- **暂停风险**：不能复制战术卡固定 10 秒 DOTween driver，否则长暂停会提前落地结算。
- **坐标风险**：当前 Overlay Canvas 的坐标换算成立；未来更换 Canvas Render Mode 或 handRoot 层级时，需重新验证 camera 参数、scale 和 slot 对齐。
- **回滚**：恢复 `PublicBuilding_Collectible` 对 `InsertCardAtFront` 的调用；删除新增飞行入口/字段和同步入口整理。无卡池、存档或 AI 数据格式影响。
