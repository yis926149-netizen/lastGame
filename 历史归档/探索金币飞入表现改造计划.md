# 探索金币飞入表现接收者实施计划

> 目标：新增一个独立接收者，在玩家探索地块奖励为“金币”时，生成与金币数量对应的金币 UI（Inspector 暴露 prefab），并模仿“战术卡牌飞入”的表现，让这些金币 UI 逐个飞向某个指定 UI（Inspector 暴露目标）。
>
> 状态：决策已确认（D1=A 叠加；D2 暂缓），按确认结果实施。本文档只描述改动方案，不包含实际代码修改。

---

## 1. 背景与目标

### 1.1 当前事实

- 探索结果已改造为统一广播流 `ExplorationBroadcastHub`，阶段为 `Explored → Settled → RewardPoint`（玩家），AI 为 `Explored → Settled`。
- 奖励快照只由 `ExplorationService` 唯一物化，`Settled` 阶段携带“实际结算结果”（`SettledRewardType` / `SettledGoldAmount`）。
- 金币奖励的实际数值来自 Excel 配置（`Config/Generated/game-config.json` → “探索奖励配置”表），而非手工 SO 默认值。
- 实测金币档位 `goldTiers = "5,5,10,15,20,25"`，即最大单次金币奖励为 **25**，不存在上百金币的档位。
- 现有 `ExplorationCoinPresenter` 已在 `RewardPoint` 阶段播放金币表现（CoinModel 金币模型弹跳 / AddCoinsUI 漂字），**不负责入账**。
- `TacticalCardPresenter.AddCardWithFly()` 已实现“从地块屏幕位置出现 → 上浮放大 → 沿二次贝塞尔曲线飞入槽位”的两段式动画，并用 `GameLoop.GameTime` 驱动以对齐暂停。

### 1.2 改造目标

1. 新增一个**纯表现**接收者，只订阅统一广播，不参与结算、不修改钱包、不发布阶段。
2. 当 `RewardPoint + 玩家 + SettledRewardType == Gold` 时，按 `SettledGoldAmount` 生成对应个数的金币 UI。
3. 金币 UI prefab 与“飞入目标 UI”均在 Inspector 暴露。
4. 动画分两段：出现（上浮+散开+放大，仿战术卡第一阶段）→ 逐枚飞向目标（二次贝塞尔，仿战术卡第二阶段）。
5. 使用对象池，最大 25 枚，池容量 30~40 即可；暂停语义对齐 `GameLoop.GameTime`。

## 2. 实测配置事实

### 2.1 金币档位（运行时唯一主源）

`Config/Generated/game-config.json` → sheet `探索奖励配置`：

```json
{
  "configId": "exploration_reward",
  "noneWeight": "20",
  "goldWeight": "20",
  "militaryWeight": "20",
  "tacticalWeight": "20",
  "buildingWeight": "20",
  "goldTiers": "5,5,10,15,20,25",
  "unitCountTiers": "0,0,0,1,1,2",
  "costNone": "0",
  "costGold": "10",
  "costMilitary": "50",
  "costTactical": "50",
  "costBuilding": "50"
}
```

结论：

- 金币档位 = `5 / 5 / 10 / 15 / 20 / 25`，最大 25。
- “一个金币 UI 对应 1 金币”的方案**性能可接受**，无需视觉数量上限或按档位曲线压缩。
- 建筑奖励降级为金币时，降级金额同样来自 `goldTiers`（见 `ExplorationRewardProvider.GenerateReward` 中 Building 分支的 `RollGold`）。

### 2.2 载荷中已有的可用字段

`ExplorationAcquisition` 在 `RewardPoint` 阶段携带：

- `Phase == ExplorationBroadcastPhase.RewardPoint`
- `FactionId == 0`
- `SettledRewardType == ExplorationRewardConfigSO.ExplorationRewardType.Gold`
- `SettledGoldAmount`（最终实际发放的金币数，已含建筑降级）
- `Cell`（`RealCenterWorldCoordinate` 为地块世界坐标）

因此接收者**无需**再读取或消费 `cell.ExplorationReward`，也无需注入钱包。

| 编号 | 问题 | 确认结果 |
|---|---|---|
| D1 | 是否与现有 `ExplorationCoinPresenter` 叠加 | **A（叠加）**：飞币与现有金币表现（CoinModel / AddCoinsUI）同时播放，`ExplorationCoinPresenter` 不改动 |

## 4. 设计决策

### 4.1 接收时机与过滤条件

```csharp
if (acquisition == null) return;
if (acquisition.Phase != ExplorationBroadcastPhase.RewardPoint) return;
if (acquisition.FactionId != 0) return;
if (acquisition.SettledRewardType != ExplorationRewardConfigSO.ExplorationRewardType.Gold) return;
if (acquisition.Cell == null || acquisition.SettledGoldAmount <= 0) return;

PlayCoinFly(acquisition.Cell, acquisition.SettledGoldAmount);
```

要点：

- 用 `SettledRewardType` 而非 `OriginalRewardType`，确保**建筑降级金币**也能飞币。
- 用 `SettledGoldAmount` 而非原始金币字段，确保降级金额正确。
- AI（`FactionId != 0`）不触发。

### 4.2 职责边界（严格表现层）

接收者：

- 订阅 `IExplorationBroadcastSource.Broadcast`；
- 生成/回收金币 UI；
- 播放出现与飞行动画；
- 目标 UI 落点反馈。

接收者**禁止**：

- 调用 `GoldWallet.AddGold()`（金币已在 Settled 入账）；
- 调用 `cell.TakeExplorationReward()`；
- 发布任何探索阶段；
- 把动画完成当作结算条件。

### 4.3 对象池

- 池容量默认 `40`，且**必须 ≥ 全局活跃金币上限**（见 §4.8），单批最大 25 仍留足余量。
- 金币 UI 从 `coinUIPrefab` 实例化，`Image.raycastTarget = false`，避免阻挡点击。
- 动画结束后回池复用。

### 4.4 两段式动画（模仿战术卡）

#### 阶段 A：出现

- 世界坐标（`cell.RealCenterWorldCoordinate`）→ 屏幕坐标 → 飞行层局部坐标。
- 初始小尺寸、透明。
- 上浮并放大、淡入，且每枚在圆形区域内**确定性散开**。

> 散开种子注意：`HexCellData.HexCoordinate` 是 `Vector3`（`HexCellData.cs:44`），不能直接当 seed。需先量化为 int，例如：
>
> ```csharp
> int seed = Mathf.RoundToInt(cell.HexCoordinate.x) * 73856093
>          ^ Mathf.RoundToInt(cell.HexCoordinate.z) * 19349663
>          ^ index;
> ```

#### 阶段 B：飞向目标

- 每枚沿二次贝塞尔曲线飞向 `targetUI`：
  - 起点 = 出现终点；
  - 控制点 = 中点上抬（金币“上抛”弧线）；若严格复刻战术卡第二段手感则改为中点**下压**——`TacticalCardPresenter` 实际为 `dashControl = liftPos * 0.5f + new Vector2(0f, -arcBump * 0.25f)`（`TacticalCardPresenter.cs:234`），与本段“上抬”方向相反，实现时二选一并保持一致；
  - 终点 = 目标 UI 屏幕位置。
- 使用 `EaseInCubic`，缩放渐缩（如 1 → 0.2），到达时回池。
- 每枚开始时间错开 `spawnInterval`（默认 0.04s）。

### 4.5 暂停语义

对齐 `TacticalCardPresenter`：

```csharp
float currentTime = _gameLoop != null ? _gameLoop.GameTime : Time.time;
```

- 游戏暂停（`GameLoop.IsPaused`）时飞币动画冻结。
- 推荐由 Presenter 集中更新所有活跃金币，而不是每枚金币各自 `Update()`（25 枚量级两者都可，但集中更新便于统一暂停/批次控制）。
- 上式的 `Time.time` 分支只是防御性写法。`GameLoop` 已在 `GameInstaller.cs:323` 以 `BindInterfacesAndSelfTo<GameLoop>().AsSingle()` 绑定，注入**必然成功**，因此注入时**不要**标 `Optional = true`——否则一旦漏绑会静默降级为 `Time.time`，表现为“暂停时金币仍在飞”且极难定位。

### 4.6 坐标转换

不假设目标 UI 与飞行层同坐标系。三处换算各自的相机参数不同，不要混用：

**(a) 地块世界坐标 → 屏幕坐标**（阶段 A 起点）

```csharp
if (Camera.main == null) return;               // 参考 TacticalCardPresenter.cs:177 的判空
Vector3 screenPos = Camera.main.WorldToScreenPoint(cell.RealCenterWorldCoordinate);
```

- **相机背后处理（必须）**：`WorldToScreenPoint` 在目标位于相机背后时 `z < 0`，且 x/y 会镜像翻转，导致金币从屏幕反侧冒出。必须显式处理：`if (screenPos.z < 0f) { /* 跳过阶段 A，直接从目标 UI 附近起飞，或整批不播 */ }`。战术卡只做了安全区 Clamp（`TacticalCardPresenter.cs:218-219`）而**没有**处理 z<0，这里不要照抄。
- **安全区**：`Mathf.Clamp(screenPos.x, margin, Screen.width - margin)`，同理 y，保证金币整体可见。

**(b) 屏幕坐标 → 飞行层局部坐标**

```csharp
Canvas flyCanvas = _flyLayer.GetComponentInParent<Canvas>();
Camera uiCamera = (flyCanvas != null && flyCanvas.renderMode == RenderMode.ScreenSpaceOverlay)
    ? null : flyCanvas?.worldCamera;

if (!RectTransformUtility.ScreenPointToLocalPointInRectangle(_flyLayer, screenPos, uiCamera, out Vector2 local))
{
    // 换算失败：该枚金币直接回池，不播动画（纯表现，无兜底结算义务）
    ReturnToPool(coin);
    return;
}
```

- `uiCamera` 必须由**飞行层 `_flyLayer` 所在 Canvas** 决定，不是目标 UI 所在 Canvas。
- 换算失败分支必须写。飞币是纯表现，没有战术卡那种“兜底结算”义务（`TacticalCardPresenter.cs:220-225` 会 `Destroy + FinishFly`），这里**直接回池即可**，绝不能因此跳过或重复任何结算。

**(c) 目标 UI → 飞行层局部坐标**（阶段 B 终点）

```csharp
Vector2 targetScreen = RectTransformUtility.WorldToScreenPoint(uiCamera, _targetUI.position);
RectTransformUtility.ScreenPointToLocalPointInRectangle(_flyLayer, targetScreen, uiCamera, out Vector2 targetLocal);
```

- `RectTransformUtility.WorldToScreenPoint(null, p)` 在 `cam == null` 时直接返回 `(p.x, p.y)`，**不会**回退 `Camera.main`——这对 Overlay Canvas 恰恰是正确行为（Overlay 下 UI 的 world 坐标即屏幕坐标）。此处**不需要**任何 `Camera.main` 兜底；(a) 处的 `Camera.main` 判空是另一回事，勿混淆。
- 目标 UI 位置每帧重新计算，支持目标 UI 移动/动画/分辨率变化。

### 4.7 生命周期与在途动画

- `OnDestroy` 必须退订 `_broadcastSource.Broadcast`（与现有 `ExplorationCoinPresenter.OnDestroy` 一致）。
- 集中驱动的每帧循环中，活跃金币实例可能已被销毁（场景切换等），必须逐个判空后剔除并跳过——参考 `TacticalCardPresenter.cs:256-261` 的 `if (flyGO == null)` 守卫。
- `OnDestroy` 时清空活跃列表与待生成队列，避免残留引用。

### 4.8 连续探索与批次

- 单次最多 25 枚，允许批次重叠（不同地块奖励互不等待）。
- 每批内部逐个飞行。
- 设置全局活跃金币上限（默认 40），超出时进入待生成队列，旧批完成即释放容量；该上限必须 ≤ 对象池容量（§4.3 池 40），否则会出现“上限允许但无实例可借”的矛盾。

注入依赖（与现有 `ExplorationCoinPresenter` 保持一致，用方法注入）：

```csharp
private IExplorationBroadcastSource _broadcastSource;

[Inject]
public void Construct(IExplorationBroadcastSource broadcastSource, GameLoop gameLoop)
{
    _broadcastSource = broadcastSource;
    _gameLoop = gameLoop;
```

### 5.2 `ExplorationFlyingCoinUI.cs`（新增，挂在金币 UI prefab 上）

职责：持有一枚金币 UI 的引用（`RectTransform` / `Image` / `CanvasGroup`），以及它的动画状态数据；由 Presenter 集中驱动，不自行 `Update()`。

建议对外接口：

```csharp
public Image Image;
public CanvasGroup CanvasGroup;
```

内部状态由 Presenter 持有（`Appear / Fly / Idle` 与各自进度、起终点、控制点、延迟时间、回调），或把状态封装为轻量结构体由 Presenter 列表统一管理。

## 7. 时序

```text
TryExplore(cell, 0)
  -> 唯一消费快照 -> Publish(Explored)
  -> RewardSystem 结算：金币入账（真实钱包已到账）
  -> Publish(Settled: Gold, amount)
  -> 动画奖励点 SignalRewardPoint(cell)
  -> Publish(RewardPoint: SettledRewardType=Gold, SettledGoldAmount=amount)

ExplorationCoinFlyPresenter（新接收者）
  -> 过滤 RewardPoint + 玩家 + Gold
  -> 生成 amount 枚金币 UI（对象池，≤25）
  -> 阶段A：地块屏幕位置出现、上浮、散开、放大
  -> 阶段B：逐枚沿贝塞尔曲线飞向 targetUI，落地回池
  -> 落点反馈（targetUI punch）
```

> 钱包金额在 `Settled` 阶段已到账，飞币仅为表现，不改变入账时序。

## 8. 测试清单

### 8.1 过滤与触发

- 玩家 `RewardPoint + Gold`：生成 `SettledGoldAmount` 枚金币 UI。
- 玩家 `RewardPoint + 非 Gold`（建筑成功/单位/战术/None）：不生成。
- AI `RewardPoint`（本不应存在）或 `FactionId != 0`：不生成。
- `SettledGoldAmount <= 0`：不生成。
- 建筑降级金币：`Original=Building, Settled=Gold` 也生成且数量正确。

### 8.2 对象池与数量

- 25 枚金币不会超出池容量。
- 动画结束回池，重复探索复用同一批实例。
- 连续两批金币不互相等待、不产生重复实例。

### 8.3 动画与坐标

- 金币从地块对应屏幕位置出现，安全区 Clamp 后整枚可见（§4.6a）。
- **相机背后**：把镜头转到探索地块背面再触发金币奖励，金币不得从屏幕反侧冒出（`screenPos.z < 0` 分支，§4.6a）。
- **换算失败**：`ScreenPointToLocalPointInRectangle` 返回 false 时该枚直接回池，不留泄漏、不影响同批其他金币（§4.6b）。
- 目标 UI 移动时，落点仍正确（每帧换算）。
- 暂停时飞币冻结（`GameLoop.GameTime` 语义）；恢复后继续，不发生位置跳变。

### 8.4 生命周期

- 播放途中切换场景/销毁 Presenter：不报 `MissingReferenceException`，广播已退订（§4.7）。
- Presenter 销毁后再有广播到达：不触发任何回调。

### 8.5 不破坏现有契约

- 钱包只入账一次（金币在 Settled 入账，飞币不重复入账）。
- `TakeExplorationReward()` 仍只由 `ExplorationService` 调用。
- 现有探索广播阶段顺序测试仍通过。

## 10. 风险与约束

1. **飞币绝不能再次入账**：金币在 `Settled` 已由 `ExplorationRewardSystem` 入账，飞币只做表现；重复 `AddGold` 会导致双倍金币。
2. **必须过滤 `SettledRewardType`**：建筑降级金币的 `OriginalRewardType` 是 `Building`，若按原始类型过滤会漏掉降级飞币。
3. **暂停语义要对齐**：直接用 DOTween 默认时间可能在逻辑暂停时仍飞行；应使用 `GameLoop.GameTime` 或显式检查 `IsPaused`。
4. **坐标空间**：`ScreenSpaceOverlay` 与 `ScreenSpaceCamera` 的换算 camera 不同，且目标 UI 可能不在飞行层同一坐标系，需逐帧换算。换算相机一律由**飞行层** Canvas 推导（§4.6）。
5. **`WorldToScreenPoint` 的两个同名 API 行为不同，勿混淆**（§4.6）：
   - `Camera.WorldToScreenPoint`（(a) 用）：需判空 `Camera.main`，且目标在相机背后时 `z<0` 并镜像翻转，必须显式处理。
   - `RectTransformUtility.WorldToScreenPoint`（(c) 用）：`cam == null` 时直接返回 `(x, y)`，**不会**回退 `Camera.main`——这正是 Overlay 下的正确行为，此处加 `Camera.main` 兜底反而是错的。
6. **批次重叠**：高额（25 枚）奖励未播完时再次探索，不能让第二批永久等待；允许批次重叠并设全局活跃上限。
7. **对象池上限**：单批最大 25，池 40（= 全局活跃上限）足够；但若后续上调 `goldTiers` 档位或活跃上限，需同步上调池容量。
8. **场景组件默认失活**：本项目场景表现组件靠 `GameInstaller.EnableMapVisualComponents` 强制 `enabled = true`。新 Presenter 若不加入该遍历，场景中一旦未勾选就静默不播且无任何报错（§6.1）。

## 11. 最终架构边界

```text
ExplorationService / ExplorationRewardSystem / AIAutoExplorer
   负责：探索事务、唯一物化、实际结算（钱包入账）
   发布：Explored / Settled / RewardPoint

   订阅：RewardPoint（仅玩家 + SettledRewardType == Gold）

GoldWallet
   负责：金币入账（仅在 Settled 由奖励系统写入）
   不负责：表现
```

该边界保证：奖励只结算一次、飞币只表现不结算、建筑降级金币正确飞入、AI 不触发玩家表现、动画与暂停语义对齐。

### 12.4 方案 B 时序（金币数字随飞币增长）

```text
Settled：真实入账 +N → HUD 先到最终值 → 同帧回退到旧值（InFlightGold=N，无闪烁）
探索动画期间：HUD 保持旧值
飞币落地 xN：InFlightGold 逐枚 -1 → HUD 数字逐枚 +1
最后：HUD = 真实钱包
```

- 真实钱包仍在 `Settled` 由 `ExplorationRewardSystem` 唯一入账，飞币 Presenter 不 `AddGold`。
- `InFlightGold` 由飞币 Presenter 维护；落地或跳过（相机背后/换算失败）都会 -1，保证最终追平、不永久少显示。
- 被动收入/扣费仍即时反映（`RefreshGoldText` 用 `Gold - InFlightGold` 计算，二者不串）。
