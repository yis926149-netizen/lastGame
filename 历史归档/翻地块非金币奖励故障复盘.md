# 翻地块非金币奖励故障复盘

> 结论一句话：**探索奖励池 `ExplorationRewardPoolDatabaseSO` 的运行时缓存 `enabledEntries` 被过早初始化为空列表，之后 `entries` 被 Unity 反序列化填充了 5 条数据，但缓存因为“非 null”而永远不再重建，导致 Provider 按 `enabled=true` 筛选时命中 0 条，所有非金币奖励在预生成阶段就退化为 null。**

---

## 一、现象

- 玩家翻地块时，只有金币奖励，军事单位 / 战术卡 / 建筑奖励都拿不到。
- 建筑奖励偶尔能看到“降级为金币”，本质也是建筑配置为 null 走了降级分支。
- Excel、生成的 CSV、生成的 `.asset`、场景绑定全部检查过，静态数据都正确。

## 二、根本原因

### 关键代码（修复前的逻辑）

```csharp
public sealed class ExplorationRewardPoolDatabaseSO : ScriptableObject
{
    [SerializeField] private ExplorationRewardPoolEntry[] entries = Array.Empty<...>();

    private List<ExplorationRewardPoolEntry> enabledEntries; // 运行时缓存

    public IReadOnlyList<ExplorationRewardPoolEntry> EnabledEntries
    {
        get { EnsureLookup(); return enabledEntries; }
    }

    private void EnsureLookup()
    {
        if (enabledEntries is not null)   // ← 只要缓存被创建过一次，就永远不再重建
            return;

        enabledEntries = new List<ExplorationRewardPoolEntry>();
        foreach (var entry in entries)
        {
            if (entry != null && entry.enabled)
                enabledEntries.Add(entry);
        }
    }
}
```

### 失效过程

1. `enabledEntries` 在 `entries` 还是默认空数组时，被 `EnsureLookup()` 首次构建成了一个 **非 null 的空列表**。
2. 随后 Unity 完成反序列化，`entries` 被填充为磁盘上的 5 条数据。
3. 但因为 `enabledEntries is not null` 成立，`EnsureLookup()` 直接 `return`，**空缓存永远不重建**。
4. Provider 里 `RollPoolEntry()` 遍历 `_pool.EnabledEntries`（空），三类奖励都 `candidates.Count == 0`，返回 null。

这解释了日志里最矛盾的一组数据：

```text
[RewardTrace] Pool rawEntries count=5          ← entries 实际有 5 条
[RewardTrace] Pool request=MilitaryUnit enabledCount=0 entries=[]  ← 缓存却是 0 条
```

### 为什么会“过早初始化”

典型触发场景（本项目已命中其一或多者）：

- Unity 关闭了 Domain Reload（Enter Play Mode Options），ScriptableObject 实例在多次运行间被复用，上一轮的空缓存被带进下一轮。
- `EnabledEntries` / `EnsureLookup` 在对象反序列化完成之前被其他代码路径访问了一次。
- 导入器 `ReplaceAll()` 与序列化反序列化的时序交错。

## 三、诊断证据链（按顺序锁定）

诊断日志前缀统一为 `[RewardTrace]`，逐层缩小范围：

1. **结算/生成层**：`Provider military count=1 units=[NULL]`、`Provider tactical card=NULL`、`Provider building config=NULL` → 问题发生在 Provider 生成时，而非 UI / 动画 / 建筑放置。
2. **Provider 解析层**：`Resolve unit poolConfig=NULL`、`Resolve tactical poolConfig=NULL`、`Resolve building poolConfig=NULL` → `RollPoolEntry()` 没有返回 configId。
3. **奖励池筛选层**：`Pool request=MilitaryUnit enabledCount=0 entries=[]` → `EnabledEntries` 为空。
4. **数据库原始字段**：`Pool rawEntries count=5` → `entries` 本身有 5 条，反序列化正常。

由此把断点收敛到：**`entries` 有数据，但 `enabledEntries` 缓存为空**，即缓存重建失效。

## 四、修复方案

文件：`Assets/GameConfig/Runtime/Database/ExplorationRewardPoolDatabaseSO.cs`

两处修改，**不改变任何奖励语义**（仍只筛选 `enabled=true`）：

```csharp
// 1) 对象生命周期边界重置缓存
private void OnEnable()
{
    enabledEntries = null;
}

// 2) 空缓存 + entries 非空时，强制重建
private void EnsureLookup()
{
    if (enabledEntries is not null &&
        (enabledEntries.Count > 0 || entries == null || entries.Length == 0))
        return;

    enabledEntries = new List<ExplorationRewardPoolEntry>();
    foreach (var entry in entries)
    {
        if (entry != null && entry.enabled)
            enabledEntries.Add(entry);
    }
}
```

修复后的预期日志：

```text
[RewardTrace] Pool rawEntries count=5
[RewardTrace] Pool request=MilitaryUnit enabledCount=5 ...
[RewardTrace] Pool result=MilitaryUnit candidates=2 ...
[RewardTrace] Pool result=TacticalCard candidates=2 ...
[RewardTrace] Pool result=Building candidates=1 ...
```

对照旧项目 `E:\BaiduNetdiskDownload\毕设\My project - 给美术\My project - new`：

- 旧项目的 `ExplorationRewardProvider`、`ExplorationRewardSystem`、`ExplorationRewardPoolDatabaseSO`、奖励池资产内容与本项目一致。
- 旧项目并非用了另一套奖励算法，而是**没有触发“空缓存不重建”这个时序问题**（域重载设置 / 资源加载时序不同）。
- 因此不能靠“从旧项目复制 Provider/System 代码”解决，问题在数据库 SO 的缓存生命周期。

## 六、预防措施 / 教训

1. **惰性缓存必须校验“缓存为空但源数据非空”的失效态**，不能只用 `is not null` 作为“已初始化”判断。
2. ScriptableObject 里所有运行时缓存，都应在 `OnEnable()` 重置，避免 Enter Play Mode（关域重载）复用实例导致脏缓存。
3. 加诊断日志时，**不要给已经 `using System;` 的文件再 `using UnityEngine;` 而不处理 `Random` 歧义**：`System.Random` 与 `UnityEngine.Random` 会触发 `CS0104`；如需别名，用不冲突的名字（如 `SystemRandom = System.Random`），且只声明一次（重复声明会 `CS1537`）。
4. 看 Editor.log 要先确认脚本已成功编译、日志来自最新程序集，否则旧程序集的日志会误导判断。
