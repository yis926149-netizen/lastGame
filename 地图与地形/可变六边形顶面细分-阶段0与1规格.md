# 阶段 0 / 阶段 1 实施规格

本文档是《可变六边形顶面细分修改规划》的细化补充，聚焦前两个阶段的可落地规格。仍不修改生产代码。

## A. 阶段 0：s=3 基线

目的：在改动任何几何前，把当前“每边 3 段（18 环点）”的默认地图锁成可回归的基线。

### A.1 收集内容

对固定 seed（沿用 `MapGenerationConfig.asset` 当前权威值 `useFixedSeed=1 / randomSeed=20260820`）生成整张地图后，按子系统记录。基线文件必须同时记录 `generatorVersion`、`xNumber/zNumber`、`solidAreaTopology`、`OuterRadius`、`SolidAreaRatio`、`elevationStep`、`shadingStyle`、高度细分开关及山脉配置标识，避免只凭 seed 误判为同一输入：

```text
局部生成器契约：
solid：     每格 packed 顶点数、三角索引数（河道格/非河道格分开统计）
river：     每河格河水顶点数、三角索引数
water：     每水格湖海水面顶点数、三角索引数
mountain：  每可见山格 flat 顶点数、三角索引数（s=3 时应为 54）

最终 Chunk 提交契约：
terrain：   每个 Chunk 的最终顶点数、各 submesh 索引数
river：     每个 Chunk 的河水顶点数、索引数
water：     每个 Chunk 的湖海/海岸顶点数、各 submesh 索引数
collision： 每个 Chunk 的碰撞顶点数、索引数与 collision mesh commit 次数
grid：      每个 Chunk 的网格覆盖层顶点数、索引数
fog：       矩形外轮廓、真实视觉轮廓、connector 外沿、探索洞与遮罩纹理分别统计
```

当前权威 asset 的 `showHexGrid=0`，因此生产配置基线应记录 `GridGeometry=null`。另使用测试克隆配置临时启用 `showHexGrid=true`，单独采集 Grid 基线；不得为了采集而修改权威 asset。`ChunkMapRenderer.CollisionCommitCount` 统计的是碰撞 Mesh 提交次数，不等同于 PhysX 内部 cooking 次数，文档和输出字段统一命名为 `collisionMeshCommitCount`。

统计必须**不依赖顶点数组顺序的偶然性**：顶点数/索引数是顺序无关的稳定量，优先作为第一道门槛。

### A.2 几何 hash 设计

仅顶点数量不够，还需锁定坐标、索引和顶点通道。基线分为两层：

1. **局部语义基线**：按 `cell.GenerateOrder` 升序，再按子系统和局部数组下标升序，便于定位具体格差异。
2. **最终提交基线**：按 `ChunkIndex(x,z)`、Mesh 类型、submesh 序号和最终数组下标遍历，覆盖不天然归属单格的 rectangle、triangle、coast、山体替换面和 collision-only 几何。
3. **量化规则**：每个坐标分量使用 `Mathf.RoundToInt(v * 10000f)` 转成有符号 `int32`；按 little-endian 四字节写入。每个数组先写 subsystem id、cell/chunk id、数组长度，再写内容，避免不同数组拼接后产生相同字节流。
4. **hash**：使用稳定的 FNV-1a `u64` 逐字节累加；不要使用 `string.GetHashCode()` 或 `Dictionary` 迭代序。
5. **覆盖通道**：至少分别 hash vertices、UV0、可选 UV2/UV3/UV4、各 submesh indices、collision vertices/indices、water、river 与 grid；同时校验所有通道长度、索引范围、预期 winding 和非预期退化三角形。
6. **河道坐标锚点**：单独记录当前 `ratio` 以及 packed `19..43` 的逐点 hash。阶段 2 即使只改顶面生成循环，也必须保证 s=3 的完整 44 点逐点一致，不能把河道内圈回归推迟到阶段 6。
7. **输出位置**：本次运行结果写入 `Temp/hex_baseline_s3.actual.json`；人工确认后的权威基线保存到版本控制内的 `Assets/Tests/Baselines/hex_surface_s3_v1.json`。

基线判定：连续两次独立生成（新进程或重建）hash 全部一致。

### A.3 截图清单

手动或 PlayMode 截图，覆盖：

```text
1. 无河平地大区域
2. 高度坡（slope）与台阶（step，含多级台阶）
3. 河源、河尾、相邻转弯、相差 2 转弯、贯穿
4. 湖海与海岸（水-陆、水-山）
5. 山-山共享边、连续脊线、山-普通边、三山交汇
6. 地图外边缘迷雾封皮

```

### A.4 退出条件

- 两次独立生成的局部语义基线与最终 Chunk 提交基线一致。
- 局部数组长度与理论值一致（s=3：每格 solid packed=44、每河格 river water=19、每水格 water=25、每可见山格 mountain flat fan=54）；最终 Chunk 数量按实际地块类型与过渡几何汇总，不与这些单格常量混用。
- 顶点、索引、UV、submesh、collision 和 fog/grid 专项校验全部通过。
- 截图与当前版本视觉一致。

## B. 阶段 1：HexSurfaceLayout 规格

### B.1 类职责

新增 `Assets/Scripts/Core/Models/HexSurfaceLayout.cs`，其中定义 `HexSurfaceLayout` 类，是网格拓扑的唯一权威来源：给定构造参数 `s`（每条逻辑边段数），提供所有顶点块的数量、索引、环序、边 profile 与镜像。**不生成任何世界坐标，不持有或读取 `MapGenerationConfigSO`、`HexCellData`、地图服务、场景对象或其他运行时状态。** 配置到布局的转换由外部调用方完成。

### B.2 构造与派生量

```text
输入 s ∈ [1, 6]
k = s - 1                      每边内部点数
RingCount              = 6 * s
SolidVertexCount       = 20 + 12 * k
WaterVertexCount       = 13 + 6  * k
RiverWaterVertexCount  = 7  + 6  * k
MountainFlatFanCount   = 3  * RingCount = 18 + 18 * k
```

k=2（当前默认）必须精确得到 44 / 25 / 19 / 54。

### B.3 packed 索引公式

```text
Center                     = 0
Corner(c)                  = 1 + c                       c ∈ [0,5]
EdgeInterior(d, j)         = 7 + d * k + j               d ∈ [0,5], j ∈ [0,k-1]
RiverSurfaceCorner(d)      = 7 + 6 * k + d
RiverBottomCenter          = 13 + 6 * k
RiverBottomCorner(d)       = 14 + 6 * k + d
RiverBottomEdge(d, j)      = 20 + 6 * k + d * k + j
```

k=2 验证（应逐项等于现状）：

```text
Corner = 1..6
EdgeInterior = 7..18
RiverSurfaceCorner = 19..24
RiverBottomCenter = 25
RiverBottomCorner = 26..31
RiverBottomEdge = 32..43
```

### B.4 环序（扇序）

`GetRingIndicesClockwise()` 必须复现现有 `RingFanOrder`：

```text
for d in 0..5:
    add Corner(d)
    for j in 0..k-1:
        add EdgeInterior(d, j)
```

k=2 时必须输出：

```text
1, 7, 8, 2, 9, 10, 3, 11, 12, 4, 13, 14, 5, 15, 16, 6, 17, 18
```

### B.5 边 profile 与镜像

本格方向 d 的完整边界折线（从角 d 到角 d+1）：

```text
GetEdgeProfileIndices(d) =
    [Corner(d), EdgeInterior(d,0), ..., EdgeInterior(d,k-1), Corner((d+1)%6)]
```

长度 = `k + 2 = s + 1`。

邻格共享边镜像（返回**邻格 solid 数组**内的索引，且返回顺序已经调整为与本格 profile 同下标逐点对应）：

```text
opp = (d + 3) % 6
rawNeighborProfile = [Corner(opp), EdgeInterior(opp,0..k-1), Corner((opp+1)%6)]
mirroredNeighborProfile = reverse(rawNeighborProfile)
```

因此契约必须明确区分两种比较：

```text
selfProfile[p] <-> mirroredNeighborProfile[p]
selfProfile[p] <-> rawNeighborProfile[profileCount - 1 - p]
```

k=2、d=0（NE）时 `mirroredNeighborProfile=[5,14,13,4]`，与当前 rectangle 端点表一致。这里是**拓扑/参数对应关系**，不是相邻 solid 世界坐标相等关系。

### B.6 边参数

```text
EdgeParameterForInteriorPoint(j) = (j + 1) / s
```

k=2 时得到 1/3、2/3，与现有 `EdgePointLift` 的 `u` 一致。

### B.7 采样 API（供阶段 6 河道使用，先在此定义契约）

```text
Vector3 SampleEdge(Vector3[] solid, HexSurfaceLayout layout, int direction, float t)
```

- 先执行 `tClamped = clamp01(t)`。
- `profile = layout.GetEdgeProfileIndices(direction)`，共 `s+1` 点、`s` 段。
- `scaled = tClamped * s`；`seg = min(floor(scaled), s-1)`；`u = (tClamped >= 1) ? 1 : scaled - seg`。
- 返回 `Lerp(solid[profile[seg]], solid[profile[seg+1]], u)`。
- `t<=0` 精确返回首点，`t>=1` 精确返回尾点。

河岸固定用 `t=1/3, 2/3`，使河宽独立于 s。

## C. 阶段 1 单元测试清单

新建 `Assets/Tests/HexSurfaceLayoutTests.cs`（或并入现有测试程序集），对 `s=1..6` 断言：

```text
1. SegmentsPerEdge == s
2. InteriorPointsPerEdge == s - 1
3. RingCount == 6 * s
4. SolidVertexCount   == 20 + 12 * (s-1)
5. WaterVertexCount   == 13 + 6  * (s-1)
6. RiverWaterVertexCount == 7 + 6 * (s-1)
7. MountainFlatFanCount == 18 + 18 * (s-1)
8. CenterIndex == 0
9. Corner(0..5) == 1..6
10. 所有 EdgeInterior/RiverBottomEdge 索引 ∈ [0, SolidVertexCount)
11. GetEdgeProfileIndices(d) 长度 == s+1，首尾为角点，内部单调
12. GetRingIndicesClockwise() 长度 == RingCount，无重复，覆盖 1..(6+6k) 全部环点
13. s=3 时 GetRingIndicesClockwise() 精确等于 1,7,8,2,...,17,18
14. 镜像：raw opposite profile 反转后与 mirrored profile 逐点一致；若比较已反转的 mirrored profile，则使用相同下标比较。
15. EdgeParameterForInteriorPoint(j) == (j+1)/s
16. s=3 时 EdgeParameter 序列为 {1/3, 2/3}
17. `s=1` 没有内部点；访问内部点或非法 direction/index 必须抛出明确范围异常。
18. 所有 packed block 索引互不重叠，并完整落在 `[0, SolidVertexCount)`；水体/河水派生块也分别校验边界。
19. `SampleEdge` 对 `t=0、1、1/3、2/3` 及各 profile 分段边界返回正确点；`t` 超出 `[0,1]` 时按规格 clamp。
20. 所有 `CellBuildContext` 创建点（当前包括 `ChunkMapRenderer` 与 `HexHighlightRenderer`）都必须传递同一语义的 `Layout`；`Solid`、`Solids`、`LakeOrSeas` 写入和读取时校验数组长度。
21. 以相邻格和真实 `SolidAreaRatio<1` 构造 rectangle transition：不要求两格 solid 世界坐标重合，而是断言 rectangle profile 起点等于本格 profile 对应点、终点等于邻格 mirrored profile 对应点，且无退化三角和错误 winding。
```

镜像测试的落地方式：用固定 `s` 构造两个相邻格的中心坐标，分别生成无扰动 solid，再断言共享边 profile 在容差内逐点重合。

## D. 阶段 1 完成定义

- `HexSurfaceLayout` 只依赖构造参数 `s`，不依赖任何运行时对象。
- 所有 `CellBuildContext` 创建点都传递 `Layout`；当前至少包括 `ChunkMapRenderer` 和 `HexHighlightRenderer`。
- 阶段 0 的 s=3 基线（局部数组与最终 Chunk 提交数据）在引入该类后保持不变：顶点、索引、UV、submesh、collision 和河道 packed `19..43` 均通过回归。
- 上述单元测试全部通过。
- `SolidAreaMeshData` 与 `CellBuildContext` 增加 `Layout` 字段，缓存写入按 `SolidVertexCount / WaterVertexCount / RiverWaterVertexCount` 校验长度；布局不一致时立即报错。
