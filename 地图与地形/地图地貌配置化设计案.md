# 地图地貌配置化设计案

> 状态：已实施（2026-07-31 落地，P0~P6 全部完成）  
> 参考模式：已落地的地图资源配置系统（`MapResourceSO` / `MapResourceDatabaseSO`）  
> 明确规则：森林取消移动惩罚，第一版配置为无任何效果；石头也保持无效果

## 1. 现状调研结论

当前地貌仍采用“枚举 + 按索引取模型 + 效果散落在业务代码”的结构：

| 职责 | 当前实现 | 代码依据 |
| --- | --- | --- |
| 类型定义 | `Enums.LandFormType` 固定定义森林、石头、大骨阵、农田、None | `Assets/Scripts/Utilities/Enums.cs:43-55` |
| 随机生成 | `Next(0,14)` 后 Clamp 到 0~4，四种地貌各 1/14，空白 10/14 | `Assets/Scripts/Managers/MapGenerator.cs:247-259` |
| 生成限制 | 水域和河流格不生成地貌 | `MapGenerator.cs:253-255` |
| 与资源互斥 | 地貌先生成，有地貌时资源生成直接跳过 | `MapGenerator.cs:126-128,271-272` |
| 地块状态 | `HexCellData.landFormType` 保存枚举，`landFormModel` 保存实例 | `Assets/Scripts/Core/Models/HexCellData.cs:18-19` |
| 模型映射 | `landFormType` 作为 `landFormModels` 列表索引 | `MapRenderer.cs:1074-1075`、`EnvironmentModelsSO.cs:7` |
| 大骨阵 | 被攻击者站在大骨阵时防御加数为 0.3 | `CombatResolver.cs:99-102,132` |
| 农田 | 站在农田每 5 秒回复 10% 最大生命 | `UnitBrainBase.cs:33-34,76-91` |
| 森林 | 构造函数中写有 `movementCost += 1` | `HexCellData.cs:317` |
| 石头 | 只有“高度 +1”的注释，没有实现 | `Enums.cs:48` |

### 1.1 森林效果实际未生效

`HexCellData` 构造函数没有接收地貌参数，构造时 `landFormType` 恒为默认 `None`（`HexCellData.cs:18,296-298`）；森林判断却在该构造函数内执行（`:317`），而真正的地貌赋值发生在所有地块构造完成之后（`MapGenerator.cs:122-128,247-259`）。因此森林移动成本从未增加；取消森林惩罚不会改变当前实际玩法，只需删除这段死代码，并把森林配置成 `None` 效果。

寻路系统本身会读取 `movementCost`（`UnitMovementSystem.cs:117,722`），所以必须明确删除森林对该字段的任何写入，防止配置化时误把原设计意图重新启用。

### 1.2 `LandFormConfigSO` 是孤悬配置

`LandFormConfigSO` 定义了 `HealRatio=0.1` 和 `HealInterval=5`（`LandFormConfigSO.cs:16-22`），但全项目没有实例资产，也没有任何运行时代码注入或读取它；`UnitBrainBase` 明确使用硬编码常量（`UnitBrainBase.cs:32-34`）。因此本次不应继续接入该旧 SO，而应把农田回血参数收回农田自己的配置资产，迁移后删除 `LandFormConfigSO.cs`。

### 1.3 不适合向单位 Brain 注入数据库

玩家单位、AI 单位和兵营单位都是运行时 `AddComponent` 后手动调用 `Initialize`：

- 玩家卡牌生成：`CardPresenter.cs:356-357`
- AI 生成：`AIEntityFactory.cs:202-203`
- 兵营生成：`BarracksSpawner.cs:165-180`
- `PlayerUnitBrain.Initialize` 与 `AIUnitBrain.Initialize` 都是手动参数传递（`PlayerUnitBrain.cs:27-53`、`AIUnitBrain.cs:18-37`）

如果把地貌数据库注入 Brain，就必须同步修改多个生成入口。更小、更可靠的方案是让 `HexCellData` 直接持有 `MapLandFormSO`；Brain 已经能通过 `GetCurrentCell()` 获取当前格（`UnitBrainBase.cs:70-74`），直接读取地块配置即可，不增加任何 Brain 初始化参数。

## 2. 设计目标

1. 一种地貌对应一个 `MapLandFormSO`，模型、生成权重和效果参数集中配置。
2. 地块直接持有 `MapLandFormSO` 引用，不保留枚举与 SO 两份状态。
3. 森林和石头第一版均配置为 `None`，没有移动、战斗、回血或高度效果。
4. 大骨阵保持防御 +0.3，农田保持每 5 秒回复 10% 最大生命，不改变现有有效玩法。
5. 生成概率保持不变：四种地貌各 1/14，空白 10/14。
6. 移除 `EnvironmentModelsSO.landFormModels` 的索引耦合；模型由各地貌 SO 直接引用。
7. 效果计算集中到纯规则类，`CombatResolver` 与旧攻击路径不能各自硬编码一套。
8. 第一版不配置生态条件；水域、河流、资源互斥仍作为地图全局规则留在 `MapGenerator`。

## 3. 数据结构设计

建议目录：`Assets/Scripts/ScriptableObjects/MapLandForm/`。

### 3.1 `LandFormEffectType`

```csharp
public enum LandFormEffectType
{
    None = 0,
    DefenseBonus = 1,
    PeriodicHeal = 2,
}
```

第一版只包含当前真实需要的三种行为，不加入未使用的移动成本、高度修改或河流效果：

| 地貌 | `effectType` | 参数 |
| --- | --- | --- |
| 森林 | `None` | 无 |
| 石头 | `None` | 无 |
| 大骨阵 | `DefenseBonus` | `defenseBonus=0.3` |
| 农田 | `PeriodicHeal` | `healRatio=0.1`、`healInterval=5` |

森林明确不提供 `movementCostModifier` 字段，避免 Inspector 中留下“填 0 还是填 1”的歧义；未来若重新设计移动类地貌，再新增独立的效果类型和执行规则。

### 3.2 `LandFormEffect`

```csharp
[System.Serializable]
public struct LandFormEffect
{
    [Tooltip("防御加数：0.3 = 防御系数 +0.3")]
    public float defenseBonus;

    [Tooltip("每次回复最大生命比例：0.1 = 10%")]
    public float healRatio;

    [Tooltip("周期回血间隔，秒")]
    public float healInterval;
}
```

该结构沿用 `TacticalCardEffect` 和 `ResourcePickupEffect` 的项目风格：按 `effectType` 读取对应字段；无效字段由编辑器校验忽略，不在第一版引入多态 SO 或反射执行器。

### 3.3 `MapLandFormSO`

```csharp
[CreateAssetMenu(fileName = "MapLandForm", menuName = "Game Data/Map Land Forms/Map Land Form")]
public class MapLandFormSO : ScriptableObject
{
    [Header("显示")]
    public string landFormId;
    public string landFormName;
    [TextArea(2, 4)] public string description;

    [Header("地图表现")]
    public GameObject modelPrefab;

    [Header("效果")]
    public LandFormEffectType effectType;
    public LandFormEffect effect;

    [Header("生成")]
    [Min(0)] public int spawnWeight = 1;
}
```

`landFormId` 只用于日志、编辑器校验和未来存档；本局运行时直接保存 SO 引用，不使用字符串查表。

### 3.4 `MapLandFormDatabaseSO`

```csharp
[CreateAssetMenu(fileName = "MapLandFormDatabase", menuName = "Game Data/Map Land Forms/Map Land Form Database")]
public class MapLandFormDatabaseSO : ScriptableObject
{
    public List<MapLandFormSO> landForms = new();

    [Tooltip("不生成地貌的权重；为保持现状配置 10")]
    [Min(0)] public int emptySpawnWeight = 10;
}
```

复现现有概率：森林、石头、大骨阵、农田各 `spawnWeight=1`，`emptySpawnWeight=10`，总权重 14。

## 4. 运行时结构

### 4.1 地块直接持有配置

`HexCellData` 原字段：

```csharp
public Enums.LandFormType landFormType = Enums.LandFormType.None;
public GameObject landFormModel;
```

迁移为：

```csharp
public MapLandFormSO landForm;
public GameObject landFormModel;
```

`null` 表示没有地貌。不要长期保留枚举和 SO 双字段，也不需要 `landFormId` 运行时字典查询；该项目的地块在每局启动时生成，没有地貌存档反序列化路径。

### 4.2 `LandFormSpawnRule`

仿照已落地的 `ResourceSpawnRule`，提供两个纯函数重载：

```csharp
public static int TotalWeight(MapLandFormDatabaseSO database);
public static MapLandFormSO RollLandForm(MapLandFormDatabaseSO database, System.Random random);
public static MapLandFormSO RollLandForm(MapLandFormDatabaseSO database, int rollValue);
```

为保持固定种子地图与旧算法一致，掷点顺序必须固定为“列表地貌在前、空白权重在后”：0~3 依次返回森林、石头、大骨阵、农田，4~13 返回 null。旧代码正是 0~3 映射四种枚举、其余值 Clamp 为 `None`（`MapGenerator.cs:257`）；如果照搬资源系统的“空白在前”顺序，概率虽相同，但同一种子下地貌位置和类型都会改变。确定性重载用于锁定该映射。

### 4.3 `LandFormEffectRule`

战斗和 Brain 不应直接比较具体地貌 ID，而应查询效果类型：

```csharp
public static float GetDefenseBonus(MapLandFormSO landForm)
{
    return landForm != null && landForm.effectType == LandFormEffectType.DefenseBonus
        ? landForm.effect.defenseBonus
        : 0f;
}

public static bool TryGetPeriodicHeal(
    MapLandFormSO landForm,
    out float healRatio,
    out float healInterval);
```

该规则类保持无状态、无 Unity 场景依赖，便于测试；不需要 `LandFormEffectService` 或 Provider。

## 5. 各模块改造

### 5.1 地貌生成

`MapGenerator` 注入 `MapLandFormDatabaseSO`，`LandFormDataGeneration` 调用 `LandFormSpawnRule.RollLandForm`。水域/河流排除保持不变（当前 `MapGenerator.cs:253-255`）。

资源互斥判断由：

```csharp
hexCellData.landFormType != Enums.LandFormType.None
```

改为：

```csharp
hexCellData.landForm != null
```

森林不再写 `movementCost`；删除 `HexCellData` 构造函数中现有的森林死代码（`HexCellData.cs:317`）。

### 5.2 地貌模型

`MapRenderer.InstantiateLandForms` 改为：地块 `landForm == null` 或 `modelPrefab == null` 时跳过，否则直接实例化 `landForm.modelPrefab`。迁移完成后不再注入 `IEnvironmentModelsProvider`。

现有四个模型引用来自 `EnvironmentModels.asset:15-19`，迁移资产时原样复制：

| 地貌 | 现有模型 GUID |
| --- | --- |
| 森林 | `a959dbb7b69ddcc47a11a936f54eb5d5` |
| 石头 | `c6d7e9e2b282a79448ea21d277267695` |
| 大骨阵 | `cb07d4819e05d704a9c1727693195573` |
| 农田 | `ad0e09072af456746ac2ff6b77407d1c` |

资源配置化后，`EnvironmentModelsSO` 当前只剩地貌模型列表（`EnvironmentModelsSO.cs:5-7`）；地貌迁移后它将没有职责，可整体删除：

- 删除 `EnvironmentModelsSO.cs` 和旧 `EnvironmentModels.asset`
- 删除 `IEnvironmentModelsProvider` / `EnvironmentModelsProvider`
- 删除 `GameInstaller` 的 `_environmentModelsSO` 字段、绑定和缺失校验
- 从 `GameScene.unity` 移除 `_environmentModelsSO` 序列化引用

### 5.3 大骨阵防御

`CombatResolver.ComputeUnitDamage` 不再把地貌效果写入 `CharacterData.LandFormType_BigBones`，改为局部查询：

```csharp
float landFormDefenseBonus = LandFormEffectRule.GetDefenseBonus(defenderCell.landForm);
float defenseGain = 1f
    + defender.Resource_Minerals
    + landFormDefenseBonus
    + defender.LandFormType_River;
```

这会删除“地貌状态缓存在单位数据上”的隐式状态，避免单位离开地貌后保留旧值。`CharacterData.LandFormType_BigBones` 随迁移删除。

`UnitMovementController.AttackDataComputation` 仍有一份镜像公式（`UnitMovementController.cs:361-398`）。第一版至少必须改成调用同一个 `LandFormEffectRule`；只有确认旧动画路径不再结算伤害后，才能在独立清理任务中删除整段，不能在配置化重构中直接猜测它已无用。

### 5.4 农田周期回血

`UnitBrainBase.TickLandHeal` 保留计时器，但条件与数值改从当前格 SO 获取：

```csharp
MapLandFormSO current = GetCurrentCell()?.landForm;
if (!LandFormEffectRule.TryGetPeriodicHeal(current, out float ratio, out float interval))
{
    _landHealTimer = 0f;
    _landHealSource = null;
    return;
}
```

新增 `_landHealSource` 缓存；单位从一种回血地貌移动到另一种不同配置时重置计时器，避免沿用前一地貌已累计的时间。到达配置间隔后调用 `Owner.Heal(ratio * Owner.unitData.hp)`。

迁移后删除：

- `UnitBrainBase` 的 `HealInterval` / `LandHealRatio` 地貌常量
- 无实际引用的 `LandFormConfigSO.cs`
- 无实际引用的 `CharacterData.LandFormType_FromLand`

祭坛回血仍使用 `BuildingData.HealInterval` 和 `AltarValue`（`UnitBrainBase.cs:93-113`），不属于地貌配置，不随本次迁移改变；可保留一个只供祭坛兜底的常量，不能误删。

### 5.5 森林和石头

森林配置：

```text
effectType = None
spawnWeight = 1
modelPrefab = 现有森林模型
```

石头配置：

```text
effectType = None
spawnWeight = 1
modelPrefab = 现有石头模型
```

两者只有生成和视觉表现，不修改 `movementCost`、`Height`、战斗属性或回血状态。原“森林移动力 -1”和“石头高度 +1”注释应同步删除，避免文档再次与实现漂移。

## 6. 数据库校验

建议 `MapLandFormDatabaseSO.OnValidate` 或独立编辑器校验覆盖：

| 校验项 | 规则 |
| --- | --- |
| 列表项 | 不允许 null |
| ID | `landFormId` 非空且唯一 |
| 权重 | `spawnWeight >= 0`、`emptySpawnWeight >= 0`、总权重 > 0 |
| 模型 | `spawnWeight > 0` 的地貌必须有 `modelPrefab`（若未来允许隐形地貌再放宽） |
| `DefenseBonus` | `defenseBonus >= 0` |
| `PeriodicHeal` | `healRatio > 0` 且 `healInterval > 0` |
| `None` | 不执行任何参数，不因残留数值产生效果 |

数据库缺失仍由 `GameInstaller.ValidateRequiredReferences` 启动时失败；条目级问题应在编辑器 `OnValidate` 提前报告。

## 8. 原子迁移步骤

| 阶段 | 内容 | 验证重点 |
| --- | --- | --- |
| P0 | 新建 `LandFormEffectType`、`LandFormEffect`、`MapLandFormSO`、`MapLandFormDatabaseSO` 和四个资产 | Inspector 引用与参数正确；森林/石头为 `None` |
| P1 | 新建 `LandFormSpawnRule`、`LandFormEffectRule` 及纯函数测试 | 10/14 空白、四种各 1/14；None 返回零效果 |
| P2 | 原子切换 `HexCellData.landFormType` → `MapLandFormSO landForm`，同步改生成、资源互斥、渲染 | 不长期保留双状态；模型分布与改造前一致 |
| P3 | 改 `CombatResolver` 与旧 `AttackDataComputation`，删除 BigBones 缓存字段 | 大骨阵仍 +0.3；森林/石头防御加成为 0 |
| P4 | 改 `UnitBrainBase` 农田回血，删除死 `LandFormConfigSO` 和 `LandFormType_FromLand` | 每 5 秒回 10%，离开/切换来源重置，暂停时不计时 |
| P5 | 删除 `Enums.LandFormType`、`EnvironmentModelsSO`/Provider、旧数据类和过时注释 | 全项目无枚举/索引/旧配置引用 |
| P6 | 全量 EditMode + PlayMode 手工验证 | 生成、模型、战斗、回血、资源互斥、公共建筑发现均正常 |

P2 必须作为一个可编译的原子变更完成，因为 `MapGenerator`、`MapRenderer`、`CombatResolver`、`UnitBrainBase` 和资源互斥都直接读取地块字段；不建议先加 SO、再长期维护枚举回填。

## 9. 测试方案

### 9.1 EditMode

1. `LandFormSpawnRule_WeightedRoll_MatchesLegacyDistribution`：0~3 依次为四种地貌，4~13 为 null，总权重 14；同时锁定旧固定种子映射。
2. `LandFormEffectRule_None_HasNoEffect`：森林和石头返回 0 防御、无周期回血。
3. `LandFormEffectRule_DefenseBonus_UsesConfiguredValue`：大骨阵返回 0.3。
4. `LandFormEffectRule_PeriodicHeal_UsesConfiguredValues`：农田返回 0.1 和 5 秒。
5. `MapGenerator_LandFormAndResourceAreMutuallyExclusive`：有地貌格不生成资源。
6. `LandFormDatabase_RejectsDuplicateIdAndInvalidWeights`：配置校验。
7. `EnvironmentModelsProvider` 相关旧测试/绑定测试更新或删除。

### 9.2 手工运行

1. 固定种子下对比改造前后地貌数量和位置，确认随机流顺序不变。
2. 森林与石头格移动速度、寻路成本和战斗数值均与普通格一致。
3. 大骨阵防守单位伤害公式仍含 +0.3。
4. 农田单位站满 5 秒回复 10%，离开后重新计时，暂停期间不累计。
5. 水域/河流无地貌；地貌格无地图资源。
6. 地貌模型继续参与选择性雾化，公共建筑发现流程不受影响。

## 10. 可行性复核

| 维度 | 结论 | 依据 |
| --- | --- | --- |
| 数据配置 | 高 | 项目已有地图资源 SO/数据库实现，可直接复用结构 |
| 生成改造 | 高 | 地貌生成集中在 `MapGenerator.LandFormDataGeneration`，仅一个入口 |
| 渲染改造 | 高 | 地貌模型只在 `MapRenderer.InstantiateLandForms` 创建 |
| 战斗改造 | 中高 | 主要结算在 `CombatResolver`，但旧 `AttackDataComputation` 仍需同步处理 |
| 回血改造 | 高 | Brain 已通过当前格读取地貌，不需要改单位生成/注入链路 |
| 资产迁移 | 高 | 四个现有模型引用明确，可直接复制到新 SO |
| 回归风险 | 中等 | 需同时覆盖生成、资源互斥、战斗和计时器；测试范围清晰 |
| 维护收益 | 高 | 删除枚举索引、硬编码效果、孤悬 SO 与两个旧数据类 |

结论：**方案可行性高，改动面中等但集中。** 推荐最小结构为：

```text
MapLandFormSO
MapLandFormDatabaseSO
LandFormSpawnRule
LandFormEffectRule
HexCellData.landForm（直接 SO 引用）
```

不推荐增加 Provider、字符串运行时查找、地貌实例类或向每个单位 Brain 注入数据库。森林与石头第一版均为纯视觉地貌；大骨阵与农田保持现有有效行为。
