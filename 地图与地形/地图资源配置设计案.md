# 地图资源（道具）配置化设计案

> 状态：已实施（2026-07-31 落地，P0~P5 全部完成）
> 参考模式：战术卡牌系统（`Assets/Scripts/TacticalCard/`）
> 目标：把地图道具从"枚举 + 多处分发硬编码"重构为"ScriptableObject 单条配置 + 数据库 + 单一规则"，与卡牌系统同构。

## 1. 现状与问题

当前地图道具（`Enums.ResourceType`：动物/植物/矿物/宝箱/回血包）的规则全部硬编码在 C# 中，且分散在 7 处：

| # | 硬编码点 | 位置 |
| --- | --- | --- |
| 1 | 类型枚举（加一种道具必须改枚举） | `Assets/Scripts/Utilities/Enums.cs:96-110` |
| 2 | 生成概率写死（`random.Next(0, 18)` + `roll < 5`） | `Assets/Scripts/Managers/MapGenerator.cs:261-283` |
| 3 | 单位拾取效果 switch（+0.7 攻 / 回 25% 血 / +0.25 防 / +50 金） | `Assets/Scripts/Controllers/UnitMovementController.cs:702-747` |
| 4 | 探索收割金币 switch（5 基础 + 20/15/25/30/10），**玩家/AI/公共建筑三处重复** | `ExplorationService.cs:87-116`、`AIAutoExplorer.cs:124-143`、`PublicBuildingBase.cs:380-406` |
| 5 | 拾取特效 switch（动物/植物/矿物/宝箱→各特效） | `Assets/Scripts/Core/Services/DataProviders/EnvironmentModelsProvider.cs:35-45` |
| 6 | 模型按枚举**索引**对齐 `EnvironmentModelsSO.resourceModels` 列表 | `MapRenderer.cs:1086-1102`、`EnvironmentModelsSO.cs:8` |
| 7 | 拾取音效字符串写死（`Cymbals-008`/`heal5`/`Metallic_Weapon_Hit-020`/`Coin8`） | `UnitMovementController.cs:723,727,731,736` |

痛点：
- 新增一种道具要同时改 7 处，漏一处就出 bug；
- 数值平衡只能改代码、无法在 Inspector 调；
- 同一套金币换算逻辑在三个文件镜像重复，已存在漂移风险（与改造前 `CardService.GenerateNextCardID` / `AICardBrain.GenerateCardId` 重复问题同构，见 `CardGenerationRule.cs:1-9` 注释）。

## 2. 参考模式：卡牌系统架构

战术卡牌系统是项目内现成的"单条 SO + 数据库 + 分发"范例：

```text
TacticalCardSO（单条卡配置）
├── 显示字段：cardId / cardName / description / cardSprite     （TacticalCardSO.cs:6-18）
├── 效果类型枚举：effectType（TacticalEffectType）               （TacticalCardSO.cs:22）
└── 效果参数 struct：effect（TacticalCardEffect，
    内含该类型所有效果参数，按类型取用）                          （TacticalCardSO.cs:25、TacticalCardEffect.cs:5-18）

TacticalCardDatabaseSO（数据库容器）
└── List<TacticalCardSO> cards                                  （TacticalCardDatabaseSO.cs:8）

GameInstaller（绑定 + 预校验）
├── Container.Bind<TacticalCardDatabaseSO>().FromInstance(...).AsSingle()   （GameInstaller.cs:196）
└── ValidateRequiredReferences 里 AddMissing 校验                          （GameInstaller.cs:236）

TacticalCardPresenter（消费端：按 effectType switch 分发）
└── switch (config.effectType) → TryExecuteRepair / TryExecuteBattleOrder   （TacticalCardPresenter.cs:95-110）
    效果参数取自 config.effect（如 healRatio，TacticalCardPresenter.cs:167）
```

本项目卡牌/建筑/天赋卡均采用该模式（`UnitDatabaseSO.cs:4`、`BuildingDatabaseSO.cs:4`、`PublicBuildingSO.cs:8`、`TalentCardConfigSO.cs:35`），道具系统应照搬。

## 3. 设计目标

1. **一条道具一条 SO**：显示、效果、金币、模型、特效、音效、生成权重全部在一处配置；
2. **单一规则**：探索收割金币换算收敛为一个静态规则类（对齐 `CardGenerationRule` 模式，`CardGenerationRule.cs:11-34`）；
3. **已有行为零代码扩展**：新增使用现有效果类型的道具，只创建 SO 资产并加入数据库；新增全新的效果行为仍需要增加执行代码；
4. **单一事实源**：运行时地块直接持有 `MapResourceSO` 引用，不同时保存字符串 ID 和旧枚举，避免两份状态不一致；
5. **剔除索引耦合**：模型/特效不再按枚举索引对齐列表（现状 `MapRenderer.cs:1094`、`EnvironmentModelsProvider.cs:33`）。

## 4. 数据层设计（新增 4 个类型，全部位于 `Assets/Scripts/ScriptableObjects/MapResource/`）

### 4.1 `ResourcePickupEffect`（效果参数 struct，对齐 `TacticalCardEffect`）

```csharp
[System.Serializable]
public struct ResourcePickupEffect
{
    [Tooltip("攻击力固定加成（动物用）：0.7 = +0.7 攻")]
    public float attackBonus;
    [Tooltip("回复比例（植物用）：0.25 = 回 25% 最大 HP")]
    public float healRatio;
    [Tooltip("防御力固定加成（矿物用）：0.25 = +0.25 防")]
    public float defenseBonus;
    [Tooltip("金币数量（宝箱用）：50 = +50 金")]
    public int goldAmount;
}
```

### 4.2 `ResourcePickupEffectType`（效果类型枚举，对齐 `TacticalEffectType`）

```csharp
public enum ResourcePickupEffectType
{
    None          = 0, // 拾取无效果（回血包现状）
    AttackBoost   = 1, // 提升下一次攻击力（动物）
    Heal          = 2, // 立即回血（植物）
    DefenseBoost  = 3, // 提升下一次防御力（矿物）
    Gold          = 4, // 获得金币（宝箱）
}
```

### 4.3 `MapResourceSO`（单条资源配置，对齐 `TacticalCardSO`）

```csharp
[CreateAssetMenu(fileName = "MapResource", menuName = "Game Data/Map Resources/Map Resource")]
public class MapResourceSO : ScriptableObject
{
    [Header("显示")]
    [Tooltip("稳定唯一 ID；仅用于日志、编辑器校验和未来存档，不作为本局运行时查找键")]
    public string resourceId;
    [Tooltip("名称")]
    public string resourceName;
    [Tooltip("描述")]
    [TextArea(2, 4)] public string description;

    [Header("地图表现")]
    [Tooltip("地图模型预制体；留空 = 不生成模型（回血包现状）")]
    public GameObject modelPrefab;
    [Tooltip("拾取特效预制体；留空 = 无特效")]
    public GameObject reapEffectPrefab;
    [Tooltip("拾取音效名；留空 = 无音效")]
    public string pickupSfxName;

    [Header("拾取效果（单位踩格）")]
    [Tooltip("拾取效果类型")]
    public ResourcePickupEffectType pickupEffectType;
    [Tooltip("拾取效果参数（按 pickupEffectType 取用）")]
    public ResourcePickupEffect pickupEffect;

    [Header("探索收割")]
    [Tooltip("探索收割金币加成（最终 = 基础 5 + 本值）")]
    public int explorationGoldBonus;

    [Header("生成")]
    [Tooltip("生成权重；0 = 本资源不生成。总权重由数据库汇总")]
    public int spawnWeight = 1;

}
```

说明：`modelPrefab` 为 null 即不生成模型——直接解决"回血包 index ≥4 被 `MapRenderer.cs:1093` 硬跳过"的隐式约定；`spawnWeight` 替代 `MapGenerator.cs:273,278-283` 写死的 `Next(0,18)` / `roll < 5`。

### 4.4 `MapResourceDatabaseSO`（数据库容器，对齐 `TacticalCardDatabaseSO`）

```csharp
[CreateAssetMenu(fileName = "MapResourceDatabase", menuName = "Game Data/Map Resources/Map Resource Database")]
public class MapResourceDatabaseSO : ScriptableObject
{
    [Tooltip("所有地图资源定义")]
    public List<MapResourceSO> resources = new();

    [Tooltip("不生成资源的权重；现状应配置为 14")]
    [Min(0)] public int emptySpawnWeight = 14;

    [Tooltip("探索任意地块的基础金币奖励")]
    [Min(0)] public int baseExplorationGold = 5;
}
```

当前实际随机生成的是 4 种资源，不是 5 种：`MapRandomResourceRoll` 仅接受 0~3，值 4（`HealthPack`）返回 `None`（`MapGenerator.cs:278-282`），且 `DomainInvariantTests.cs:57-66` 明确测试了该行为。因此复现现状应配置 4 条资源各 `spawnWeight=1`、`emptySpawnWeight=14`，总权重 18，资源生成概率为 4/18。

## 5. 运行时层设计

### 5.1 直接持有 SO 引用，不增加 Provider

参考卡牌运行时实例直接保存 `TacticalCardSO Config`（`TacticalCardInstance.cs:3`），地图地块也应直接保存 `MapResourceSO`。本系统没有存档反序列化、网络同步或外部字符串输入，不需要每次通过 `resourceId` 查字典；额外增加 `IResourceConfigProvider` 只会增加接口、缓存和空值分支。

`MapResourceDatabaseSO` 仅注入需要“遍历全部资源”的 `MapGenerator`；拾取、渲染和探索逻辑直接读取地块上的 SO 引用。`EnvironmentModelsSO` 继续负责地貌模型，但资源模型和四个拾取特效字段（`EnvironmentModelsSO.cs:8-12`）在迁移完成后删除。

### 5.2 `ResourceRewardRule`（单一收割规则，对齐 `CardGenerationRule`）

`Assets/Scripts/Core/Services/ResourceRewardRule.cs`——**消灭三处镜像重复**（现状：`ExplorationService.cs:91-101`、`AIAutoExplorer.cs:127-136`、`PublicBuildingBase.cs:384-393` 三份相同 switch）：

```csharp
public static class ResourceRewardRule
{
    public static int ComputeExplorationReward(int baseReward, MapResourceSO resource)
        => baseReward + (resource == null ? 0 : resource.explorationGoldBonus);
}
```

基础奖励不能继续写成 `const 5`，否则仍是硬编码；它来自 `MapResourceDatabaseSO.baseExplorationGold`。纯函数只负责计算，便于 EditMode 测试。

### 5.3 `MapResourceCollectionService`（统一消费、拾取与收割）

原案只收敛了金币计算，但玩家探索、AI 探索和公共建筑占领还会重复执行“读取资源→清数据→销毁模型→加金币”。更合理的边界是一个收集服务统一负责资源的一次性消费：

```csharp
public class MapResourceCollectionService
{
    public bool TryCollectForUnit(HexCellData cell, CharacterData character, int factionId);
    public int HarvestForGold(HexCellData cell, int factionId);
}
```

- 两个入口都先调用地块的 `TakeResource()`，原子式“返回旧配置并清空”，防止重复结算；
- `TryCollectForUnit` 按 `pickupEffectType` 应用效果，并统一处理模型销毁、音效和特效；
- `HarvestForGold` 使用 `ResourceRewardRule` 计算并向指定阵营钱包发放金币，同时统一销毁模型；
- `UnitMovementController.AutoHarvestResource` 最终只保留一次服务调用；三个探索/占领调用点也只保留 `HarvestForGold`；
- 音效仍用字符串是因为现有接口就是 `AudioManager.PlaySFX(string)`（`AudioManager.cs:118-127`）。当前 `AudioManager` 未暴露音效目录查询接口，因此本次只校验非必填字段的空白规则；若要编辑期验证名称是否存在，应先为音频系统增加只读查询 API，不能让资源数据库反向读取 `AudioManager` 私有字典。

### 5.4 生成与渲染改造

- `MapGenerator.ResourceDataGeneration`（`MapGenerator.cs:261-283`）：在“空白权重 + 所有资源正权重”中掷点，命中空白则地块保持 null，否则直接写入选中的 `MapResourceSO` 引用；资源的水域/河流/地貌互斥规则暂时保持为全局地图规则，不在第一版做成每资源生态条件。
- `MapRenderer.InstantiateResources`（`MapRenderer.cs:1086-1102`）：遍历数据库，`modelPrefab == null` 跳过（删除 `(int)resourceType >= 4` 硬跳过 `MapRenderer.cs:1093`）；不再按枚举索引取 `resourceModels`（`MapRenderer.cs:1094`）。

## 6. 地块数据变更

`HexCellData`（`HexCellData.cs:21-22`）直接把枚举字段替换为 SO 引用：

```csharp
public MapResourceSO resource;
public GameObject resourceModel;
```

把 `GetResource()` + `ReapResource()` 改为一次操作，减少“先读后清”被重复调用的可能：

```csharp
public MapResourceSO TakeResource()
{
    MapResourceSO taken = resource;
    resource = null;
    return taken;
}
```

本项目地块由地图启动时运行时生成，没有资源存档反序列化路径；全项目实际资源读取点也只有单位拾取和三处探索/占领，因此一次性切换比长期保留 `resourceId + ResourceType` 双字段更安全、工作量更小。

## 7. 绑定与预校验（对齐 `GameInstaller`）

- 绑定：`Container.Bind<MapResourceDatabaseSO>().FromInstance(_mapResourceDatabaseSO).AsSingle();`（对齐 `GameInstaller.cs:196` 的卡牌绑定写法）；
- 新增 `[SerializeField] private MapResourceDatabaseSO _mapResourceDatabaseSO;`（对齐 `GameInstaller.cs:22`）；
- `ValidateRequiredReferences` 增加 `AddMissing(missing, _mapResourceDatabaseSO, nameof(_mapResourceDatabaseSO));`（对齐 `GameInstaller.cs:236`）；
- 数据库校验：拒绝 null 条目、重复/空 `resourceId`、负权重、总权重为 0；对需要表现的资源检查模型/特效配置。数据库缺失仍沿用 `GameInstaller.cs:248-253` 的失败方式，条目错误建议由 `OnValidate` 在编辑期提前报告。

## 8. 资产与配置示例

目录：`Assets/Resources/` 或 `Assets/ScriptableObjects/MapResources/`（跟随现有 SO 资产存放位置，如 `EnvironmentModels.asset`）：

```text
MapResourceDatabase.asset
├── Animals.asset     （模型=动物预制体, 特效=reapAnimalsEffect, pickup=AttackBoost 0.7,
│                       explorationGoldBonus=20, weight=1, legacy=Animals）
├── Plants.asset      （pickup=Heal 0.25, explorationGoldBonus=15, ...）
├── Minerals.asset    （pickup=DefenseBoost 0.25, explorationGoldBonus=25, ...）
├── Chest.asset       （pickup=Gold 50, explorationGoldBonus=30, ...）
└── HealthPack.asset  （保留历史数据但 spawnWeight=0；或本次不迁移该不可达配置）
```

复现现有概率：动物、植物、矿物、宝箱各 `spawnWeight=1`，数据库 `emptySpawnWeight=14`，总权重 18 → 每格 4/18 概率生成资源。不要创建“空白资源 SO”，因为“没有资源”应由 null 表示，而不是一条可被错误渲染或收割的伪资源。

## 10. 风险与开放问题

1. **效果仍需代码实现**：SO 能配置现有 `AttackBoost/Heal/DefenseBoost/Gold`，但新增“召唤单位”等全新行为必须新增执行器分支；“任意新效果零代码”不属于本方案承诺。
2. **"宝箱仅玩家有效"差异**（`UnitMovementController.cs:734`）：这是现有行为但疑似规则缺口。配置化时先原样保留，是否允许 AI 获得金币应作为独立玩法决策，不在重构中顺手改变。
3. **旧公式残留**：`UnitMovementController.cs:393-395` 与 `BuildingBase.cs:128-134` 中 `Resource_Animals`/`Resource_Minerals` 的消费语义不一致（单位战不重置），本次只做"配置化"不修行为，需在文档另记。
4. **公共建筑收割逻辑**：`PublicBuildingBase` 的"已探索格跳过 + `_pendingCaptureRewards` 补偿"（`PublicBuildingBase.cs:331-333,349-351`）与配置化无冲突，保持不动。
5. **`CharacterData.Resource_Plants`**（`CharacterData.cs:39`）：全项目未被赋值，P5 一并删除。

## 11. 可行性复核结论

结论：**修订后可行性高，建议实施；原案可行但偏重，且生成概率有事实错误。**

| 维度 | 结论 | 依据 |
| --- | --- | --- |
| Unity 数据配置 | 高 | 项目已有多套 SO + Zenject 实例绑定；卡牌数据库直接注入已有先例（`GameInstaller.cs:196`） |
| 改动范围 | 中等且可控 | 核心调用点集中在地图生成、渲染、单位拾取和三处收割，没有存档/网络迁移 |
| 运行时成本 | 可忽略 | 地块直接持有 SO 引用，避免字符串字典查询；600 格地图规模下权重选择只发生在初始化 |
| 行为回归风险 | 中等 | 资源同时连接生成、表现、拾取、探索和公共建筑；必须用测试锁定 4/18 概率和现有效果 |
| 扩展能力 | 中高 | 使用已有四类效果新增资源无需代码；新增全新行为仍需代码，边界清晰 |
| 维护收益 | 高 | 消除模型索引约定、4 个效果 switch/映射和三份完整收割重复 |

推荐采用修订后的最小结构：`MapResourceSO + MapResourceDatabaseSO + MapResourceCollectionService + 两个纯规则函数`。不推荐引入字符串运行时查找、额外 Provider、双字段长期兼容或“空白资源 SO”。
