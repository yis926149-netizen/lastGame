# 地图道具（地块资源）系统总结

说明：项目中没有独立的"道具系统"代码命名，地图上的道具即**地块资源（`ResourceType`）**——动物、植物、矿物、宝箱、回血包。以下每句均附代码出处。

## 1. 道具的类型定义

道具共 5 种，定义在 `Assets/Scripts/Utilities/Enums.cs:96-110`：

```csharp
public enum ResourceType
{
    Animals,    //动物 - 提升下一次攻击力
    Plants,     //植物 - 立即回血
    Minerals,   //矿物 - 提升下一次防御力
    Chest,      //科技文化值宝箱 - 提升科文
    HealthPack, //击杀敌人掉落的回血包
    None
}
```

其中 `HealthPack` 的注释（"击杀敌人掉落的回血包"）是历史设计，当前代码中**没有击杀掉落实现，也不会被地图随机生成**：`MapRandomResourceRoll` 的条件是 `roll < (int)HealthPack`，所以掷到枚举值 4 时返回 `None`（`MapGenerator.cs:278-282`），测试也明确验证了该约束（`DomainInvariantTests.cs:57-66`）。它目前只保留了三处探索金币换算分支（`ExplorationService.cs:100`、`AIAutoExplorer.cs:135`、`PublicBuildingBase.cs:392`），正常流程不可达。

## 2. 道具的生成（地图初始化阶段）

生成在 `Assets/Scripts/Managers/MapGenerator.cs:261-283` 的 `ResourceDataGeneration`：

- **生成条件**：逐格遍历，跳过湖泊/海洋和有河流的格子（`MapGenerator.cs:269`：`if (isLakeOrSea(hexCellData) || hexCellData.hasRiver) { continue; }`）；也跳过已有地貌的格子（`MapGenerator.cs:271`：`if (hexCellData.landFormType != Enums.LandFormType.None) { continue; }`），即**地貌与资源互斥**。
- **概率**：`hexCellData.resourceType = MapRandomResourceRoll(random.Next(0, 18))`（`MapGenerator.cs:273`），掷 0~17 共 18 等份；由于 `HealthPack` 的枚举值为 4，而条件是 `roll < (int)HealthPack`（`MapGenerator.cs:280`），实际只有 0~3 映射为动物、植物、矿物、宝箱，4~17 均为 `None`。因此**每个合格格有 4/18 ≈ 22.2% 概率生成资源，4 种实际资源各 1/18 等概率**；`DomainInvariantTests.cs:57-66` 对此有明确测试。

## 3. 道具的数据存储与模型

- 数据挂在地块上：`HexCellData.resourceType`（`HexCellData.cs:21`）与 `resourceModel`（`HexCellData.cs:22`）；读取用 `GetResource()`（`HexCellData.cs:354-357`），清除用 `ReapResource()`（`HexCellData.cs:360-363`，置为 `None`）。
- 视觉模型：`Assets/Scripts/Managers/MapRenderer.cs:1086-1102` 的 `InstantiateResources` 按类型从 `EnvironmentModelsSO.resourceModels` 取预制体实例化到 `RealCenterWorldCoordinate`，挂在 `Resource` 根节点并设为 `FogAffectedEnvironment` 层（参与选择性雾化）。
- **只有前 4 种有模型**：`MapRenderer.cs:1093` 跳过 `(int)resourceType >= 4`，而 `EnvironmentModels.asset` 中 `resourceModels` 只有 4 项（索引 0~3 = 动物/植物/矿物/宝箱）。所以**宝箱有模型、回血包没有模型**（`MapRenderer.cs:1093-1094` 与 `EnvironmentModels.asset` 的 `resourceModels` 列表）。
- 模型显隐受公共建筑系统控制：公共建筑占位区生成时 `hex.resourceModel.SetActive(false)`（`PublicBuildingGenerator.cs:270-271`），发现时 `hex.resourceModel.SetActive(true)`（`PublicBuildingBase.cs:160-161`）。

## 4. 拾取途径 A：单位踩格自动拾取（核心玩法）

单位移动完成时自动拾取脚下道具，入口在 `Assets/Scripts/Controllers/UnitMovementController.cs:232-241` 的 `OnMoveFinished`：

```csharp
AutoHarvestResource();
```

`AutoHarvestResource`（`UnitMovementController.cs:702-747`）逻辑：

- 获取脚下地块：`_mapDataService.GetCellByWorldPosition(transform.position)`（`:706`），无资源直接返回（`:709-710`）。
- **先收割后生效**：`currentCell.ReapResource()` 清掉地块资源（`:712`），并 `Destroy(resourceModel)`、置空引用（`:713-717`）——因此**一个道具只能被拾取一次**。
- 效果按类型（`:719-738`）：
  - `Animals`：`characterData.Resource_Animals = 0.7f`（`:722`），播 SFX `Cymbals-008`（`:723`）；
  - `Plants`：`characterData.Heal(0.25f * characterData.unitData.hp)` 立即回 25% 最大生命（`:726`），播 `heal5`（`:727`）；
  - `Minerals`：`characterData.Resource_Minerals = 0.25f`（`:730`），播 `Metallic_Weapon_Hit-020`（`:731`）；
  - `Chest`：仅当 `PlayerIndex == 0`（玩家单位）时 `_goldWallet.AddGold(0, 50)` 加 50 金币（`:733-736`），播 `Coin8`（`:736`）——**AI 单位拾取宝箱无任何效果**；
  - `HealthPack`：switch 中无分支，拾取无效果。
- 拾取特效：`_environmentModelsProvider.GetReapEffect(resource)`（`:740`）取特效预制体，实例化在地块中心上方 0.5 处，4 秒后销毁（`:741-746`）。特效映射在 `EnvironmentModelsProvider.cs:35-45`：动物→`reapAnimalsEffect`、植物→`reapPlantsEffect`、矿物→`reapMineralsEffect`、宝箱→`reapChestEffect`（定义于 `EnvironmentModelsSO.cs:9-12`）。

**拾取不要求已探索**——探索不限制移动（`HexCellData.cs:315-316` 注释：未探索格不再通过 movementCost 隐式阻挡寻路），所以单位只要经过道具格就自动拾取；玩家与 AI 单位共用同一 `UnitMovementController`，拾取逻辑对双方一致（除宝箱的金币分支）。

## 5. 道具 Buff 的消费位置

- **攻击建筑时**：`Assets/Scripts/Controllers/BuildingBase.cs:128-134` 伤害公式含 `attacker.Resource_Animals`（+0.7 攻），且**一次性清空**：`if (attackGain > 1f) { attacker.Resource_Animals = 0; }`。
- **单位对单位战斗时**：`Assets/Scripts/Core/Services/CombatResolver.cs:127` 同样使用 `attacker.Resource_Animals` 加成、`:132` 使用 `theAttacked.Resource_Minerals`（+0.25 防），但**结算后不重置**——与建筑攻击的"一次性消耗"语义不一致（`CombatResolver.cs:126-134` 无清空逻辑；全项目 `Resource_Animals` 清空只出现在 `BuildingBase.cs:133`）。
- 另有一处残留的旧公式在 `UnitMovementController.cs:393-395`（`AttackDataComputation` 相关，仍引用这两个字段）。
- `CharacterData.Resource_Plants` 字段存在（`CharacterData.cs:39`）但**全项目从未被赋值**，是遗留字段。

## 6. 拾取途径 B：探索收割（换算为金币）

探索地块时道具不进入单位背包，而是直接换算金币。三处实现完全相同（基础 5 + 类型加成）：

- **玩家探索**：`Assets/Scripts/Core/Services/Exploration/ExplorationService.cs:87-116` 的 `HarvestAndReward`——基础 `int reward = 5`（`:91`），动物 +20、植物 +15、矿物 +25、宝箱 +30、回血包 +10（`:96-101`），随后 `cell.ReapResource()` 并销毁模型（`:104-112`），`_goldWallet.AddGold(0, reward)`（`:114`）。在 `TryExplore` 中于占领地块后同步执行（`ExplorationService.cs:69`）。
- **AI 探索**：`Assets/Scripts/AI/AIAutoExplorer.cs:124-143` 的 `HarvestAndReward`，加成数值与玩家完全一致（`:131-135`），`_goldWallet.AddGold(AIIndex, reward)`（`:142`）。
- **占领公共建筑**：`Assets/Scripts/Controllers/PublicBuildingBase.cs:380-406` 的 `HarvestAndReward`，数值同上（`:388-392`）。特点：势力范围扩张时**只收割"未探索过"的格**（`!hex.IsExploredBy(0)`）或**补偿收割**发现时记录的 `_pendingCaptureRewards`（`:331-333`、`:349-351`），避免同一道具被重复收割；`_pendingCaptureRewards` 在发现阶段登记（`PublicBuildingBase.cs:149-153`）。

对比可见同一道具的两套价值：单位踩格拾取（动物=下 1 次攻击 +0.7、植物=回 25% 血、矿物=防御 +0.25、宝箱=+50 金、回血包=无效果）与探索收割（固定金币 5+类型加成，宝箱只值 30 金）。

## 7. 道具不参与寻路与索敌

全项目对 `GetResource()`/`resourceType` 的读取只有 4 处（`grep` 结果）：探索收割（`ExplorationService.cs:93`、`AIAutoExplorer.cs:128`）、单位踩格拾取（`UnitMovementController.cs:709`）、公共建筑占领收割（`PublicBuildingBase.cs:385`）。**没有任何单位会主动搜索、趋近或绕开道具格**——拾取完全是被动触发（走过即拾取）。

| 道具 | 单位拾取效果（`UnitMovementController.cs:719-738`） | 探索收割金币（三处一致） | 地图模型 | 拾取特效（`EnvironmentModelsSO.cs`） |
| --- | --- | --- | --- | --- |
| 动物 Animals | 下次攻击 +0.7 | +20 | 有（index 0） | reapAnimalsEffect |
| 植物 Plants | 立即回 25% 最大血 | +15 | 有（index 1） | reapPlantsEffect |
| 矿物 Minerals | 防御 +0.25 | +25 | 有（index 2） | reapMineralsEffect |
| 宝箱 Chest | 玩家 +50 金（AI 无效） | +30 | 有（index 3） | reapChestEffect |
| 回血包 HealthPack | 无效果 | +10 | 无（index ≥4 被跳过） | 无 |
