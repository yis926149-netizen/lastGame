# 地图高度控制——颜色图方案讨论

## 目标

让策划能通过一张颜色图快速定义地图宏观地形分布，取代纯随机生成。系统读取颜色图，输出 `int[,]` 高度数组，接入现有管道（TerrainGenerator → MapGenerator → HexCellData → MeshDataGenerator），下游完全不动。

---

## 颜色-高度映射规则

| 颜色 | 地形 | 高度区间 |
|------|------|---------|
| 蓝色 `#0000FF` | 水域 (SeaFloor) | `Height <= seaLevel` |
| 绿色 `#00FF00` | 平地 (FlatLand) | `seaLevel < Height < midPoint` |
| 橙色 `#FF8C00` | 高地 (HighLand) | `Height >= midPoint` |

`midPoint` 不是独立配置项，复用现有 `WaterLevelConfig.ClassifyHeight` 中的计算：

```csharp
float midPoint = WaterLevel + (MaxHeight - WaterLevel + 1f) * 0.5f;
// Height < midPoint → 平地；Height >= midPoint → 高地
```

`WaterLevel`（= `seaLevel`）和 `MaxHeight`（= 地图实际最大高度）均在运行时由现有流程自动设置，颜色图方案直接复用，无需新增配置项。

配置（`MapGenerationConfigSO`）中的 `minHeight`、`maxHeight`、`seaLevel` 仍控制实际高度数值范围，颜色图只决定每个格子归到哪个区间。

---

## 整体流程

```
策划绘制的颜色图（软边缘，分辨率可不等于地图尺寸）
       │
       ▼
对每个六角格坐标 (x, z) 采样 GetPixelBilinear(coord)
       │
       ▼
像素颜色 → RGB 欧氏距离 → 判定归属颜色（蓝/绿/橙）
       │
       ▼
纯色区域 → 在对应高度区间内加局部 Perlin 扰动
跨色过渡区 → 颜色本身就是渐变，用颜色权重对三个高度区间做加权 lerp
       │
       ▼
int[,] 高度数组 → 可选通过 OptimizeTerrain（多数投票消除碎块）
       │
       ▼
进入现有管道（HexCellData → MeshDataGenerator → 渲染）
```

---

## 关键设计决定

### 1. 图片分辨率

不强制与地图格子数一致。策划可绘制任意分辨率的颜色图，采样时对每个六角格坐标走 `GetPixelBilinear(u, v)`。

**关键修正**：六角格地图每行有半格水平偏移（offset），不是正交网格。为保证图片与地图的空间对应关系直观，**UV 应使用世界坐标归一化**而非行列索引：

```csharp
// 错误示范：直接用行列索引会导致图片竖直线在地图里变锯齿
u = x / xNumber;  // ❌
v = z / zNumber;

// 正确做法：用世界坐标归一化，自动考虑偏移
float worldX = hexCellData.CenterWorldCoordinate.x;
float worldZ = hexCellData.CenterWorldCoordinate.z;
// 归一化到 [0, 1]：找到世界坐标的 min/max 边界，按比例缩放
u = (worldX - minWorldX) / (maxWorldX - minWorldX);
v = (worldZ - minWorldZ) / (maxWorldZ - minWorldZ);
```

地图边界可在生成前遍历一次 `centerWorldCoordinates` 取得，或直接用六角格公式推导。

- 低分辨率图（10×10 → 20×30 地图）：每个像素覆盖约 6 个格子，适合大区域划分
- 高分辨率图（200×300 → 20×30 地图）：软画笔渐变过渡更细腻，像素级平滑自然充当了过渡区
- 最佳实践：比地图格子尺寸大 2~5 倍，让软画笔有足够像素来显示渐变，又不至于图片太大难以编辑

### 2. 颜色识别

RGB 欧氏距离分类：

```
dist = |R - R_ref|² + |G - G_ref|² + |B - B_ref|²
归类为距离最近的参考色
```

| 参考色 | RGB |
|--------|-----|
| 蓝色 | (0, 0, 255) |
| 绿色 | (0, 255, 0) |
| 橙色 | (255, 140, 0) |

- 三者在 RGB 空间中呈三角形分布，距离足够远，分类准确率高
- 无需灰度介入，避免了灰色与过渡色混淆的问题

### 3. 软边缘处理（核心差异化）

策划用软画笔（如 Photoshop 软笔刷）绘制颜色区域，边界处自然出现渐变像素。

对于边界像素，**使用反距离加权（IDW）混合**：

```
dist_i = sqrt((R-R_ref_i)² + (G-G_ref_i)² + (B-B_ref_i)²)
weight_i = 1 / (dist_i + epsilon)  // epsilon=0.001 防止除零
归一化：weight_i = weight_i / sum(weight_j)
```

三个参考色各自得到权重后，对三个高度区间的**中值**做加权插值：

```
水域中值 = (0 + seaLevel) / 2
平地中值 = (seaLevel + midPoint) / 2
高地中值 = (midPoint + maxHeight) / 2

最终高度 = weight_蓝 × 水域中值 + weight_绿 × 平地中值 + weight_橙 × 高地中值
```

**为什么选 IDW 而非 barycentric**：
- IDW 对任意颜色都输出正权重，策划意外用错颜色不会产生负权重崩溃
- 地形过渡本来就需要偏软的平滑效果，IDW 的"远近渐变"特性正好契合
- 实现简单，鲁棒性高

示例：像素 RGB = (0, 128, 128)（蓝绿色），距离蓝色、绿色较近，橙色很远 → 高度 ≈ lerp(水域中值, 平地中值, 权重比例)。

### 4. 区间内随机

纯色区域中的每个格子，在对应高度区间内加局部 Perlin 噪声扰动，避免同一颜色区域内所有格子高度相同。

**扰动公式**：

```csharp
float baseHeight = 从颜色映射或权重插值得到的基础高度;
float noise = Mathf.PerlinNoise(x * noiseFreq + seed, z * noiseFreq + seed) * 2 - 1;  // [-1, 1]
float finalHeight = baseHeight + noise * noiseAmplitude;

// Clamp 到对应区间
if (bucket == 0) finalHeight = Mathf.Clamp(finalHeight, minHeight, seaLevel);
else if (bucket == 1) finalHeight = Mathf.Clamp(finalHeight, seaLevel + 0.01f, midPoint - 0.01f);
else finalHeight = Mathf.Clamp(finalHeight, midPoint, maxHeight);
```

**参数化配置**（新增到 `MapGenerationConfigSO`）：

```csharp
[Header("颜色图扰动")]
[Tooltip("区间内高度随机扰动振幅（整数级差单位），0=无扰动")]
[Range(0f, 2f)] public float heightNoiseAmplitude = 0.5f;

[Tooltip("扰动噪声频率，越小越连贯，越大越碎")]
[Range(0.01f, 0.5f)] public float heightNoiseFrequency = 0.1f;
```

**Seed 对接**：扰动噪声使用 `SeedService.GetRandom("Terrain")` 生成的 offset，保证同 seed 同颜色图生成完全相同的地形（可复现）。

不需要直方图均衡（颜色图本身已经决定了每种高度的面积比例），只需要小振幅的局部噪声即可。

## 对比现有流程

| 环节 | 现有（纯随机） | 新方案（颜色图） |
|------|--------------|----------------|
| 宏观地形 | Perlin 噪声全局控制 | 策划绘制的颜色分区控制 |
| 面积配比 | 直方图均衡强制均分 | 策划画笔面积决定 |
| 微扰动 | 八度噪声叠加 | 同，但振幅更小、clamp 到区间内 |
| 平滑优化 | 多数投票消除碎块 | 可选保留，但颜色图本身已无碎块问题 |
| 河流生成 | 自动判断落差 | 不变，仍按高度差检查流向 |

---

## 对下游系统的影响（无）

- `HexCellData.Height` 仍是 `float`，源来自颜色图还是算噪声，下游不感知
- 过渡面片（step/slope）按高度差自动生成，不受影响
- 战斗高地加成、材质分桶、水域判定均只依赖 Height 值，不关心来源
- 河流仍按 `CheckHeight()` 判断流向

唯一需要策划注意的：水域应连片、位于低洼或边缘，否则河流无法正常汇入。

## 推荐落地顺序

1. **纹理导入设置验证**：准备一张测试颜色图，在 Unity 导入设置中确保：
   - Read/Write Enabled：✔ 开启
   - Compression：None（RGBA 32bit）
   - Generate Mip Maps：✘ 关闭
   - Filter Mode：Bilinear
   - 防止 DXT/ETC 压缩导致颜色失真，影响欧氏距离分类准确性

2. **配置参数扩展**（`MapGenerationConfigSO`）：
   ```csharp
   [Header("颜色图高度控制")]
   [Tooltip("可选：颜色图纹理（蓝=水域、绿=平地、橙=高地），不设置则走随机生成")]
   public Texture2D heightPaletteMap;
   
   [Tooltip("区间内高度随机扰动振幅（整数级差单位），0=无扰动")]
   [Range(0f, 2f)] public float heightNoiseAmplitude = 0.5f;
   
   [Tooltip("扰动噪声频率，越小越连贯，越大越碎")]
   [Range(0.01f, 0.5f)] public float heightNoiseFrequency = 0.1f;
   ```

3. **采样逻辑实现**（新增辅助方法到 `TerrainGenerator` 或 `MapGenerator`）：
   ```
   GetHeightFromPaletteMap(Texture2D tex, int xNumber, int zNumber, 
       Vector3[] centerWorldCoords, System.Random random, 
       float noiseAmp, float noiseFreq) -> int[,]
   {
       计算世界坐标边界 → 
       对每个格子 → 归一化UV → GetPixelBilinear → 
       欧氏距离分类 → IDW权重插值 → 
       加Perlin扰动 → Clamp到区间 → 
       float转int（Round）
   }
   ```

4. **分支切换**（`MapGenerator.TerrainHeightGeneration`）：
   ```csharp
   int[,] arrHeight;
   if (_config.heightPaletteMap != null)
       arrHeight = GetHeightFromPaletteMap(...);
   else
       arrHeight = TerrainGenerator.GenerateTerrainHeight(...);  // 现有随机流程
   ```

5. **保留平滑后处理**：`OptimizeTerrain`（多数投票）可选保留，但颜色图方案通常不需要（软边缘已处理过渡）。可加一个配置开关 `bool applyTerrainSmoothing`。

6. **float → int 取整规则**：使用 `Mathf.RoundToInt(finalHeight)`，在边界值（如 seaLevel ± 0.5）时按就近取整，避免系统性偏差。

两套流程用 `heightPaletteMap` 是否为空判断，互不侵入，回溯风险为零。
