# 12. 游戏 UI、开始场景与交互状态审计报告

## 结论

本轮发现并修复了远程攻击双入口竞争、临时高亮破坏其他网格状态、菜单动画期间重复输入、伪功能控件、事件生命周期和开始场景缩放等明显问题。静态复核和 C# 编译通过后，未发现其他明确的阻断性代码缺陷。

## 已修复

### [P1] 同一次右键可被两套远程攻击入口消费

- 技能按钮和全局输入处理器原先各自保存攻击者并监听右键。切换选择或组件执行顺序变化时，同一帧可能让两个单位分别行动，或在攻击后留下旧范围与指示器。
- 现在 `PlayerInputHandler` 是唯一攻击执行入口；技能模式只展示范围，并在选择变化、单位忙碌、阶段切换或组件禁用时清理状态。

### [P2] 临时网格高亮会覆盖全局网格和其他交互状态

- 远程模式原先取消时直接隐藏格子且不恢复材质；卡牌结束拖拽时扫描全图并关闭所有网格。
- 远程模式现在保存并恢复每格进入前的激活状态与颜色；卡牌拖拽只恢复自己实际修改的一格，不再影响 `G` 键网格状态。

### [P2] 单位信息面板每帧重复创建 Tween

- 面板原先在每个 `Update` 中创建 0.5 秒 Tween，快速选择时会持续叠加动画。
- 现在只在可见状态变化时启动一次 Tween，切换前终止旧动画，并把 Tween 与对象生命周期关联。

### [P2] 菜单动画存在 0.1 秒无交互锁窗口

- 一级菜单点击后原先延迟开启遮罩，快速点击可并发修改共享动画状态。
- 现在点击入口同步开启遮罩，动画窗口内后续点击不会再进入菜单逻辑。

### [P2] 可见菜单与设置控件伪装为已实现功能

- 开始菜单只实现了开始游戏和选项，却把多人、教程、地图等入口显示为可点击；退出桌面也没有行为。设置和按键绑定控件可编辑，但没有应用或持久化路径。
- 现在只开放单人模式、游戏选项、开始游戏和退出桌面；其他入口明确禁用。退出命令已接入 `Application.Quit`。设置页保留内容展示，但所有未接入配置系统的控件不可编辑。

### [P2] Presenter 事件未成对退订

- `UIManagerPresenter` 订阅科技、文化和单位移除事件后没有释放契约。
- 现在实现 `IDisposable` 并对称退订，场景容器销毁后不会继续持有旧视图。

### [P2] 开始场景固定像素缩放导致窄屏裁切

- `CanvasScaler` 原先使用 `Constant Pixel Size`，固定尺寸菜单在较小窗口中会超出视口。
- 现在改为 `Scale With Screen Size`，参考分辨率为 1920x1080，宽高匹配值为 0.5。

## 已核对

- 当前 GameScene 中 `UnitInfoPanel` 的四个固定子节点满足 `UIManager` 的层级契约；开始菜单当前配置也满足 8 个一级按钮和至少 5 个次级按钮。菜单接线已增加数量校验。
- 进入游戏使用静态加载锁防重复点击，返回选项页和返回主菜单均有重复实例保护。
- 卡牌拖拽在非玩家阶段、阶段中途切换和应用失焦时会取消并回到原位。

## 验证

- `dotnet build MainGame.csproj --no-restore`：成功，0 error；保留现有 Zenject 字段静态告警。
- `git diff --check`：通过，仅输出仓库既有的行尾转换提示。
- 仍需在 Unity PlayMode 手工验证：远程技能后切换单位、网格开启时拖卡、菜单快速连点、返回菜单后二次开局，以及 1920x1080、1366x768、1280x800、1024x768 和窄屏布局。
