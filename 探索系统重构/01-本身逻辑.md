## 2. 探索的含义

探索不是"获得视觉情报"，而是**一个复合动作**：花费资源探索地块 = 占领该地块（圈入势力范围）+ 收割该地块资源。

> **新模式下没有"建城"这个概念。** 势力范围不再由建城产生，主要由探索直接产生；另一来源为占领公共建筑（见 `06-公共建筑与探索系统对接.md`）。

即"探索"一次性完成以下三件事：

1. 将地块标记为已探索（`IsExplored = true`）
2. **将该地块圈入玩家势力范围**（占领）
3. **收割该地块上的资源**（资源系统后续需重构）

| 行为 | 未探索格 | 已探索格 |
|---|:---:|:---:|
| 查看地形/资源/单位/建筑 | ✓ 允许 | ✓ 允许 |
| 悬停查看格信息 | ✓ 允许 | ✓ 允许 |
| 移动进入 | ✓ 允许（方案C：不限制） | ✓ 允许 |
| 部署单位/建筑 | ✗ 禁止（需在势力范围内） | ✓ 允许（需在势力范围内） |
| ~~建城~~ | — 概念已移除 | — 概念已移除 |
| 圈入势力范围（占领） | — | ✓ 探索时自动完成 |
| 收割资源 | — | ✓ 探索时自动完成 |
| 攻击其中单位 | ✓ 允许 | ✓ 允许 |

> ⚠️ 注意：部署检查的是**势力范围归属**（`territoryService.IsInPlayerTerritory`），不是 `IsExplored`。玩家探索的地块自动占领，因此已探索格通常也在势力范围内，但这是两个独立概念。

## 3. 探索合法性规则

### 基本规则（推荐）

- 目标格必须是未探索格。
- 目标格必须与至少一个已探索格相邻（只能从已探索边界向外扩张）。
- 水域格是否允许探索待确认。

### 规则接口

```csharp
public interface IExplorationRule
{
    bool IsValid(HexCellData cell, HexCellData[] allCells);
    string GetInvalidReason(HexCellData cell);
}
```

第一版实现仅检查"未探索 + 邻接已探索格"，不需要复杂策略。

## 6. 探索服务

```csharp
public interface IExplorationService
{
    ExploreResult CanExplore(HexCellData cell);
    ExploreResult TryExplore(HexCellData cell);
    event Action<HexCellData> CellExplored;
}
```

```csharp
public enum ExploreResult
{
    Success,
    AlreadyExplored,
    NotAdjacent,         // 不邻接已探索格
    InsufficientFunds,
    InvalidTarget,       // 水域等规则禁止的目标
}
```

### 内部事务流程

探索是一次性完成**标记 + 占领 + 收割**的复合动作：

```
TryExplore(cell)
  → CanExplore(cell) → 不合法则返回原因
  → costProvider.GetCost(cell)
  → wallet.CanAfford(cost) → 不足则返回 InsufficientFunds
  → wallet.TrySpend(cost)
  → cell.SetExplored()                  ← 只在服务内部调用
  → territoryService.Claim(cell)        ← 将地块圈入玩家势力范围
  → resourceService.Harvest(cell)       ← 收割该地块资源（资源系统重构后完善）
  → CellExplored?.Invoke(cell)          ← 通知探索标记层等订阅者
  → return Success
```

原子性：`TrySpend` 失败时不改变探索状态；中途失败时调用 `wallet.Refund(cost)`。

> ⚠️ `territoryService` 和 `resourceService` 当前对应的系统（势力范围、资源）仍需重构，此处先以接口占位，不直接调用旧的 `SphereOfInfluenceRenderer` 或建城逻辑。

## 7. 通行性规则与探索的解耦（方案C：不限制移动）

> **注**：当前项目是实时制，`movementCost` 不是"花费行动点"，而是寻路算法的**权重**（森林权重高，寻路倾向于绕过）。单位实际移动速度由 `UnitData.MovementPoints` 决定，不受地形减速。

**已确认：探索不限制移动（方案C）。** 未探索格完全自由通行，探索只提供占领 + 收割。

**现状问题**：`ExploreThisHexCell()` 把 `movementCost` 从 `float.MaxValue` 恢复为地形权重（1或2）。即未探索格当前通过 `movementCost = MaxValue` 隐式阻挡寻路——这与方案C冲突，必须解除。

### 解耦方案

未探索格不应影响寻路，`movementCost` 只反映地形本身：

```csharp
// HexCellData.cs 构造时
// 删除：未探索 → movementCost = float.MaxValue
// 改为：地形权重按实际地形直接计算，与探索状态无关
//   普通格 = 1
//   森林   = 2
//   水域   = float.MaxValue（固有不可通行，与探索无关）
//   雕像格 = float.MaxValue（建筑占位，与探索无关）
```

- **删除** `ExploreThisHexCell()` 中对 `movementCost` 的所有修改。
- 探索后**不需要**重算权重——权重从一开始就按地形正确设置。
- 寻路入口**不需要**探索检查——未探索格和已探索格对移动完全一致。

### 方案C的好处

- 消除"删自动探索导致寻路停滞"的风险（不再有隐式封锁）。
- `UnitMovementSystem` 完全不需要改动寻路逻辑。
- 探索与移动彻底解耦，职责清晰。

> 保留的不可通行地形（水域、雕像）与探索无关，这些 `movementCost = MaxValue` 写入点保持不动。

## 8. 开局初始化

### 推荐方案

玩家开局有**一个主城**（唯一）。开局布局：

1. **主城本身**：占 1 格。
2. **主城固有势力范围**：主城周围一环（6 格），开局即属于玩家势力范围，无需探索。
3. **赠送 1 次免费探索**：玩家开局获得一次免费探索机会，目标为势力范围的相邻地块（即第二环的某一格）。玩家自行选择探索方向。

```csharp
// GameFlowManager.cs
// 1. 生成主城（占 1 格）
_cityService.SpawnMainCity(startCell);

// 2. 主城周围一环圈入固有势力范围（不算探索，直接占领）
_territoryService.ClaimRing(startCell, radius: 1);

// 3. 赠送 1 次免费探索额度（玩家点击选择目标）
_explorationService.GrantFreeExplore(count: 1);
```

- 主城周围一环（6 格）为玩家初始部署空间（主城本身占位，不可叠加部署单位/建筑）。
- 免费探索让玩家可以主动选择第一个扩张方向，探索后该地块被占领并收割资源。
- 免费探索使用与付费探索相同的流程，只是跳过资源扣费。

### 免费探索额度

`ExplorationService` 维护一个免费探索计数：

```csharp
TryExplore(cell):
  → CanExplore(cell) 校验合法性
  → 若有免费额度 → 消耗额度，跳过 wallet.TrySpend
  → 否则 → 正常扣费
```

> ⚠️ AI 同样拥有主城 + 一环固有势力范围 + 1 次免费探索，开局初始化逻辑一致。
