## 2. 移动系统（方案C：探索不限制移动）

### 当前问题

`UnitMovementSystem.cs:661, 669`：寻路算法读取 `cell.movementCost` 作为权重。  
未探索格当前通过 `movementCost = float.MaxValue` 隐式阻挡寻路——这与已确认的方案C（探索不限制移动）冲突。

### 修改方案

**方案C已确认：探索不限制移动。** 未探索格与已探索格对寻路完全一致。

只需让 `HexCellData` 构造时地形权重按实际地形计算，不受探索状态影响：

```csharp
// HexCellData.cs 构造函数
// 删除：未探索 → movementCost = float.MaxValue
// 改为：直接按地形设置（普通1、森林2、水域MaxValue）
```

- **删除** `ExploreThisHexCell()` 中对 `movementCost` 的所有修改。
- `UnitMovementSystem` **不需要修改**——寻路逻辑保持原样，未探索格权重正常参与寻路。

保留的不可通行地形（水域 `IsWater`、雕像 `IsStatue`）由地形本身决定，与探索无关。

> ⚠️ 这大幅简化了阶段2的工作量，也消除了"删自动探索导致寻路停滞"的风险。

## 4. 主城与建新城功能移除

> **新模式：玩家开局有一个主城，不能建新城。势力范围只能通过探索拓展。**

### 核心规则确认

| 项 | 规则 |
|---|---|
| 主城 | 开局存在，唯一，提供初始势力范围 |
| 建新城 | 功能移除（UIController/PlayerUnitBrain 的建城入口删除） |
| 势力范围拓展方式 | 探索（主要）+ 占领公共建筑（次要，强制覆盖） |
| 部署规则 | 只能在己方势力范围内部署单位/建筑 |

### UIController 路径

`UIController.cs:261-337`：建城逻辑。  
**移除建城入口**（建城按钮、`FoundCity` 调用及后续探索）。

### PlayerUnitBrain 路径

`PlayerUnitBrain.cs:123-178`：AI 自动建城。  
**移除自动建城逻辑**（`TryFoundCity`）。AI 的势力扩张改为通过探索（见 §7 AI 探索行为）。

### 主城生成与初始势力范围

`GameFlowManager` 开局流程保留主城生成，但初始势力范围由两部分构成：

1. **主城固有势力范围**：主城位置及周围 N 格（产品待定半径）
2. **初始免费探索区域**：起始格及相邻一圈免费探索并占领（见 `01-本身逻辑.md §8`）

两者可以重叠。主城势力范围为玩家提供初始部署空间。

### 势力范围来源迁移

| 项 | 旧模式 | 新模式 |
|---|---|---|
| 势力范围产生方式 | 建城 → 城市周围圈地 | 主城固有范围 + 探索地块占领 |
| 势力范围数据源 | 多城市的固定圈集合 | 主城固有范围 + 已占领地块集合 |
| 建新城 | 允许 | **禁止** |
| 建筑拓展势力范围 | 可能存在 | 普通建筑**禁止**；公共建筑占领后自动扩张（另见 §12） |

> ⚠️ 主城仍是数据锚点（如 `PlayerModelManager.SingleCity_SphereOfInfluence_HexC_HexCellData`），但其势力范围数据源改为"固有范围 + 探索占领集合"。排查并迁移城市半径圈逻辑。

## 7. AI 探索行为（与玩家一致）

`AIFogService.cs`：AI 的独立战争迷雾服务，当前在 `AIUnitBrain.cs` 中被使用。

**需删除。** AI 与玩家行为一致的原则：

- AI 也看到完整地图（无独立战争迷雾）。
- AI 也需要通过探索来解锁未探索格的操作权。
- AI 的探索方式：自动对邻接已探索区域的未探索格进行探索（不需要玩家那样的手动操作 UI），但同样需消耗资源（占位阶段免费）。
- 删除 `AIFogService` 后，`AIUnitBrain.cs` 中对 `_aiFogService.IsExplored(aiIndex, cell)` 的查询改为读取 `cell.IsExplored`（即全局统一的探索状态）。

> ⚠️ AI 也需要消耗资源来探索。在占位资源阶段免费通行；正式经济系统上线后，AI 应有独立的资源收入与支出逻辑（另行设计）。

## 10. 事件系统

### 当前问题

`MapVisualEventSO.Raise()` 是一个"万能刷新"事件，以下所有情况都触发它：
- 单位移动
- 建筑变化
- 势力变化
- 探索变化

导致单位走一步就全量刷新顶点色、FogMask、SyncCellObjectVisibility 等。

### 短期方案

探索重构期间继续复用 `MapVisualEventSO.Raise()`，但 `IExplorationService.CellExplored` 事件单独新建：

```csharp
event Action<HexCellData> CellExplored;
```

供探索视觉刷新订阅。方案三的视觉区分由 Shader 自动处理（去饱和+薄雾在 `FogBlend_final` 中完成），因此 CellExplored 事件的订阅方主要是 `MapRenderer`（更新 FogMask 纹理 R 通道），Shader 自动生效。

### 长期方案（完成重构后）

考虑拆分为：
```
ExplorationChanged(cell)
TerritoryChanged(owner)
EntitySpawned/Removed
MapGeometryChanged
```

暂不强制要求，在迁移阶段 6 后再评估。

## 11. 与 HexCellData 的接口约定

重构后，外部模块对探索状态的读写约定：

| 操作 | 允许路径 |
|---|---|
| 读取 `IsExplored` | 任意模块均可读 |
| 写入（探索）| 只允许 `IExplorationService` |
| 开局初始化 | `GameFlowManager` → `ExplorationService.InitializeStartArea()` |
| 直接调用 `ExploreThisHexCell()` | **禁止**，接口变为 internal 或删除 |
