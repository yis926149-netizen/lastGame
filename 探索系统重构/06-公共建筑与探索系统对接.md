# 探索系统重构 · 06 公共建筑与探索系统对接

> 本文件只讨论**公共建筑系统**与**探索重构**的交互点。公共建筑本身的完整设计见根目录 `公共建筑系统设计讨论.md`。

---

## 1. 为什么要单独一篇

公共建筑是**独立于探索的第二条势力范围来源**：

| 势力范围来源 | 触发方式 | 范围 |
|---|---|---|
| 探索地块 | 花费资源探索相邻格 | 该格本身 |
| 占领公共建筑 | 击破其血量 | 建筑4格 + 各占位格外一环，**强制覆盖**原归属 |

这推翻了重构早期"探索是唯一势力范围拓展方式"的假设，因此需要在探索文档中明确对接。

---

## 2. 关键冲突点：两态迷雾假设已失效

公共建筑设计文档基于**旧的两态迷雾**做了几个决策，探索重构后这些前提已改变，需要对应调整：

| 公共建筑决策# | 原假设（两态迷雾） | 探索重构后 |
|---|---|---|
| #10 可见性 | 需单位走近才发现，随所在格 `IsExplored` 显隐 | **公共建筑始终可见**（地图全可见，无视觉遮挡） |
| #39 可见性（两态） | 随 `IsExplored` 显隐，无记忆区，归属颜色仅可见时展示 | **始终显示模型和归属颜色**（含中立态白/灰色） |
| #25 战争迷雾 | `FieldOfViewService`/`AIFogService` 跳过公共建筑视野 | 两个服务都将删除，此决策自然失效 |

### 处理

- 公共建筑及其血条、归属颜色**始终显示**，不再随 `IsExplored` 显隐。
- 这与 `03-视觉表现.md §2` 的"所有对象始终可见"一致——公共建筑属于建筑类，应纳入 `SyncCellObjectVisibility` 的清理范围。
- 决策 #10、#39、#25 在公共建筑落地时按此更新。

## 3. 势力范围数据源合并

探索重构把势力范围数据源从"城市中心圈"改为"己方已占领地块集合"（见 `02-§4`）。公共建筑占领后的势力范围要合并进同一个集合。

### 统一数据模型

```
玩家势力范围 = 主城一环固有范围
             ∪ 探索占领的地块集合
             ∪ 公共建筑占领带来的地块（强制覆盖）
```

- 三者都写入同一个"已占领地块集合"（按归属 PlayerIndex 区分）。
- `SphereOfInfluenceRenderer` 渲染此统一集合，不再区分来源。
- 公共建筑决策 #7/#8/#20/#33（占位格外扩一环、复用 SphereOfInfluence 逻辑、强制覆盖、HashSet 去重）与此模型兼容，直接沿用。

### 强制覆盖的处理顺序

公共建筑易主时（决策 #20/#32）强制划归新主人的地块，可能与探索占领的地块重叠。约定：

- **公共建筑占领优先级最高**：其4格 + 外一环无条件归占领方，覆盖探索占领记录。
- 若某格原是玩家探索占领、后被 AI 通过公共建筑强夺，则该格归属改为 AI，玩家失去该格。
- 反之亦然。

## 4. 探索邻接规则与公共建筑飞地

`04-A3` 确认"只能探索相邻己方势力范围的格子"，`04-H4` 确认势力范围**可以不连通**（飞地合法）。

公共建筑正是产生飞地的主要方式：

```
玩家占领一个远处的公共建筑
  → 获得该建筑周围的势力范围（与主城不连通的飞地）
  → 玩家现在可以从这块飞地的边界继续探索扩张
```

### 对探索合法性的影响

`IExplorationRule.IsValid(cell)` 判断"是否邻接己方势力范围"时，**必须包含公共建筑飞地**：

```csharp
// 邻接判断遍历所有己方已占领格，含公共建筑带来的飞地
bool IsAdjacentToOwnTerritory(HexCellData cell)
{
    foreach (var neighbor in GetNeighbors(cell))
        if (territoryService.IsInPlayerTerritory(neighbor))
            return true;  // 飞地边界也算
    return false;
}
```

## 5. AI 对称性

`04-E3/H5` 确认 AI 与玩家完全对称。公共建筑争夺对双方规则一致：

- AI 同样可以击破公共建筑获得势力范围。
- AI 同样可以从公共建筑飞地边界继续探索。
- 公共建筑决策 #12/#36（AI 主动争夺、攻击优先级）保持不变。

> 注意：公共建筑本身是**特殊 AI 势力**（决策 #1，占独立 PlayerIndex，不可操作）。它不探索、不扩张，只是被争夺的对象。删除 `AIFogService` 时，其"跳过公共建筑视野"的逻辑（#25）一并移除。

## 6. 公共建筑地块不可探索

公共建筑生成时，其 4 个占位格 **加上每个占位格外一环** 的所有地块，标记为不可探索（见公共建筑决策 #42）。这些地块**只能通过占领公共建筑获得**，玩家无法花费资源主动探索它们。

### 实现要点

- 生成阶段：公共建筑生成后，对 4 格 ∪ 各格外一环 → 对结果集做 HashSet 去重 → 逐个设置 `unexplorable = true`
- `IExplorationRule.IsValid(cell)` 需增加 `unexplorable` 检查，返回 `false`
- 公共建筑易主时，`OnCaptured()` 仅写入势力范围（决策 #32），但 `unexplorable` 标记不应清除——地块本身仍不可通过探索获取
- 探索 UI 应对这些地块显示"不可探索"提示（不同于"太远"或"资源不足"）

### 数据字段

`HexCellData` 新增字段：

```
bool isUnexplorable;  // 不可探索（公共建筑覆盖区域用）
```

> 注：`unexplorable` 是**永久标记**，不会因易主而变化。即使建筑被摧毁（后续扩展），该标记也应保留。

## 7. 落地检查清单

公共建筑系统实装时，需与探索重构对齐的点：

- [ ] 公共建筑始终可见（不随 `IsExplored` 显隐），纳入 `SyncCellObjectVisibility` 清理
- [ ] 归属颜色（含中立白/灰）始终显示
- [ ] 公共建筑占领的势力范围写入统一"已占领地块集合"
- [ ] 强制覆盖时正确更新地块归属（覆盖探索占领记录）
- [ ] 探索邻接判断包含公共建筑飞地边界
- [ ] 删除 `AIFogService` 时移除其对公共建筑的特殊跳过逻辑
- [ ] 公共建筑决策 #10/#25/#39 按"全可见"更新
- [ ] 公共建筑 4 格 + 外一环标记为 `isUnexplorable`，`IExplorationRule.IsValid` 中拦截

## 8. 与公共建筑设计文档的关系

- 公共建筑的**完整设计**（血量、多格、易主、生成、GameLoop 接入等）以 `公共建筑系统设计讨论.md` 为准。
- 本文件只覆盖**探索重构带来的调整**，主要是可见性假设和势力范围数据源合并。
- 两个系统若有冲突，可见性以本文件为准（全可见），其余以公共建筑文档为准。
