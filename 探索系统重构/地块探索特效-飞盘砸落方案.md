# 地块探索特效 —— 飞盘砸落方案（方案二）

## 效果目标

与方案一（石柱升起）不同的视觉叙事：一枚扁平的六边形石盘从**地下弹出后向空中抛起**，
到达顶点后加速下坠，砸入地块表面，撞击瞬间爆发出**势力范围扩散环**和**奖励特效**（金币粒子、单位生成）。

> **已确定的四个设计答案（2026-07-27）**：
> 1. **盘体出现方式**：从地下弹出后继续飞高（与方案一的"出土"延续）
> 2. **光环终态**：纯视觉近似，不与领土边界精确对齐
> 3. **旋转方式**：绕水平轴翻腾，类似抛硬币
> 4. **Pool 重命名影响**：`ExplorationPillarPool` 在 `GameInstaller.cs` 中仅用 `GetComponentsInChildren` 遍历，无 Zenject `Container.Bind()` 绑定，重命名风险为零

> **重要：此方案与方案一（石柱升起）共存，不覆盖。**
> 通过 `ExplorationEffectManager`（原 `ExplorationPillarPool`）上的 Inspector 枚举下拉框
> `EffectStyle` 在 `PillarRise` / `DiskSmash` 之间切换，运行时根据选中值加载对应 Prefab 和播放逻辑。

## 方案对比：柱体升起 vs. 飞盘砸落

| | 方案一（石柱升起） | 方案二（飞盘砸落） |
|---|---|---|
| **主体** | 高柱体 (H=3.5)，从地下弹出 | 扁平六边形盘 (H≈0.15~0.3)，向上抛 |
| **运动** | Y 轴线性上升 + OutBack 弹跳 | 抛物线：上抛 → 下坠 → 撞击 |
| **视觉高潮** | 顶部溶解消散 | 撞击瞬间爆发 |
| **叙事感** | "地表破开、露出秘密" | "砸出领地、震出奖励" |
| **回调时机** | 溶解进度 30% 时触发领土 | **撞击瞬间**触发领土 + 奖励 |
| **动画总时长** | ~3.5s（1.0 + 0.5 + 2.0） | **~1.0s**（节奏更紧凑） |
| **文件** | ExplorationPillarMesh.cs / Effect.cs / .shader | ExplorationDiskMesh.cs / Effect.cs / .shader（新建） |

## 一、盘体 Mesh 设计

盘体是**扁平六边形**，不再是高柱体。

### 方案 A：实心盘（推荐首选）

- 顶面正六边形 + 底面正六边形 + 侧面（厚度 0.15~0.3）
- 类似一枚巨大的六边形硬币/石板
- Pivot 在底面中心，方便定位
- **盘体出现方式**：撞击完成后立即从地面以下弹出（类似方案一的前半段），
  然后继续飞高进入抛物线顶点。即：地下升起（0.05s）→ 继续上抛至顶点（0.15s）→ 滞空（0.05s）→ 下坠撞击（0.15s）。
  这个"先出土后升空"的设计让盘体像从地底发射出的信物，与方案一的"出土"视觉有延续性。
- 外径：2.1（= OuterRadius × SolidAreaRatio），贴合格子实心边界
- 朝向：Pointy-top，第一个顶点对齐 +Z，与地图格子完全一致

**代码来源**：直接复用 `ExplorationPillarMesh.cs` 的生成逻辑，只需将 `_height` 参数从 3.5 降为 0.2。
因此 `ExplorationDiskMesh.cs` 几乎就是 PillarMesh 的复制，仅默认高度不同，顶部边缘可加倒角（侧面顶点稍内缩）。

### 方案 B：六边形环/框架（后续升级）

- 只有六条边的边框，中间镂空
- 撞击时效果穿过镂空中心爆发，更科幻/魔法感
- Mesh 需要内外两层六边形做环形 strip，UV 沿环展开
- 可等方案 A 实现后再升级

**建议**：先用方案 A，后续可选升级为方案 B。

## 二、抛物线轨迹（上抛 + 下坠）

运动分四段：

```
阶段         时间(s)     Y(t) 描述
───────────────────────────────────────────────────
地下         0.00        y₀ - h_under              盘体在地底（与方案一"出土"一致）
弹出         0.00~0.05   y₀ - h_under → y₀        从地下弹出到地面（OutBack 缓动）
上抛         0.05~0.20   y₀ → y₀ + h_peak          继续飞高，进入抛物线上升段
滞空顶点    ~0.20        y₀ + h_peak                极短悬停（曲线峰值）
下坠         0.20~0.35   y₀ + h_peak → y₀         加速砸落（水平轴翻转，快于上抛）
撞击         0.35        y₀                         碰撞 + 特效爆发
```

### 轨迹计算方式选型

| 方式 | 优点 | 缺点 |
|---|---|---|
| **AnimationCurve × 2**（上抛 + 下坠各一条） | 独立调节上升和下落缓动 | 两段拼接不自然 |
| **物理公式** `y = -½gt² + v₀t + y₀` | 自然抛物线，自动 EaseIn/Out | 参数不如曲线直观 |
| **AnimationCurve × 1**（推荐） | 一条曲线搞定全程，Inspector 拖拽直观 | 曲线形状需手动调出先高后低 |

**推荐**：单条 `AnimationCurve` 控制归一化高度，曲线形状设计为（注意曲线始末 h 均为负值，表示盘体起点/终点在地面以下）：

```
Height(normalized)
1.0 │           ╱╲
    │          ╱  ╲
0.5 │         ╱    ╲
    │        ╱      ╲
0.0 │───────╱────────╲─── Time
    │      ╱          ╲
-0.3│─────╱────────────╲──── (terrain surface = 0)
    0  0.07  0.2  0.35  0.4
```

曲线特点：
- `t=0` 时 h = -0.3（盘体在地下 `-0.3 × throwHeight` 处）
- `t≈0.07`（~7%）时 h = 0（盘体刚弹到地面，对应"出土"）
- `t≈0.28`（~28%）时 h = 1.0（盘体到达最高点）
- `t≈0.5`（~50%）时 h 回落到 0（撞击地面）
- `t>0.5` 时 h 继续向下进入负值（嵌入地面，scaleY 同步缩减到 0）

代码思路：
```csharp
// startPos = cellY（地面高度，即 HexCellData.RealCenterWorldCoordinate.y）
// peakPos  = cellY + throwHeight（建议 2.0~3.0 世界单位）
float h = _trajectoryCurve.Evaluate(t / totalFlyTime); // 曲线值: 0→1→0
// h=0 时盘在地面，h=1 时在最高点，h 再次=0 表示撞击
transform.position = new Vector3(cellX, Mathf.Lerp(cellY, cellY + throwHeight, h), cellZ);
```

> 因为 `Mathf.Lerp(a, b, 0) = a`, `Mathf.Lerp(a, b, 1) = b`, `Mathf.Lerp(a, b, 0) = a`，
> 所以 `h` 先去 1 再回 0 天然实现抛物线。

### 翻转方式：抛硬币式翻转

飞盘在空中的旋转方式：**绕水平轴（X 轴或 Z 轴）翻转，类似抛硬币**。

- **具体运动**：盘体从地上弹出后，在空中绕 X 轴向前翻转（像硬币被抛起后在空中翻腾），下坠段继续保持翻转，撞击瞬间骤停
- **视觉效果**：比绕 Y 轴自旋更有"被抛出"的物理感，侧视和俯视角度都能明显观察到
- **实现**：Coroutine 中 `transform.Rotate(Vector3.right, flipSpeed * Time.deltaTime)`，结合抛物线高度变化，翻速在上升段慢（显得轻）、下坠段快（显得重）
- **翻转圈数**：建议 1.5~2 圈完整翻腾，撞击瞬间停在正面朝上的姿态

## 三、撞击时刻设计（核心高潮）

这是新方案与方案一最大的区别。方案一高潮在"溶解"，方案二高潮在"撞击"。

### 撞击瞬间效果清单

| 效果 | 实现方式 | 说明 |
|---|---|---|
| **盘体撞击反馈** | Y 略微下压 + 快速嵌入（0.1s 内 scale Y→0） | 物理感 |
| **屏幕震动** | Camera 父节点短促偏移（0.05~0.1s） | 强烈打击感 |
| **尘土粒子爆发** | `ParticleSystem`，环形 burst，沿地面扩散 | 碎片/尘埃 |
| **势力范围扩散环** | 见第四节 | 核心可视化 |
| **金币粒子弹出** | 见第五节 | 奖励反馈 |
| **单位生成特效** | 见第五节 | 奖励反馈 |

### 回调时机

当前方案一中 `CompleteExploration` 在溶解进度 ≥30% 时触发。新方案中，**撞击瞬间触发**最合理：

- 盘体 Y 第一次回到 `cellY` 的那一帧 → 调用 `CompleteExploration`
- 领土圈入 + 资源收割 + 随机奖励（金币 + 单位）同时发生在撞击时刻
- 这恰好与现有的 `onDissolveStart` 回调机制对应——只需改名为 `onImpact`，触发时机从"溶解 30%"改为"Y 回到地面"

```csharp
// 现有回调机制（方案一）
pillar.Play(cellPos,
    onDissolveStart: () => CompleteExploration(cell),  // 溶解 30%
    onComplete: (effect) => ReturnToPool(effect));

// 新方案的触发时机
disk.Play(cellPos,
    onImpact: () => CompleteExploration(cell),         // 撞击瞬间
    onComplete: (effect) => ReturnToPool(effect));
```

## 四、势力范围扩散环（视觉重点）

"砸出势力范围"的核心可视化：一个**六边形光环**从撞击点向外扩展到影响力边界。

### 技术选型

| 方案 | 实现 | 优点 | 缺点 |
|---|---|---|---|
| **Mesh 缩放（推荐）** | 和盘体一样的六边形 Mesh，初始 scale=盘体大小，逐渐放大到 2~3 倍 | 精度高，可用自定义透明 Shader，与现有 Shader 体系一致 | 是独立对象，需额外管理 |
| **LineRenderer** | 6 条线段组成的六边形环 | 轻量，代码简单 | 无填充；拐角无圆角 |
| **ParticleSystem（环形）** | Shape=Circle，Emit from edge | 自带动画曲线 | 粒子离散感，不够整六边精确 |
| **Projector/Decal** | 地表投影贴花扩散 | 贴合地形 | Built-in RP 下 Projector 性能差；六边形贴花对齐难 |

**推荐：Mesh 缩放方案**，理由：
1. 六边形 mesh 可直接复用盘体生成逻辑，代码零额外成本
2. 配合自定义透明 Shader，边缘发光 + 渐隐（类似现有 dissolve shader 的边缘发光思路）
3. 颜色：撞击时亮白/金色 → 扩散后变淡 → 最终透明消失

### 光环动画参数

- 起始 scale：1.0（盘体大小 / 格子实心边界）
- 结束 scale：约 3.0~4.0 倍，**纯视觉近似，不与领土范围精确对齐**
- 持续时间：0.3~0.5s
- 曲线：EaseOutCubic（先快后慢，有冲击力）
- 叠加：光环扩散同时播放粒子 burst（小光点沿边缘飞散）

> **设计原则**：光环的终态大小仅做视觉上的"势力扩散"感，不需要与 `ITerritoryService.Claim()` 的实际边界
> 严格对应。领土扩展由逻辑层精确控制，光环是氛围装饰。

### 光环材质

光环 mesh 使用独立材质（新建 `ExplorationRing.mat`）：
- Shader：内置 Standard → Rendering Mode = Fade/Transparent
- Albedo 颜色：暖金色或玩家派系色
- Alpha：由 AnimationCurve 控制，从 0.6 线性衰减到 0
- Emission：亮色，营造发光光环感
- 与光环 scale 同步：scale 越大，alpha 越小，形成扩散 + 渐隐效果

> 不需要复杂的 Dissolve Shader——直接用 C# 侧 `material.color` Alpha 控制即可。

## 五、奖励可视化（金币 + 单位）

撞击瞬间同步弹出：

### 金币粒子

- 生成 4~8 个金币粒子，从撞击点以随机水平角度 + 向上力度（30°~60° 仰角）弹射
- 抛物线飞行轨迹（物理或 AnimationCurve 模拟），空中停留 0.5~0.8s 后消失
- 实现：轻量 `ExplorationCoinBurst` prefab，挂 `ParticleSystem`（Shape=Circle, emit from edge），或直接用几个临时金币 sprite GameObject
- 最佳时机：撞击后 0.05~0.1s（比光环稍晚一帧，形成"先是冲击波、后有东西飞出来"的层次感）

### 单位生成

- 单位在目标格子 / 相邻格子上出现，伴随：
  - 一道垂直光柱（Cylinder mesh + 透明发光材质，scale Y 快速从 0 展开到单位高度再缩回 0）
  - 或：单位模型缩放入场（scale 0→1，OutBack 缓动，0.3s）
- **关键**：单位的实际创建由 `ExplorationRewardSystem` 处理（监听 `ExplorationRewardTriggered` 事件），视觉效果只需监听同一事件播放生成特效即可，不修改奖励逻辑

## 六、完整时间轴

```
时间(s)   事件                                          回调
──────────────────────────────────────────────────────────────────
0.00      盘体定位到 cellPos - 地下，准备弹出
0.00~0.05 盘体从地下弹出到地面（OutBack，出土预兆）
0.05      盘体到达地面，继续向上抛
0.05~0.20 盘体上抛阶段，抛硬币式水平翻转
~0.20     盘体到达最高点，极短悬停
0.20~0.35 盘体加速下坠，翻转速度加快
0.35      ★ 撞击瞬间 ★
          ├ 屏幕震动（0.08s）
          ├ 盘体 Y 嵌入地面 (scaleY→0 in 0.1s)
          ├ 尘土粒子环形 burst
          ├ 光环开始扩散                               → onImpact 回调
          ├ 金币粒子弹出                               → CompleteExploration(cell)
          └ 单位生成特效触发                           → 领土 + 收割 + 奖励事件
0.35~0.70 光环扩散到最大，alpha 渐隐至 0
0.50      金币粒子飞至顶点开始下落
0.70~0.90 金币/单位特效完全消失
1.00      盘体回池
```

**总时长约 1 秒**（方案一约 3.5 秒），节奏更紧凑，适合快速连续探索。

## 七、与方案一共存：Inspector 下拉框架构

两种特效方案不互相覆盖，通过枚举 + 工厂模式切换。

### 7.1 枚举定义

```csharp
public enum ExplorationEffectStyle
{
    PillarRise,   // 方案一：六边形石柱从地下升起 → 溶解消散
    DiskSmash     // 方案二：六边形飞盘上抛下坠 → 撞击扩散
}
```

### 7.2 改造 `ExplorationPillarPool` → `ExplorationEffectManager`

原 `ExplorationPillarPool` 重命名为 `ExplorationEffectManager`，增加 Inspector 字段：

```csharp
public class ExplorationEffectManager : MonoBehaviour
{
    [SerializeField] private ExplorationEffectStyle _effectStyle = ExplorationEffectStyle.PillarRise;

    [Header("方案一：石柱升起")]
    [SerializeField] private GameObject _pillarPrefab;

    [Header("方案二：飞盘砸落")]
    [SerializeField] private GameObject _diskPrefab;

    // 内部队列，运行时根据 _effectStyle 选择对应 Prefab
    private Queue<ExplorationPillarEffect> _pillarPool;   // 保留兼容
    private Queue<ExplorationDiskEffect> _diskPool;       // 新增

    private void OnCellExplored(HexCellData cell)
    {
        switch (_effectStyle)
        {
            case ExplorationEffectStyle.PillarRise:
                PlayPillarEffect(cell);
                break;
            case ExplorationEffectStyle.DiskSmash:
                PlayDiskEffect(cell);
                break;
        }
    }
}
```

`_effectStyle` 在 Inspector 中显示为下拉框，切换即可改变运行时特效类型。

### 7.3 为什么不直接用一个抽象基类

方案一二的动画流程差异较大（一个上升+溶解，一个上抛+下坠+撞击+光环），抽象基类的好处有限。
简单 switch + 两套独立 Effect 脚本更清晰，各自修改不受对方影响。

## 八、关键权衡与决策

| 决策点 | 选项 | 推荐 |
|---|---|---|
| 盘体撞击后 | 嵌入地面消失 / 破碎成粒子 / 溶解 | **缩小 Y 嵌入**（实现简单，物理感好） |
| 光环 | Mesh 缩放 / LineRenderer / Particle | **Mesh 缩放**（和现有 Shader 体系一致） |
| 金币 | 3D coin prefab / 粒子 sprite | **轻量粒子 sprite**（低消耗，无需额外模型资产） |
| 单位出现 | 缩放入场 / 光柱现身 / 从光环中走出 | **缩放入场 + 亮闪**（简单有效） |
| 屏幕震动 | Camera 脚本 / Cinemachine | 如果项目已有 Cinemachine → 用 Impulse；否则手动 `parent.position += offset` |
| 两种方案共存方式 | switch + 两套脚本 / 抽象基类 | **switch + 两套独立脚本**（简单，互不干扰） |

## 九、潜在坑点

1. **地形高度**：盘体在下坠阶段，目标 Y 锁定在 `cell.RealCenterWorldCoordinate.y`（不是每帧读取 `transform.position.y`），因为不同格子高度不同。

2. **多格同时探索**：快速连续探索多个格子时，多个盘体可能同时播放。当前 Pool 预热 5 个实例，方案二动画仅 ~1s，5 个足够覆盖绝大多数情况。

3. **光环与斜坡**：光环是水平面上方的六边形环，Y 建议固定在 `cellY + 0.05`（略高于地面），防止嵌入地形。在陡坡上光环可能一边高于地面、一边低于——这是已知但不严重的问题，可暂不处理。

4. **回调唯一性**：确保 `CompleteExploration` 只在撞击瞬间调用一次（不是每帧），用 `_impactCallbackFired` bool 保护。

5. **盘体的 `_PillarBottomY` / `_PillarHeight` Shader 属性**：方案二的盘体不需要 dissolve，需要用不同的 Shader（或至少设置 `_DissolveProgress = 0` 永久保留）。建议为盘体使用独立材质，不绑定 Pillar dissolve shader。

6. **Inspector 下拉框切换后 Pool 预热**：如果运行时切换 `_effectStyle`，需要清空旧 Pool 并预热新类型的实例。建议在 `_effectStyle` 的 setter 中或 `OnValidate` 中处理。

7. **Pool 重命名影响范围确认**：`ExplorationPillarPool` 在 `GameInstaller.cs:255` 中通过 `GetComponentsInChildren<ExplorationPillarPool>()` 搜索并启用，
   未使用 Zenject `Container.Bind()` 绑定。因此重命名为 `ExplorationEffectManager` 后只需更新 `GameInstaller.cs` 那一行，
   不影响任何 Zelject 注入。场景中唯一的 GameObject 名为 "ExplorationPillarPool"，
   重命名后场景中的对象名和脚本名需同步更新。
