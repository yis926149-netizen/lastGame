# 天赋卡牌系统整合方案

> 基于 README、改造方案讨论总结、游戏机制暂缺总览；涵盖 2026-07-24 实时化改造和 07-25~07-26 探索/公共建筑改造后的项目现状。

## 前提：两套系统并存，互不干涉

- **系统一（保留不动）**：现有手牌系统 —— 所有卡牌无条件解锁，实时自动补牌，拖拽部署单位/建筑。
- **系统二（新增）**：天赋卡系统 —— 触发时从 3 张选 1，获得整局永久 Buff。

两者数据、UI、触发、消耗完全独立，唯一交汇点是"都作用于同一批 Unit"。

## 一、架构兼容性分析

| 维度 | card 项目 | 主项目 | 兼容评估 |
|---|---|---|---|
| DI 框架 | Zenject `GameInstaller` | Zenject `Infrastructure/Installers/GameInstaller` | ✅ 绑定风格一致，可直接照搬 |
| Buff 承载 | `BuffManager` 挂在每个 `PlayerCharacterBase`（MonoBehaviour，每帧 Update 计时） | `UnitBrainBase`（MonoBehaviour）+ `IUnitStrategy` 装饰器链，`CharacterData` 是纯 C# POCO；现有 `BuffAggregator`（加算） | ⚠️ card 项目是乘法累积 Buff，主项目 BuffAggregator 是加法聚合。需决定天赋 Buff 用哪种清算方式 |

## 二、核心设计决策

### 决策 1：Buff 承载方式 —— 阵营级而非单位级

**推荐方案**：做注入式的 **`FactionBuffService`**（每个阵营一份实例，通过 Zenject 注入）。

**理由**：
- 天赋卡效果是"整局全阵营生效"，单位不需要各自维护
- 新部署的单位自动享受已有天赋（查询阵营全局值）
- 契合主项目"纯 C# 服务 + DI"的风格，不需要给每个 Unit 额外挂 MonoBehaviour
- 与主项目现有的 `UnitBrainBase` + `IUnitStrategy` 装饰器链不冲突——天赋 Buff 影响数值（乘数/加数），兵种策略装饰器影响行为（狂暴/恐惧），各走各的层

**与主项目现有 BuffAggregator 的关系**：
- 主项目已有 `BuffAggregator.Compute(baseValue, activeBuffs, statType)`，用于单位身上行为类 buff 的加法聚合
- 天赋系统的乘法/加法 Buff 从 `FactionBuffService` 查询，在 CombatResolver / UnitMovementSystem 等结算入口处**先查阵营天赋乘数，再交给 BuffAggregator 做单位级 buff 加算**。两层独立、先乘后加

**接口形态**：
```csharp
public interface IFactionBuffService
{
    float GetStatMultiplier(string statId);   // 累积乘数
    float GetStatAddition(string statId);     // 累积加数
    void AddBuff(Buff buff);
    void RemoveBuff(Buff buff);
}
```

### 决策 2：statId 映射方案（基于当前项目实际属性）

> 科技/文化系统已删除，战争迷雾已删除，以下为可用的 stat 维度。

| 天赋效果方向 | statId | 类型 | 结算位置 | 备注 |
|---|---|---|---|---|
| 全军攻击力 +X% | `damage` | 乘数 | `CombatResolver.Resolve()` | 直接作用于最终伤害 |
| 全军防御力 +X% | `defense` | 乘数 | `CombatResolver.Resolve()` | 降低受到的伤害 |
| 全军受伤减免 X% | `damage_taken` | 乘数 | `CombatResolver.Resolve()` | 与 defense 独立叠算 |
| 全军攻速 +X% | `attack_speed` | 乘数 | `UnitBrainBase` 攻速计时器 | `AttackInterval` 字段 × 乘数 |
| 全军移动速度 +X% | `move_speed` | 乘数 | `UnitMovementSystem.UpdateMovement` | `MovementPoints × 10` × 乘数 |
| 全军攻击距离 +N | `attack_range` | 加数 | `RangedStrategy.CanAttack` 范围扫描 | 仅远程单位有效 |
| 进战槽位数 +N | `melee_slots` | 加数 | `HexCellData.TryClaimAttackerSlot` | 允许更多近战单位同格围攻 |
| 全军回血频率 +X% | `heal_speed` | 乘数 | `UnitBrainBase` 回血计时器 | 单位自带农田/祭坛回血间隔缩短 |
| 全军回血量 +X% | `heal_amount` | 乘数 | `UnitBrainBase` 回血计算 | 每次回血数值提升 |

> card 项目的 `StatMultiplierBuff` 只支持乘数。主项目需额外补 `StatAdditiveBuff`（加数型）。

### 决策 3：触发时机（基于当前项目实际触发点）

> 科技/文化系统已删除，不可作为触发条件。以下为主项目当前实际可行的触发点：

| card 项目 | 主项目等价触发 | 可行性 | 说明 |
|---|---|---|---|
| 游戏开始（Tier 0） | 游戏开始 | ✅ | 仅玩家触发，免费 1 张入门天赋 |
| Boss 击败 | **占领公共建筑** | ✅ 推荐 | 公共建筑易主为主项目核心争夺机制，触发频率适中 |
| — | 探索 N 个地块 | 可选 | 每探索一定数量地块触发一次选卡 |
| — | 时间驱动（每 X 分钟） | 可选 | 纯时间触发，适合长时间对局 |

**推荐初始阶段**：
- 游戏开始（1 次）→ 入门天赋
- 每占领 1 个公共建筑（N 次）→ 主成长驱动
- 占领敌方主城（1 次，游戏终结时刻）→ 可额外给 1 次

### 决策 4：AI 是否同享

| 方案 | 描述 | 利弊 |
|---|---|---|
| A | 仅玩家拥有天赋系统 | 最简单，但 AI 无成长，后期碾压 |
| B | AI 达到同样条件时，后台随机自动选 1 张，进 AI 阵营 `FactionBuffService` | 推荐。`FactionBuffService` 按阵营隔离天然支持，AI 不弹 UI 但效果同等生效 |

## 六、天赋 Buff 与现有 BuffAggregator 的结算链路

```
结算入口（如 CombatResolver.Resolve）：
  baseAttack = attacker.UnitData.AttackDamage
  factionMultiplier = factionBuffService.GetStatMultiplier("damage")    // ← 天赋乘数（新）
  preBuffValue = baseAttack × factionMultiplier
  finalValue = BuffAggregator.Compute(preBuffValue, unitBuffs, "damage") // ← 单位级 Buff（旧，加法）
  → 结算
```

两层隔离、先乘（阵营天赋）后加（单位 buff），互不污染。

### 关键技术要点

1. **DOTween 替代手写协程**：card 项目全部动画是协程自算缓动，主项目统一用 DOTween。
   - `EaseOutQuad` → `Ease.OutQuad`
   - `EaseOutQuint` → 自定义 `AnimationCurve` 或 `Ease.OutQuint`
   - 但 `Ease.OutQuint` 在 DOTween 中不存在，可用 `Ease.OutCubic` 近似或自定义曲线

2. **不用 MonoBehaviour 动画组件**：card 项目里动画是纯代码控制的 `RectTransform` + `CanvasGroup` + `Image`，没有用到 Unity Animator。主项目延续此风格，更可控、无 timeline 依赖。

3. **CanvasGroup 是关键介质**：暗幕和卡牌的 alpha 控制都走 `CanvasGroup`。CardFrame.prefab 默认没有，代码里动态 `AddComponent` 或修改 prefab 均可。

4. **暗幕的 raycastTarget**：选卡面板最外层半透明 Image 必须 `raycastTarget = true`，阻止点击穿透到下方游戏 UI。选完关闭时设为 false。
