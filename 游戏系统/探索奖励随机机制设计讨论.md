# 探索奖励随机机制 · 设计讨论

## 功能目标

探索地块时，除现有的"标记已探索 + 占领 + 收割资源"之外，额外获得随机奖励：

- **金币奖励**：随机获得 0 / 25 / 50 / 100 / ... 等档位的金币
- **单位奖励**：随机获得 0 / 1 / 2 / 3 / ... 等档位的单位（己方仙人掌）

两个奖励互不相干，分别独立掷骰，但每次探索都会触发。

> 随机奖励**叠加**于现有的收割奖励之上（现已有：基础 5 金 + 资源地块额外 10~30 金）。

---

## 1. 核心时序（基于实际代码）

当前 `ExplorationService` 已将流程拆为两段（`ExplorationService.cs`）：

```
TryExplore(cell)
  → 校验：水域禁止(L38) / 已探索 / 不可探索 / 邻接 / 扣费
  → 标记已探索 cell.ExploreThisHexCell()
  → 触发 CellExplored 事件
  → return Success

  ...动画播放中（ExplorationPillarPool 监听 CellExplored 播柱体特效）...

onDissolveStart 回调（ExplorationPillarPool.cs:82）：
  → CompleteExploration(cell)
      → 圈入势力范围 territoryService.Claim(cell)
      → 收割资源 HarvestAndReward(cell)  ← GoldWallet.AddGold(0, reward)
      → 刷新视觉 mapVisualEvent.Raise()
  → [新增] 触发 ExplorationRewardTriggered 事件
  → 奖励系统监听：掷骰 → 加金币 + 生成单位
```

**奖励触发时机**：与 `CompleteExploration` 在同一个 `onDissolveStart` 回调内触发，保证在动画溶解开始（即柱体升起到顶点）时发放，不是动画完全结束后。

## 2. 随机表结构（已确认）

每次探索分别掷两个独立的骰子，概率表互不影响。各档位**等概率**。

| 档位 | 金币  | 单位数 |
|------|-------|--------|
| 0    | 0     | 0      |
| 1    | 25    | 1      |
| 2    | 50    | 2      |
| 3    | 100   | 3      |
| 4    | 200   | 4      |
| 5    | 400   | 5      |

> 档位数和每档数值通过 SO 配置，方便调参。

## 3. 与现有系统的对接点

### 3.1 金币钱包 ✅ 已有，无需新增

`GoldWallet` 已存在，提供 `AddGold(int playerIndex, int amount)`（`ExplorationService.cs:112`）。奖励系统直接注入 `GoldWallet` 调用即可。

### 3.2 单位生成与战斗 ✅ 无需额外触发战斗

- 战斗全自动即时结算（`CombatResolver.Resolve()`）
- 单位 Brain 在 `OnStepFinished()` 自动索敌并攻击
- 奖励系统只负责**生成单位**，放入地块后 Brain 接管一切

> ⚠️ 当前无统一玩家单位生成接口，详见第 6 节"实现缺口 #1"。

### 3.3 水域格 ✅ 禁止探索，无需处理

`ExplorationService.cs:38-40` 在入口拦截水域格：

```csharp
if (targetCell.HexType == Enums.HexType.LakeOrSea)
    return ExploreResult.AlreadyExplored;
```

奖励系统永远不会收到水域格的请求。

### 3.4 地块占用与单位溢出（已确认）

**生成策略**：逐个生成，放不下溢出到邻格（可溢出到未探索格，水域除外）。

> ⚠️ 奖励生成的单位**不主动设置 Occupant**，直接 `Instantiate` + 放置世界坐标后让 Brain 自行通过移动系统占格。原因见第 6 节"实现缺口 #3"。

溢出邻格选择算法：优先非水域、无建筑的空格；随机选中一格。若所有邻格均不可用，跳过该单位（不生成）。

### 3.5 事件链（新增 ExplorationRewardTriggered 事件）

| 事件 | 来源 | 触发时机 |
|------|------|----------|
| `CellExplored` | `ExplorationService` | 探索成功立即，触发动画 |
| `ExplorationRewardTriggered` | `IExplorationService`（新增） | 柱体溶解开始时（`onDissolveStart`），与 `CompleteExploration` 同点 |

奖励系统监听 `ExplorationRewardTriggered`，不监听 `CellExplored`（避免在动画开始前就发奖励）。

## 5. 实现缺口（编码前需要解决）

### 缺口 #1：无统一玩家单位生成接口

**现状**：
- 玩家单位生成：`CardPresenter.SpawnUnit()` 私有方法（`CardPresenter.cs:262`），无法被外部调用
- AI 单位生成：`AIEntityFactory.GenerateUnit()` 公开方法，但生成的是敌方单位（`tag = "EnemyUnit"`, `PlayerIndex = 1`）

**影响**：奖励系统无法调用现有代码生成玩家单位。

**解决方案**：提取 `IPlayerUnitSpawnService` 接口，`CardPresenter` 实现并暴露：

```csharp
public interface IPlayerUnitSpawnService
{
    /// <summary>在指定世界坐标生成玩家单位，返回生成的 GameObject（失败返回 null）。</summary>
    GameObject SpawnPlayerUnit(int unitID, Vector3 worldPosition);
}
```

`CardPresenter.SpawnUnit()` 改为该接口的实现；DI 绑定后奖励系统注入使用。

---

### 缺口 #2：IExplorationService 缺少 ExplorationRewardTriggered 事件

**现状**：`IExplorationService` 只有 `CellExplored` 事件和 `CompleteExploration` 方法，奖励触发时机没有对应的通知接口。

**解决方案**：在 `IExplorationService` 新增事件，在 `ExplorationPillarPool.onDissolveStart` 回调中触发：

```csharp
// IExplorationService.cs
event Action<HexCellData> ExplorationRewardTriggered;
```

```csharp
// ExplorationPillarPool.cs onDissolveStart 回调
_explorationService.CompleteExploration(capturedCell);
_explorationService.RaiseRewardTrigger(capturedCell);  // 新增
```

---

### 缺口 #3：奖励生成单位的占用逻辑

**现状**：正常部署单位通过 `CardPresenter.SpawnUnit()` → `h.SetHaveUnit(true, g)` 登记占用，再由 `UnitMovementController` 走移动系统。

**问题**：奖励单位是"凭空生成"在地块上，若该格有敌人需要进入进攻槽，但 `TryClaimAttackerSlot(dir, unit)` 需要一个方向参数（0-5），凭空生成无从提供方向。

**解决方案**：奖励生成的单位**不预先设置占用**——只设置 `h.SetHaveUnit(true, g)` 登记存在，不调用 `SetOccupant` 或 `TryClaimAttackerSlot`。单位 Brain 启动后通过正常的移动+索敌流程自然处理占用。如果目标格有敌人，Brain 会在第一个 tick 内识别并发起攻击，进攻槽由 Brain 的移动系统自动申请。

---

### 缺口 #4：溢出到邻格时目标格的选择

**现状**：文档描述"放不下就溢出"，但未定义选格算法。

**解决方案**：遍历目标格的 6 个邻格，筛选条件：
- `HexType != LakeOrSea`（非水域）
- `BulidingTypeOnHex_Building.Key == NoBuilding`（无建筑）
- `!IsHaveUnit()`（无其他单位）

从候选格中随机选一格生成。若无候选格，该单位跳过不生成（不报错，静默丢弃）。

---

### 缺口 #5：PlayerIndex 硬编码问题

**现状**：玩家 PlayerIndex 在整个项目中暂时硬编码为 `0`（`CardPresenter.cs:293`），AI 为 `1`。

**影响**：奖励系统目前可安全硬编码 `playerIndex = 0`，但后续多玩家化时需要改。

**解决方案**：奖励系统接口预留 `playerIndex` 参数，当前实现传 `0`，后续替换不改接口：

```csharp
// ExplorationRewardSystem 内部
_goldWallet.AddGold(0, goldAmount);         // 暂时硬编码
_unitSpawnService.SpawnPlayerUnit(unitID, position); // SpawnPlayerUnit 内部处理 PlayerIndex
```

## 6. 模块边界（更新后）

```
ExplorationService         → 校验 + 标记探索 + 新增 ExplorationRewardTriggered 事件
ExplorationPillarPool      → 监听 CellExplored，播动画；onDissolveStart 触发
                              CompleteExploration + ExplorationRewardTriggered
CardPresenter              → 实现 IPlayerUnitSpawnService，暴露单位生成能力
ExplorationRewardSystem    → 监听 ExplorationRewardTriggered，掷骰，调用 GoldWallet + IPlayerUnitSpawnService
GoldWallet                 → 加金币（已有 AddGold）
CombatResolver             → 战斗结算（已有，Brain 自动调用）
```

奖励系统不碰 `ExplorationService` 内部，不改现有探索流程。改动点仅三处：
1. `IExplorationService` + `ExplorationService`：新增 `ExplorationRewardTriggered` 事件
2. `ExplorationPillarPool.onDissolveStart`：新增一行触发事件
3. `CardPresenter`：实现 `IPlayerUnitSpawnService` 并注册到 DI
