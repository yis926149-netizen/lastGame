# 断供迷雾与建筑失能吞并设计方案

> 本方案在《后勤系统设计方案》基础上追加三条规则：**断供迷雾覆盖建筑**、**建筑断供失能**、**区域连接即吞并**。
> 涉及对原方案的更新点：§6.6（箭塔不再"不受后勤影响"）、§7.1（迷雾范围延伸至建筑）、§8.2（占领条件）、§10.3 / §10.6（测试项）。原方案其余部分继续有效。
>
> 2026-08-02 修订：补充决策 10-12（中立公共建筑豁免占领/吞并、公共建筑吞并含外一环、吞并格并入主城单城字典），并修正代码审查发现的实现细节（建筑归属同步、领地字典重建、重入保护、血条隐藏粒度等）。

## 二、规则定义

### 2.1 建筑迷雾（决策 3、4）

- 断供地块的迷雾覆盖范围从"地面"延伸至**该格上的建筑模型**（含公共建筑），双方观察一致（保持原 §7.1 规则）。
- **血条 UI** 在玩家视角不可见（`IsVisibleToFaction(cell, 0) == false`）时隐藏（含其子 UI）。
- 单位不雾化、不失能、可通行可战斗（决策 8）。

### 2.2 建筑失能（决策 2）

- **定义**：`IsFunctional = (建筑所在格 Player_City_Index.Key == 建筑所属阵营) && IsLogisticsConnected(cell, 所属阵营)`。
- **阵营来源**：`建筑所属阵营` 一律取 `BuildingBase.Player_City_Index.Key`（易主时由迁移函数同步刷新，见 3.4）。**禁止**使用 Awake 时缓存的 tag/阵营快照——现有 `BarracksSpawner._isPlayer`（BarracksSpawner.cs:32）在吞并后不会刷新，必须改为查询时从建筑归属派生。
- **适用范围**：全部建筑类型——箭塔、兵营、攻击/防御雕像、祭坛、普通建筑、公共建筑（反转原 §6.6"箭塔不受影响"）。
- **失能表现**：
  - 箭塔停止开火；
  - 兵营暂停生产（`BarracksSpawner.cs:50` 已有后勤暂停，统一改走门控）；
  - 雕像/祭坛等增益、行为停摆；
  - 公共建筑区域断供时停止特殊行为与奖励结算。
- **不失能的情况**：
  - 主城永不失能（主城是 BFS 根，永远连通）；
  - 建筑随新主易主后，若新主后勤畅通则立即恢复功能。
- 失能建筑**仍是移动阻挡物**；仍可被占领（随地块易主，见 2.3）。
- 实现细节：箭塔失能停止开火时必须同时清除 `_lockedTarget`（ArrowTowerShooter.cs:24），避免恢复供应后对旧目标射击。

### 2.3 占领判定修改（决策 1、7）

**入口一**：`UnitMovementSystem.TryCaptureEnemyCell`（UnitMovementSystem.cs:247-274）

现有条件（:265-271）：目标格存在敌方建筑 → 不占领。

修改为：

> 目标格存在敌方建筑时，仅当该建筑**功能正常**（供应畅通）才阻止占领；
> 建筑**失能**时不阻止占领——占领继续执行，建筑随格易主（不摧毁、HP 回满）。

**适用范围（决策 10）**：逐格占领只对阵营 0/1 有效——`Player_City_Index.Key ≥ 2`（中立公共建筑伪阵营）的格**豁免占领**，不触发 `TryCaptureEnemyCell`，也不参与建筑摧毁后的占领判定。

**建筑归属同步**：建筑随格易主时**必须同步更新 `BuildingBase.Player_City_Index`**（建筑自身归属真相源，BuildingBase.cs:28）——它被 `ArrowTowerShooter` 阵营判定（ArrowTowerShooter.cs:113-116）、血量 buff（BuildingBase.cs:47）、占领阻挡判定（UnitMovementSystem.cs:269）直接读取；`LogisticsService.TransferOwner` 只改地块归属不改建筑，迁移函数见 3.4。

**入口二**：`BuildingController.TryCaptureAfterBuildingDestroyed`（BuildingController.cs:323-341）——建筑被摧毁后单位站在该格 → 占领。**保留**。

**两种吞并方法并存**（决策 7）：
1. 逐格占领（上述两个入口，玩家/AI 单位踩上敌方地块即占领）；
2. 区域吞并（见 2.4，断供区与敌方后勤网络相邻即整体易主）。

### 2.4 区域吞并（决策 5、6、9）

**触发时机**：每次后勤重算完成后自动执行（并入 `LogisticsService.RecalculateAll` 尾部，见 3.5）。

**判定条件**（全部满足）：
1. 断供区域：阵营 g（仅 0/1）的所有断供格（`Key == g && !IsLogisticsConnected(cell, g)`）按 6 邻域连通分量划分；含 `Key ≥ 2`（中立公共建筑）格的连通分量**不参与吞并**（决策 10）；
2. 区域**不含任何主城格**（防御性检查；主城连通分量恒有供应，正常不会命中）；
3. 区域边界（任意一格）与吞并方 f 的后勤网络（`_connectedCells[f]`）**共边相邻**，且 f ≠ g。

**吞并效果**：
- 整个区域原子易主给 f：逐格**批量写入**归属 `(f, 0)` + `ExploreBy(f)`（迷雾按新归属清除，TerritoryService.cs:83-89 的语义；**禁止逐格调 `TransferOwner`**，见 3.5 防递归）；
- 格上建筑整体迁移（tag/视觉/索引/HP 回满，见 3.4）；
- 公共建筑整体易主（走 `OnCaptured` 同款路径，含其 `OccupiedHexes` 全部格、奖励结算、`OnPublicBuildingCaptured` 事件，PublicBuildingBase.cs:217-252）；
- **立即吞并**：无等待时长、无单位/建筑在场要求（决策 5）；
- **无数量限制**：所有满足条件的区域一次全部吞并（决策 6）；
- **公共建筑含外一环**（决策 11）：区域内公共建筑走 `OnCaptured` 全量路径——`ExpandSphereOfInfluence`（PublicBuildingBase.cs:305）把占位格+外一环全部格归属写入新主并结算奖励/收割（`HarvestForGold`），吞并范围实际大于断供区域本身；
- **并入主城单城字典**（决策 12）：吞并格写入 `(f, 0)`，吞并后重建领地字典，归入吞并方主城 `(f, 0)` 条目（P0 接受，见 3.5）。

**防递归**：吞并导致的归属变化会再触发一次内部重算，重算封顶 3 层（重入保护）；吞并中**批量写入归属、禁止逐格调用 `TransferOwner`/`SetOwner`**（其内部会重算导致嵌套 BFS，TerritoryService.cs:88）；整个流程**只触发一次 `LogisticsChanged`**（由最内层无迁移的那次重算触发）。

## 三、系统架构与代码改造

### 3.1 BuildingSupplyGate（新组件，统一失能门控）

挂在 `BuildingController` 上（或独立组件注入）：

```text
class BuildingSupplyGate : MonoBehaviour
    [Inject] ILogisticsService _logisticsService;
    HexCellData _cell;                    // 建筑所在格（部署/易主时解析）
    int _factionId;                       // 建筑所属阵营（Player_City_Index.Key）
    public bool IsFunctional;             // 缓存

    Start(): 解析 _cell；_factionId = BuildingBase.Player_City_Index.Key
             _logisticsService.LogisticsChanged += Refresh
             Refresh()
    // 易主（占领/吞并）后由 BuildingTransferService 重刷 _factionId 并 Refresh()
    Refresh(): IsFunctional = _logisticsService.IsOwnedBy(_cell, _factionId)
                             && _logisticsService.IsLogisticsConnected(_cell, _factionId)
    OnDestroy(): 退订
```

公共建筑门控：`_factionId = PlayerIndex`（§4.3 修复后 `Key == PlayerIndex`），`_cell = RootHex`，区域断供即失能。中立公共建筑（`PlayerIndex ≥ 2`）不挂门控或恒视为失能——但其格已豁免占领/吞并（决策 10），失能只影响行为停摆，不影响归属。

### 3.5 AnnexationService（区域吞并，并入重算流程）

推荐独立类 `AnnexationService`，由 `LogisticsService.RecalculateAll`（TerritoryService.cs:103）尾部调用：

```text
// LogisticsService.RecalculateAll() 改造后：
BFS 双方 → _connectedCells
if (AnnexationPass() 发生了迁移):
    领地字典重建（Player/Enemy RebuildSphereOfInfluence）
    if (重算层数 < 3): RecalculateAll()   // 吞并后状态已稳定，仅 1 次尾递归
    return                                 // 事件由最内层"无迁移"的那一次触发
Version++; LogisticsChanged?.Invoke()      // 整个吞并流程只触发一次

AnnexationPass() -> bool（是否发生迁移）:
  foreach 断供方 g in {0, 1}:
    unsuppliedCells = { cell | Key == g && !IsLogisticsConnected(cell, g) }   // 仅 0/1
    regions = FloodFill(unsuppliedCells)          // 6 邻域连通分量
    foreach 区域 R in regions:
      if R 含主城格: continue
      if R 含 Key >= 2 格: continue               // 中立公共建筑豁免（决策 10）
      if 无邻居 ∈ _connectedCells[f]（f ≠ g）: continue
      // 批量归属写入：cell.Player_City_Index = (f, 0) + ExploreBy(f)
      // 禁止调用 TransferOwner/SetOwner（内部重算 → 嵌套 BFS，TerritoryService.cs:88）
      foreach cell in R:
        cell.Player_City_Index = (f, 0); cell.ExploreBy(f)
        if 有建筑: BuildingTransferService.TransferBuilding(building, f, g)
        // 公共建筑：TransferBuilding 步骤 5 走 OnCaptured 全量（含外一环，决策 11）
  返回是否有迁移
```

吞并方冲突消解：固定按阵营顺序处理（先 f=0），先吞并方优先，后处理方不会重复吞并（区域已并入先方网络）。

### 3.6 建筑雾化与血条隐藏

- `FogEnvironmentSelectiveEffect`（MapRenderer.cs:1610）：
  - `Initialize`（:1627）增加建筑根节点参数（`PlayerBuilding` / `EnemyBuilding`，运行时按存在与否收集）；
  - `AddRenderers`（:1761）将其 Renderer 纳入对象遮罩，后处理按 `_FogMaskTex` 自动雾化，边界与地形自动对齐（FogEnvironmentSelective.shader:39-46）；
  - 刷新时机：**无需新增事件**——部署（CardPresenter.cs:428）、建筑死亡（BuildingController.cs:315）、城市易主（BuildingController.cs:152/:247/:280）、占领/吞并迁移（3.4 步骤 6）均已 Raise，`RefreshRenderers` 由 `OnMapVisualChanged` / `OnLogisticsChanged`（MapRenderer.cs:1193-1201）驱动，覆盖全部路径。
- 血条：`BuildingController` 订阅 `LogisticsChanged` / `MapVisualEvent`，玩家视角 `!IsVisibleToFaction(cell, 0)` 时**隐藏整个建筑 Canvas**（`GetComponentInChildren<Canvas>()` 的 GameObject）——血条是 Canvas 的 child0（SpawnUIWiring.cs:52-56），兵营生产进度条是血条的兄弟（BarracksSpawner.cs:193），只隐藏 Slider 会漏掉进度条（决策 4）。
- **单位擦除层（方案A，决策 8 单位不雾化）**：单位材质是透明队列（如 `UnityChan/Skin - Transparent`，Queue=Overlay+104），不在相机深度纹理中——对象遮罩的深度裁剪（`FogEnvironmentObjectMask` 的 `clip(sceneDepth - eyeDepth)`）看不到"单位挡在金矿/建筑前"，雾化会连带盖住单位（金矿地貌处可见此现象）。修复：新增 `Hidden/FogEnvironmentUnitErase` 擦除 shader 与单位根节点（`PlayerUnit`/`EnemyUnit`），在雾化对象绘制**之后**用单位自身深度与场景深度比较，把"可见单位"像素从遮罩清零（单位被不透明物体遮挡时不擦除）；CommandBuffer 每帧按当前变换重绘，移动中的单位实时生效；单位销毁需刷新列表（`UnitRemovalService` 补 Raise）。
- **单位 UI 擦除（世界空间 Canvas）**：单位血条/图标 Canvas 是 `m_RenderMode: 2`（World Space），渲染进场景颜色且 UI/Default 材质不写深度——同样的机制导致雾化对象把单位 UI 一并雾化。CanvasRenderer 不能走 `DrawRenderer` 几何替换，改为**屏幕矩形擦除**：新增 `Hidden/FogEnvironmentUnitUIErase`（全屏 quad + `_UnitUIRects[32]` 归一化矩形数组），每帧在 `OnPreCull` 把单位根下所有 Canvas 的 `GetWorldCorners` 投影为屏幕 AABB（含 1px padding、离屏剔除），写入擦除材质（CommandBuffer 执行时读取最新值），在模型擦除后绘制全屏 quad 清零命中像素；上限 32 个 UI，超出忽略。

### 3.7 前置数据修复（依赖后勤方案 §4，先行完成）

- **§4.3 公共建筑**：归属直接写阵营 Key，不伪装 `(1, 0)` 城市条目——否则区域吞并检测无法识别公共建筑区域，且失守可能删除 AI 主城键。
- **中立公共建筑可见性（代码审查 A7，与 §4.3 一并处理）**：当前 `IsVisibleToFaction` 对 `Key ≥ 0` 一律走"归属方探索+供应"（TerritoryService.cs:160-165），而探索位掩码只有 0/1 位（HexCellData.cs:223）→ 中立公共建筑（Key ≥ 2）Reveal 后仍对双方迷雾，与后勤方案 §2.3"中立格按观察方发现状态"矛盾。修复：`Key ≥ 2` 视作中立，按观察方 `IsExploredByFaction(viewer)` 判断。实施前先在运行时验证该问题是否已存在。
- §4.1 归属一致化（占领/吞并后领地字典必须从地块重建，禁止手工维护）、§4.2 主城索引冲突、§4.6 地形归属过滤按原方案执行。

## 四、典型时序

**场景：玩家切 AI 走廊 → 区域吞并**

```text
主城P - 蓝 - 蓝 - 红(兵营·功能) - 红 - 红 - 红 - 主城A
```

1. 玩家先摧毁红方功能兵营（索敌正常）→ `BuildingDestroyed` → 玩家单位在格上 → `TryCaptureAfterBuildingDestroyed` 占领该格 → 重算；
2. 重算后红方后方区域断供（`Key==1 && !IsLogisticsConnected`）；
3. `AnnexationPass`：区域边界与玩家网络相邻 → 整区域吞并（含剩余建筑，建筑随格易主、HP 回满）；
4. 吞并后重算一次，只触发一次 `LogisticsChanged`；
5. 区域并入玩家网络 → 玩家 `ExploreBy` 已自动写入 → `IsVisibleToFaction` 双方均为 true → 迷雾清除、血条恢复显示、建筑恢复功能。

**飞地场景（跨中立占领）**

```text
主城P - 蓝 - 蓝 - 中立 - 中立 - 蓝(原红)          // 占领后断供
```

- 新占格断供 → 迷雾覆盖（含建筑）；
- 若 AI 网络与这块飞地相邻 → 立即吞回（决策 5）。对称博弈，符合"断供即脆弱"的设计意图。

## 六、测试范围

### 6.1 原方案测试项更新

- §10.3 "箭塔不受影响" **删除**，改为"断供后箭塔/兵营/雕像全部失能"；
- §10.6 增加：失能建筑可被占领且随格易主；吞并只触发一次 `LogisticsChanged`。

### 6.2 新增用例

**失能与索敌**
- 断供后箭塔不开火、兵营暂停（保留进度）、雕像停摆；
- 失能建筑不被双方索敌（`FindNearestEnemyBuilding` 返回其他目标/空）；
- 功能正常建筑仍被索敌、仍阻挡占领。

**占领（决策 1a）**
- 敌方失能建筑 + 我方单位在格上 → 占领成功，建筑随格易主（tag/视觉/HP 回满/索引迁移/建筑归属同步）；
- 敌方功能建筑 → 不占领；
- 建筑摧毁后单位在格上 → 占领（保留，回归）；
- 失能公共建筑随格易主走 `OnCaptured` 全量路径；
- 中立公共建筑格（Key ≥ 2）不触发占领（决策 10）；
- 建筑随格易主后 `BuildingBase.Player_City_Index` 已同步（箭塔阵营判定、血量 buff、占领阻挡判定正确）。

**区域吞并**
- 断供区域与敌方网络相邻 → 整区域吞并（含建筑、公共建筑、金矿格）；
- 不含主城格（主城免疫）；
- 含 `Key ≥ 2` 格的连通分量不吞并（中立公共建筑豁免，决策 10）；
- 公共建筑吞并含外一环归属（决策 11，`ExpandSphereOfInfluence` 全量路径）；
- 吞并后领地字典重建正确：吞并格并入吞并方 `(f, 0)` 单城字典（决策 12）；
- 吞并全流程只触发一次 `LogisticsChanged`（重入保护 + 事件延迟）；
- 吞并后迷雾按新归属清除（双方 `IsVisibleToFaction` 均为 true）；
- 飞地吞并被切断后由原主吞回（对称回归）。

**迷雾与血条**
- 断供地块地面 + 建筑 + 血条全部隐藏（玩家视角）；
- 恢复供应后全部恢复显示；
- 单位在断供地块通行、战斗不受影响（回归）。

**公共建筑（前置 §4.3）**
- 公共建筑失守不删除 AI 主城键（回归）；
- 公共建筑区域断供检测正确、吞并后整体易主。

## 七、风险与遗留问题

1. **飞地反复易主**：跨中立占领的飞地断供后，对方网络相邻即可立即吞回。当前设计接受（决策 5 立即吞并）；若实战振荡严重，追加"易主保护期"（建议 5 秒，配置化）。
2. **单位不雾化与建筑雾化的视觉对比**：决策 8 已确认不改，记录在案；若后续调整，可将单位纳入 `FogEnvironmentSelectiveEffect` 或按 `IsVisibleToFaction` 单独处理。
3. **公共建筑依赖 §4.3**：未修复前区域吞并检测对公共建筑区域无效，实施顺序上必须先完成。
4. **索引字典迁移不对称**：`EnemyModelManager` 无按类型建筑索引，AI 建筑迁移仅维护 tag/视觉/归属；若后续 AI 需要按类型检索建筑（如加成类逻辑），需补对称结构。
5. **失能即脆弱的设计张力**：失能建筑"不可索敌但可被踩走"，意味着断供区的建筑是"奖励"而非"目标"，防御价值只在供应畅通时存在——与 §6.6 旧直觉相反，需在策划案中同步措辞。
6. **领地描边线穿透迷雾**：`SphereOfInfluenceRenderer` 描边线不在雾化范围内，断供后领地线可能"浮在迷雾上"（与建筑悬浮同类表现问题）；待建筑雾化落地后评估。
7. **占领"无敌方单位"依赖移动阻挡**：`TryCaptureEnemyCell`（UnitMovementSystem.cs:247-274）本身无单位检查，依赖寻路层对"敌方有单位格"不可入；实施时验证寻路条件，若可入需在占领判定补单位检查。
8. **公共建筑吞并的连锁扩张**：决策 11 的 `OnCaptured` 全量路径会把外一环格无条件写入新主（PublicBuildingBase.cs:330-341），可能连带划走区域外的中立/敌方格——这是既有"公共建筑占领即圈地"规则的延伸，接受；但吞并后新主网络若与外一环断开，该环仍属新主（断供态），后续可能再次被吞回。
