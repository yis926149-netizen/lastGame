# 竖屏适配方案讨论

## 背景

UI 布局基于横屏 1920×1080 设计，切换竖屏后 Canvas 缩放错误、元素错位。

## 技术诊断

### Canvas Scaler 配置

| 参数 | 当前值 | 问题 |
| --- | --- | --- |
| Scale Mode | `Scale With Screen Size` | 正确 |
| Reference Resolution | `1920 × 1080` | 横屏参考，竖屏下宽高比反转导致缩放异常 |
| Screen Match Mode | `Match Width Or Height` | — |
| Match | `0.5` | 宽高各占 50%，竖屏下无法正确匹配任一方向 |

### 硬编码布局偏移

代码中多处使用可读性差的固定像素值，假设横屏坐标系：

**CardController.cs**

| 行 | 值 | 用途 |
| --- | --- | --- |
| 75 | `new Vector3(0, -25f, 0)` | 预告卡初始偏移 |
| 95 | `400f` | 拖拽缩放的最大距离阈值 |
| 117 | `new Vector3(0, 35, 0)` | 悬停时的上移偏移 |

**UIController.cs**

| 行 | 值 | 用途 |
| --- | --- | --- |
| 198 | `new Vector2(0, 315)` | 信息面板滑入偏移量 |

## 方案对比

### 方案 ：完整竖屏适配

#### B1. 修改 Canvas Scaler

| 改动 | 说明 |
| --- | --- |
| Reference Resolution | 从 `1920×1080` 改为 `1080×1920` |
| Match | 从 `0.5` 改为 `1`（完全匹配高度） |

运行时可用脚本检测屏幕方向，动态切换参考分辨率。

#### B2. 重构 UI 锚点

所有 UI 元素的 RectTransform 需要从固定像素坐标改为屏幕比例锚点：

| UI 元素 | 当前布局 | 目标 Anchor |
| --- | --- | --- |
| 手牌卡槽 | 底部水平排列，固定 Y | `anchorMin/Max = (0, 0)` 底部居中 + 按屏幕宽度计算卡间距 |
| 暂停按钮 | 左上角固定位置 | `anchorMin/Max = (0, 1)` 左上角 |
| 金币/收入 HUD | 右上角固定位置 | `anchorMin/Max = (1, 1)` 右上角 |
| 单位信息面板 | 固定位置 + 315px 上滑 | `anchorMin/Max = (1, 0.5)` 右侧居中 |
| 天赋选卡面板 | 3 张卡横排居中 | 适配短边，改为纵向排列或缩小卡尺寸 |

#### B3. 删除硬编码像素偏移

所有固定数值改为相对 `Screen.width` / `Screen.height` 计算：

| 位置 | 替换方案 |
| --- | --- |
| 预告卡初始 `-25f` | `Screen.height * -0.015f` |
| 拖拽最大距离 `400f` | `Screen.height * 0.37f` |
| 悬停上移 `35f` | `Screen.height * 0.025f` |
| 信息面板滑入 `315` | `Screen.height * 0.29f` |

#### B4. 镜头适配

CameraController 可能也需要根据屏幕方向调整正交尺寸或距离，确保竖屏下地图可视区域合理。

**优点**：真正支持竖屏。  
**缺点**：涉及 Canvas Scaler、每个 UI 元素的 Anchor、至少 5 处代码硬编码、以及镜头适配，改完后需要全量 UI 回归测试。

---

## 推荐选择

**方案 A**。策略游戏天然适合横屏，为竖屏投入大量 UI 改造性价比极低。除非目标平台有硬性竖屏要求，否则锁定横屏即可。
