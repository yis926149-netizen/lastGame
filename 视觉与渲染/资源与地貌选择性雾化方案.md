# 资源与地貌选择性雾化方案

## 需求定义

> 未探索区域中，只处理地图地形，以及地图生成的资源模型、地貌模型。
> 玩家单位、AI 单位、建筑、特效、路径和 UI 都保持正常显示。

因此不能采用"统一全屏后处理所有 3D 内容"的做法，那会把未探索区域里的单位和建筑一起雾化。

## 核心思路

保留当前地形迷雾，再给后处理增加一张"资源与地貌对象遮罩"。

最终判定：

```
地形：
  继续使用现有 Terrain/FogBlend Shader

屏幕中的其他像素：
  只有同时满足以下条件才雾化：
  1. 该像素属于 LandForm 或 Resource
  2. 该像素世界位置位于未探索区域
```

Shader 逻辑概括：

```hlsl
if (objectMask > 0 && fogMaskAtWorldPosition < 0.5)
{
    // 去饱和 + 叠加雾色
}
```

这样单位即使走进未探索格，也不会被处理。

---

## 需要两张遮罩

### 1. 现有探索遮罩 `_FogMaskTex`

- `0`：未探索
- `1`：已探索

负责回答：**这个世界 XZ 位置是否属于未探索区域？**

现有代码可直接复用：

- `MapRenderer.cs:1233-1255`：创建遮罩
- `MapRenderer.cs:1257-1287`：六边形盖章
- `MapRenderer.cs:1289-1303`：探索后更新

### 2. 新增对象分类遮罩 `_FogAffectedObjectMask`

一张屏幕空间 RenderTexture：

- 黑色：地形以外、不需要处理的对象
- 白色：地貌或资源模型

负责回答：**当前屏幕像素是否属于需要被雾化的资源或地貌？**

由此严格按对象类别处理，而不依赖单位所在格。

## 推荐渲染流程

```
主相机正常渲染场景
        ↓
额外渲染资源/地貌对象遮罩
        ↓
全屏后处理读取：
  - 场景颜色
  - 相机深度
  - 资源/地貌对象遮罩
  - _FogMaskTex
        ↓
只对"对象遮罩为白且地块未探索"的像素处理
        ↓
Screen Space Overlay UI 最后正常显示
```

地形仍继续由现有 Shader 处理，因此不会误伤单位和建筑。

## 如何识别资源和地貌

地图生成时已有清晰的对象分组：

```csharp
GameObject landForm = new GameObject("LandForm");
GameObject Resource = new GameObject("Resource");
```

位置：

- `Assets/Scripts/Managers/MapRenderer.cs:1051-1067`
- `Assets/Scripts/Managers/MapRenderer.cs:1068-1083`

所有地貌实例挂在 `LandForm` 根对象下，资源实例挂在 `Resource` 根对象下。

最稳妥方式是为它们设置专用 Layer，例如 `FogAffectedEnvironment`，并**递归**设置：

```
LandForm 根对象及全部子 Renderer → FogAffectedEnvironment
Resource 根对象及全部子 Renderer → FogAffectedEnvironment
```

必须递归，因为实例化的预制体内部通常还有多层子对象，真正的 `MeshRenderer` 不一定在根节点。

不建议通过名称或 Tag 在 Shader 中识别：

- Shader 无法直接读取 GameObject 名称
- Tag 不参与相机 Culling Mask
- 每帧按名称搜索对象效率和可靠性都差

专用 Layer 是最直接的对象分类方式。

## 对象遮罩生成方式

### 方式 1：专用遮罩相机

增加一台与主相机参数同步的隐藏相机：

- 只渲染 `FogAffectedEnvironment` Layer
- 输出到单通道/低精度 RenderTexture
- 使用纯白替换 Shader
- 背景清为黑色
- 不显示到屏幕

**优点**：实现直观；Layer 筛选天然准确；不需遍历 Renderer；只需同步矩阵。

**缺点**：地貌/资源额外绘制一遍；需保证投影完全一致；**需要解决被单位/建筑遮挡时的深度关系**。

关键问题——被遮挡穿透：

```
主画面：单位挡住资源箱
遮罩相机：不渲染单位，只看到资源箱
后处理：可能把单位所在像素误认为资源箱像素
```

结果是单位局部被误雾化。因此不能只用简单的"忽略其他对象"遮罩相机，除非遮罩生成时还能与主相机深度比较。

### 方式 2：CommandBuffer + 主相机深度（推荐）

在主相机完成不透明物体深度之后：

1. 创建一张黑色对象遮罩 RT
2. 用 `CommandBuffer.DrawRenderer()` 重绘所有资源和地貌 Renderer
3. 使用纯白遮罩材质
4. 绘制时使用主相机现有深度做 `ZTest`
5. 只有真正从主相机可见的资源/地貌像素才写白
6. 后处理读取这张遮罩

**优点**：被单位/建筑遮挡的资源不会穿透写入遮罩；与主相机投影天然一致；不需第二台相机；执行时机可精确控制。

**缺点**：需收集维护 Renderer 列表；每个 Renderer 至少增加一次遮罩绘制；半透明和裁剪材质需额外处理；CommandBuffer 生命周期需正确解绑释放。

对当前需求，这是更稳的选择。

## 地形处理

### 地形继续使用现有 Shader

现有地形已正确处理：

- `TerrainBase_Fog.shader`
- `ThreeMaterialBlend_Land.shader`
- `RealMaterialMaskBlend.shader`
- `FogBlend.cginc`

不必为了资源和地貌把地形也迁移到全屏后处理，可避免：

- 地形重复雾化
- 全屏后处理误处理单位
- 对地形深度重建精度的额外依赖

### 后处理只负责资源和地貌

后处理应先检查对象遮罩，提前退出：

```hlsl
float objectMask = tex2D(_FogAffectedObjectMask, uv).r;

if (objectMask < 0.5)
{
    return sourceColor;
}

// 只有对象遮罩通过后，才读取深度、重建世界坐标、采样 _FogMaskTex
```

屏幕中大多数像素可提前返回，减少开销。

## 单位进入未探索地块时的结果

| 内容 | 是否被雾化 |
|---|---|
| 未探索地形 | 是 |
| 未探索格上的树木、石头等地貌 | 是 |
| 未探索格上的动物、植物、宝箱等资源 | 是 |
| 玩家单位 | 否 |
| AI 单位 | 否 |
| 玩家建筑 | 否 |
| AI 建筑 | 否 |
| 公共建筑 | 否 |
| 探索柱、攻击粒子等特效 | 否 |
| 路径和势力范围 | 否 |
| UI、血条、费用标签 | 否 |

玩家或 AI 单位进入未探索格时呈现：

```
地面有雾
周围资源和地貌有雾
单位保持正常颜色、正常亮度
单位移动不会自动解除迷雾
```

完全符合"只有地图及其之上的资源、地貌需要被雾化"的范围。

> 补充：当前 `HexCellData.IsExplored` 是全局状态，不区分玩家和 AI。AI 自动探索（`AIAutoExplorer.cs:83,92`）会解除玩家画面的迷雾。本方案不改变这一逻辑，如需分阵营遮罩需另行重构。

## 静态合批的影响

资源和地貌生成后执行：

```csharp
StaticBatchingUtility.Combine(landForm);   // MapRenderer.cs:1065-1066
StaticBatchingUtility.Combine(Resource);   // MapRenderer.cs:1081-1082
```

注意事项：

- Layer 必须在静态合批前设置好
- Renderer 列表最好在合批前或合批完成后统一收集
- 不能依赖探索时修改每个 Renderer 的 MaterialPropertyBlock
- CommandBuffer 重绘静态合批 Renderer 的实际批次数需用 Frame Debugger 验证
- 即使主场景是一个静态批次，遮罩 Pass 也未必保持相同合批效率

它仍比给每个资源/地貌动态换材质更适合当前结构。

---

## 透明材质的特殊问题

部分地貌可能使用：

- Alpha Cutout 树叶
- Transparent 材质
- 双面材质

纯白替换 Shader 若不处理原材质的 Alpha Clip，可能把树叶贴图中本应透明的区域也写成白色，出现方形或大片雾化区域。

处理分三档：

1. **简单版**：遮罩只按模型几何形状绘制，先观察实际效果
2. **Cutout 版**：为树叶等材质提供能采样 `_MainTex` 和 `_Cutoff` 的遮罩 Pass
3. **材质分类版**：Opaque、Alpha Cutout、Transparent 使用不同遮罩材质

建议先统计实际地貌与资源材质。若大部分是低多边形不透明模型，简单版即可，不要一开始把透明兼容做得过重。

## 性能特点与优化

成本：

- 一张屏幕空间对象遮罩
- 资源和地貌额外绘制一次
- 一次全屏 Blit
- 深度纹理
- 未探索对象像素上的探索遮罩与雾纹理采样

优化：

- 对象遮罩使用 `R8`，无需 RGBA32
- 遮罩可尝试半分辨率，但树枝、动物轮廓可能变粗
- 后处理先检查对象遮罩，黑色区域立即返回
- 遮罩 Shader 不计算光照，只写必要数据
- 缓存 Renderer 列表，不要每帧 `FindObjectsOfType`
- 资源被收割销毁时，从列表清理或跳过 Unity fake-null
- 地貌是静态对象，可一次收集并长期复用

阶段 1 已加入：

- `FogAffectedEnvironment` Layer（`ProjectSettings/TagManager.asset` 第 7 层）
- `MapRenderer` 在静态合批前递归设置资源/地貌 Layer
- 主相机运行时自动挂载选择性雾化组件（正式命名为 `FogEnvironmentSelectiveEffect`），无需修改场景序列化
- `FogEnvironmentObjectMask.shader`：重绘资源/地貌，并用主相机深度排除被单位/建筑遮挡的部分
- 阶段 1 曾使用验证 Shader 输出纯红色；正式版已替换为 `FogEnvironmentSelective.shader`，并从对象数据缓冲直接读取模型 Fog UV
- 分辨率变化时自动重建遮罩；资源收割及探索刷新后重建 Renderer 命令列表

阶段 1 验收结果：

1. 未探索格上的资源和地貌应变成纯红色
2. 已探索格上的资源和地貌应保持原色
3. 玩家/AI 单位、建筑、特效、路径和 UI 应保持原色
4. 单位挡在资源或地貌前方时，单位轮廓不应被红色覆盖
5. 相机平移、旋转、缩放及横竖屏切换时，红色区域不应漂移

最终实现补充：对象缓冲不是简单黑白遮罩，而是 `ARGBHalf` 数据缓冲：

```text
R = 环境模型片元对应的 Fog UV.x
G = 环境模型片元对应的 Fog UV.y
B = 有效环境物件标记
```

对象遮罩 Pass 直接从模型顶点计算世界 XZ 并编码 Fog UV。后处理不再依赖 `_CameraDepthTexture` 重建模型位置，因此不会因模型背后地面的视差而在相机移动时出现雾效穿洞或滑动。相机深度只在生成对象缓冲时用于遮挡判定，避免被单位/建筑挡住的环境模型穿透写入。

开发期使用的纯红验证和 `F8` 调试模式已在验收完成后删除，正式组件/Shader 命名为：

- `FogEnvironmentSelectiveEffect`
- `Hidden/FogEnvironmentSelective`
- `Hidden/FogEnvironmentObjectMask`

- 为 `LandForm` / `Resource` 设置专用 Layer

## 最终推荐

> 保留现有地形 Shader 迷雾；为 `LandForm` 和 `Resource` 分配专用 Layer；
> 通过 CommandBuffer 和主相机深度生成可见对象遮罩；
> 后处理只对"资源/地貌遮罩 × 未探索遮罩"的交集进行去饱和和雾色叠加。

这是选择准确性与工程复杂度之间最合适的办法。

实现第一步应先做纯红色测试版本，验证分类、深度遮挡和边界准确后，再替换为正式雾化算法。
